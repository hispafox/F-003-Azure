## Slide 2 — Qué vais a construir
Un pipeline YAML en Azure DevOps que:
1. Se dispara al hacer push a main
2. Compila la app .NET 8
3. Ejecuta los tests
4. Publica code coverage
5. Despliega al slot staging de App Service
6. Ejecuta smoke test en staging
7. Espera aprobación manual
8. Swap staging → producción

**Tiempo estimado:** 30 minutos
**Prerequisitos:** Azure DevOps con repos y la app del módulo 2

## Slide 4 — Paso 1: Crear el archivo de pipeline

En la raíz del repo, cread `azure-pipelines.yml`:

```yaml
trigger:
  branches:
    include: [main]

pool:
  vmImage: 'ubuntu-latest'

variables:
  buildConfiguration: 'Release'
  appName: 'app-curso-$(nombre)'
  resourceGroup: 'rg-curso-azure-$(nombre)'

stages:
- stage: Build
  displayName: 'Build + Test'
  jobs:
  - job: Build
    steps:
    - task: UseDotNet@2
      inputs: { version: '8.x' }
    - script: dotnet restore
    - script: dotnet build -c $(buildConfiguration) --no-restore
    - script: dotnet test -c $(buildConfiguration) --no-build --collect:"XPlat Code Coverage" --logger trx
    - task: PublishTestResults@2
      inputs: { testResultsFormat: 'VSTest', testResultsFiles: '**/*.trx' }
    - script: dotnet publish -c $(buildConfiguration) -o $(Build.ArtifactStagingDirectory)/app
    - task: ArchiveFiles@2
      inputs:
        rootFolderOrFile: '$(Build.ArtifactStagingDirectory)/app'
        archiveFile: '$(Build.ArtifactStagingDirectory)/deploy.zip'
    - publish: $(Build.ArtifactStagingDirectory)/deploy.zip
      artifact: webapp
```

## Slide 6 — Paso 3: Stage de swap a producción (con aprobación)

```yaml
- stage: SwapProd
  displayName: 'Swap to Production'
  dependsOn: DeployStaging
  jobs:
  - deployment: SwapSlots
    environment: 'curso-production'  # Configurar aprobación en ADO
    strategy:
      runOnce:
        deploy:
          steps:
          - task: AzureAppServiceManage@0
            inputs:
              azureSubscription: 'Azure-Curso'
              Action: 'Swap Slots'
              WebAppName: $(appName)
              SourceSlot: 'staging'
          
          - script: |
              sleep 10
              STATUS=$(curl -s -o /dev/null -w "%{http_code}" "https://$(appName).azurewebsites.net/health")
              echo "Production health: HTTP $STATUS"
              if [ "$STATUS" != "200" ]; then echo "ROLLBACK NEEDED"; exit 1; fi
            displayName: 'Post-deploy health check'
```

**2. KQL queries para análisis histórico** (si conectáis ADO a Log Analytics):

```kusto
// Tasa de éxito de pipeline en últimos 30 días
AzureDevOpsAuditing
| where TimeGenerated > ago(30d)
| where ActionId == "Pipelines.RunCompleted"
| extend Status = tostring(Data.result)
| summarize 
    Total = count(),
    Success = countif(Status == "succeeded"),
    Failed = countif(Status == "failed")
  by bin(TimeGenerated, 1d)
| extend SuccessRate = round(Success * 100.0 / Total, 2)
| render timechart

// Steps que más tardan (cuello de botella)
AzureDevOpsAuditing
| where TimeGenerated > ago(7d)
| where ActionId == "Pipelines.TaskCompleted"
| summarize 
    AvgDuration = avg(todouble(Data.duration_seconds)),
    P95Duration = percentile(todouble(Data.duration_seconds), 95)
  by tostring(Data.task_name)
| order by AvgDuration desc
| take 10
```

## Slide 10 — Auto-rollback: cuando los smoke tests fallan

El smoke test post-deploy debe **disparar rollback automático** si falla. Sin esto, un deploy malo deja producción rota hasta que alguien intervenga.

**1. Pipeline con rollback automático:**

```yaml
# Stage de deploy con rollback automático
stages:
- stage: DeployToProduction
  jobs:
  - deployment: DeployProd
    environment: production  # Configurar approval en ADO
    strategy:
      runOnce:
        deploy:
          steps:
          # 1. Deploy a slot staging primero (no producción directa)
          - task: AzureWebApp@1
            displayName: 'Deploy to staging slot'
            inputs:
              azureSubscription: '$(azureSubscription)'
              appName: '$(appName)'
              slotName: '$(stagingSlot)'
              package: '$(Pipeline.Workspace)/drop/*.zip'
          
          # 2. Smoke tests sobre slot staging
          - script: |
              chmod +x ./scripts/smoke-tests.sh
              SMOKE_URL="https://$(appName)-$(stagingSlot).azurewebsites.net" \
                ./scripts/smoke-tests.sh
            displayName: 'Smoke tests on staging slot'
            name: 'smokeTests'
          
          # 3. Si pasan: swap a producción
          - task: AzureCLI@2
            displayName: 'Swap to production'
            condition: succeeded()
            inputs:
              azureSubscription: '$(azureSubscription)'
              scriptType: 'bash'
              scriptLocation: 'inlineScript'
              inlineScript: |
                az webapp deployment slot swap \
                  --name $(appName) \
                  --resource-group $(resourceGroup) \
                  --slot $(stagingSlot) \
                  --target-slot production
          
          # 4. Re-validar producción tras swap
          - script: |
              sleep 10  # Dar tiempo a propagación
              SMOKE_URL="https://$(appName).azurewebsites.net" \
                ./scripts/smoke-tests.sh
            displayName: 'Validate production post-swap'
            name: 'validateProd'
          
          # 5. AUTO-ROLLBACK si validation falla
          - task: AzureCLI@2
            displayName: '🔄 Auto-rollback on failure'
            condition: failed()
            inputs:
              azureSubscription: '$(azureSubscription)'
              scriptType: 'bash'
              scriptLocation: 'inlineScript'
              inlineScript: |
                echo "::error::Validation failed, rolling back..."
                az webapp deployment slot swap \
                  --name $(appName) \
                  --resource-group $(resourceGroup) \
                  --slot $(stagingSlot) \
                  --target-slot production
                
                # Notificar
                curl -X POST $(TEAMS_WEBHOOK) -H "Content-Type: application/json" \
                  -d '{"text":"⚠️ Auto-rollback ejecutado tras fallo en validation. Investigar inmediatamente."}'
                
                # Falla el pipeline para que se sepa
                exit 1
```

**2. Smoke test con thresholds estrictos** (necesario para auto-rollback robusto):

```bash
#!/bin/bash
# scripts/smoke-tests.sh
set -e

URL="${SMOKE_URL:?SMOKE_URL required}"
TIMEOUT=10

echo "🔍 Smoke tests: $URL"

# Test 1: Health endpoint responde 200
HTTP_CODE=$(curl -o /dev/null -s -w "%{http_code}" --max-time $TIMEOUT "$URL/health")
if [ "$HTTP_CODE" != "200" ]; then
    echo "❌ Health check failed: $HTTP_CODE"
    exit 1
fi

# Test 2: Latencia P95 < 2s sobre 10 requests
TOTAL_TIME=0
for i in {1..10}; do
    T=$(curl -o /dev/null -s -w "%{time_total}" --max-time $TIMEOUT "$URL/")
    TOTAL_TIME=$(echo "$TOTAL_TIME + $T" | bc -l)
done
AVG=$(echo "scale=3; $TOTAL_TIME / 10" | bc -l)
THRESHOLD=2.0
if (( $(echo "$AVG > $THRESHOLD" | bc -l) )); then
    echo "❌ Latencia ${AVG}s > threshold ${THRESHOLD}s"
    exit 1
fi

# Test 3: Endpoint crítico funciona
RESP=$(curl -s --max-time $TIMEOUT "$URL/api/productos")
if ! echo "$RESP" | jq . > /dev/null 2>&1; then
    echo "❌ /api/productos no devuelve JSON válido"
    exit 1
fi

# Test 4: Error rate de los últimos 5 min < 1% (requiere App Insights)
ERROR_RATE=$(az monitor app-insights query \
    --app "$APPINSIGHTS_NAME" \
    --analytics-query "requests | where timestamp > ago(5m) | summarize ErrorRate = countif(success==false)*100.0/count()" \
    --query "tables[0].rows[0][0]" -o tsv)
if (( $(echo "$ERROR_RATE > 1.0" | bc -l) )); then
    echo "❌ Error rate ${ERROR_RATE}% > 1%"
    exit 1
fi

echo "✅ Smoke tests passed (latency: ${AVG}s, errors: ${ERROR_RATE}%)"
```

**3. Aprendizaje clave:**

```
Sin auto-rollback:
- Deploy malo → producción rota
- Alguien debe ver alerta + ejecutar rollback manual
- MTTR típico: 15-60 minutos
- Usuarios afectados durante todo ese tiempo

Con auto-rollback:
- Deploy malo → smoke test falla → swap inverso automático
- MTTR: <2 minutos
- Usuarios casi no notan
- El equipo investiga con la app ya estable
```

**Hace la diferencia entre "deploy con miedo" y "deploy con confianza".**

## Slide 17 — Reto avanzado: pipeline con OIDC federado (sin passwords)

Reescribimos el pipeline para ELIMINAR todos los passwords usando OIDC + Federated Credentials:

**Setup inicial — crear app registration + federated credential:**

```bash
# 1. Crear App Registration en Microsoft Entra
APP_NAME="sp-pipeline-curso-prod"
APP_ID=$(az ad app create --display-name $APP_NAME --query appId -o tsv)
SP_ID=$(az ad sp create --id $APP_ID --query id -o tsv)

# 2. Asignar permisos a la suscripción
SUBSCRIPTION_ID=$(az account show --query id -o tsv)
az role assignment create \
  --assignee $APP_ID \
  --role "Contributor" \
  --scope "/subscriptions/$SUBSCRIPTION_ID/resourceGroups/rg-curso-prod"

# 3. Crear federated credential (sin secret/password)
# Para Azure DevOps:
cat > fic.json <<EOF
{
  "name": "ado-curso-prod",
  "issuer": "https://vstoken.dev.azure.com/<tu-org-id>",
  "subject": "sc://<tu-org>/<tu-proyecto>/sc-azure-prod",
  "audiences": ["api://AzureADTokenExchange"]
}
EOF

az ad app federated-credential create \
  --id $APP_ID \
  --parameters fic.json

# Para GitHub Actions:
cat > fic-github.json <<EOF
{
  "name": "github-curso-prod",
  "issuer": "https://token.actions.githubusercontent.com",
  "subject": "repo:tu-org/tu-repo:environment:production",
  "audiences": ["api://AzureADTokenExchange"]
}
EOF

az ad app federated-credential create \
  --id $APP_ID \
  --parameters fic-github.json

echo "App ID (CLIENT_ID): $APP_ID"
echo "Tenant ID: $(az account show --query tenantId -o tsv)"
echo "Subscription ID: $SUBSCRIPTION_ID"
```

**Configurar Service Connection en Azure DevOps:**
```
Project Settings → Service connections → New service connection
├── Type: Azure Resource Manager
├── Authentication method: Workload Identity Federation (manual)
│   └── ⭐ Esta es la opción nueva (no Service Principal con secret)
├── Service Principal Id: <APP_ID>
├── Tenant Id: <TENANT_ID>  
├── Subscription Id: <SUBSCRIPTION_ID>
├── Subscription Name: <name>
└── Service connection name: sc-azure-prod-oidc

Result: NO password stored, NO rotation needed, NO leak risk
```

**Pipeline ADO completo con OIDC:**
```yaml
# azure-pipelines-prod.yml (ADO con OIDC)
trigger:
  branches:
    include: [main]

variables:
  - name: vmImage
    value: 'ubuntu-latest'
  - name: webAppName
    value: 'app-curso-prod'
  - name: resourceGroup
    value: 'rg-curso-prod'

stages:
  - stage: Build
    jobs:
      - job: BuildAndTest
        pool:
          vmImage: $(vmImage)
        steps:
          - task: UseDotNet@2
            inputs:
              version: '8.0.x'
          
          - task: DotNetCoreCLI@2
            displayName: 'Build'
            inputs:
              command: 'build'
              projects: '**/*.csproj'
              arguments: '--configuration Release'
          
          - task: DotNetCoreCLI@2
            displayName: 'Test'
            inputs:
              command: 'test'
              arguments: '--collect:"XPlat Code Coverage"'
          
          - task: DotNetCoreCLI@2
            displayName: 'Publish'
            inputs:
              command: 'publish'
              publishWebProjects: true
              arguments: '-c Release -o $(Build.ArtifactStagingDirectory)'
              zipAfterPublish: true
          
          - task: PublishBuildArtifacts@1
            inputs:
              pathToPublish: $(Build.ArtifactStagingDirectory)
              artifactName: 'drop'

  - stage: DeployStaging
    dependsOn: Build
    jobs:
      - deployment: DeployToStaging
        environment: 'staging'
        pool:
          vmImage: $(vmImage)
        strategy:
          runOnce:
            deploy:
              steps:
                # ⭐ NO secret needed - OIDC token automatically obtained
                - task: AzureWebApp@1
                  displayName: 'Deploy to Staging'
                  inputs:
                    azureSubscription: 'sc-azure-prod-oidc'  # OIDC connection
                    appName: $(webAppName)
                    deployToSlotOrASE: true
                    slotName: 'staging'
                    package: '$(Pipeline.Workspace)/drop/*.zip'
                
                - task: AzureCLI@2
                  displayName: 'Smoke test'
                  inputs:
                    azureSubscription: 'sc-azure-prod-oidc'
                    scriptType: 'bash'
                    scriptLocation: 'inlineScript'
                    inlineScript: |
                      STAGING_URL="https://$(webAppName)-staging.azurewebsites.net"
                      sleep 30  # Wait for warmup
                      
                      for i in {1..10}; do
                        STATUS=$(curl -s -o /dev/null -w "%{http_code}" $STAGING_URL/health)
                        if [ "$STATUS" = "200" ]; then
                          echo "✅ Staging health OK ($i)"
                          exit 0
                        fi
                        sleep 5
                      done
                      
                      echo "❌ Staging health failed"

  - stage: DeployProduction

                        --name $(webAppName) \
```

## Slide 19 — Reto: Bicep con what-if preview gate

Pipeline IaC con safety net antes de deploy:

```yaml
# .github/workflows/deploy-infra.yml
name: Deploy Infrastructure

on:
  pull_request:
    paths: ['infra/**']
  push:
    branches: [main]
    paths: ['infra/**']

permissions:
  id-token: write
  contents: read
  pull-requests: write  # Para comentar el what-if en el PR

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Bicep build
        run: |
          for f in $(find infra -name "*.bicep"); do
            echo "Building $f"
            az bicep build --file $f
          done

  whatif:
    needs: validate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - uses: azure/login@v2
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          subscription-id: ${{ vars.AZURE_SUBSCRIPTION_ID }}
      
      - name: Run what-if
        id: whatif
        run: |
          OUTPUT=$(az deployment group what-if \
            --resource-group rg-curso-prod \
            --template-file infra/main.bicep \
            --parameters infra/main.prod.bicepparam \
            --no-pretty-print 2>&1)
          
          echo "$OUTPUT" > whatif.json
          
          # Parse changes
          MODIFY=$(echo "$OUTPUT" | jq '[.changes[]? | select(.changeType == "Modify")] | length')
          DELETE=$(echo "$OUTPUT" | jq '[.changes[]? | select(.changeType == "Delete")] | length')
          CREATE=$(echo "$OUTPUT" | jq '[.changes[]? | select(.changeType == "Create")] | length')
          
          echo "modify=$MODIFY" >> $GITHUB_OUTPUT
          echo "delete=$DELETE" >> $GITHUB_OUTPUT
          echo "create=$CREATE" >> $GITHUB_OUTPUT
      
      - name: Comment PR with what-if
        if: github.event_name == 'pull_request'
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const whatif = fs.readFileSync('whatif.json', 'utf8');
            
            const body = `## 🔍 Bicep What-If Result
            
            **Summary:**
            - 🟢 Create: ${{ steps.whatif.outputs.create }}
            - 🟡 Modify: ${{ steps.whatif.outputs.modify }}
            - 🔴 Delete: ${{ steps.whatif.outputs.delete }}
            
            <details>
            <summary>Full output</summary>
            
            \`\`\`json
            ${whatif.substring(0, 30000)}
            \`\`\`
            </details>
            
            ⚠️ **Review carefully before merging**`;
            
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: body
            });
      
      # Block deploy si hay deletes inesperados
      - name: Block on unexpected deletes
        if: steps.whatif.outputs.delete > '0'
        run: |
          echo "❌ ${{ steps.whatif.outputs.delete }} resources would be DELETED"
          echo "Review changes manually before proceeding"
          exit 1

  deploy:
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    needs: whatif
    runs-on: ubuntu-latest
    environment: prod-iac  # Required approval
    steps:
      - uses: actions/checkout@v4
      
      - uses: azure/login@v2
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          subscription-id: ${{ vars.AZURE_SUBSCRIPTION_ID }}
      
      - name: Deploy with Stack
        run: |
          az stack group create \
            --name stack-curso-prod \
            --resource-group rg-curso-prod \
            --template-file infra/main.bicep \
            --parameters infra/main.prod.bicepparam \
            --action-on-unmanage detachAll \
            --deny-settings-mode denyWriteAndDelete \
            --deny-settings-excluded-actions \
              "Microsoft.Web/sites/restart/action" \
            --yes
      
      - name: Tag deployment
        run: |
          DEPLOY_ID="$(date +%Y%m%d-%H%M%S)-${{ github.run_number }}"
          echo "Deployment ID: $DEPLOY_ID"
          
          # Tag all stack resources
          az tag update \
            --resource-id /subscriptions/${{ vars.AZURE_SUBSCRIPTION_ID }}/resourceGroups/rg-curso-prod \
            --operation merge \
            --tags "lastDeploy=$DEPLOY_ID" "deployedBy=github-actions"
```

**Resultado en PR:**
```
🔍 Bicep What-If Result

Summary:
- 🟢 Create: 2
- 🟡 Modify: 1
- 🔴 Delete: 0

[Detailed JSON output...]

⚠️ Review carefully before merging
```

**Workflow:**
1. Dev abre PR con cambios en infra/
2. Pipeline ejecuta what-if y comenta en PR
3. Reviewer ve EXACTAMENTE qué cambiará
4. Si hay deletes → pipeline falla automáticamente
5. Merge → triggers deploy stage
6. Required approval en Environment 'prod-iac'
7. Deployment Stack actualiza recursos
8. Tags actualizadas con deployment ID

## Slide 21 — Troubleshooting common pipeline issues

Top problemas y soluciones rápidas:

**1. "OIDC token not found":**
```yaml
# ❌ Missing permissions
jobs:
  deploy:
    runs-on: ubuntu-latest
    # Missing: permissions block

# ✅ Add permissions
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      id-token: write   # ⭐ Required
      contents: read
```

**2. "Service connection authorization failed":**
```bash
# Verificar federated credential subject MATCH exact:

# ADO subject format:
# sc://ORG-NAME/PROJECT-NAME/SC-NAME
# (case-sensitive!)

# GitHub subject format:
# repo:owner/repo:environment:env-name
# repo:owner/repo:ref:refs/heads/main
# repo:owner/repo:pull_request

# Verify:
az ad app federated-credential list --id $APP_ID --output table
```

**3. "Pipeline runs forever / stuck":**
```yaml
# ❌ No timeout = potentially runs hours
- script: do_something_long.sh

# ✅ Always set timeoutInMinutes
- script: do_something_long.sh
  timeoutInMinutes: 30  # Hard limit

# Same for jobs
jobs:
  - job: Deploy
    timeoutInMinutes: 60  # Job-level timeout
```

**4. "Deploy succeeds but app crashes":**
```bash
# Causa común: missing environment variables
# Solution: usar Bicep para asegurar config

# Verify app settings post-deploy
az webapp config appsettings list \
  --name app-curso-prod \
  --resource-group rg-curso-prod

# Check startup logs
az webapp log tail --name app-curso-prod -g rg-curso-prod

# Or download logs
az webapp log download --name app-curso-prod -g rg-curso-prod
```

**5. "Bicep what-if shows no changes but deploy fails":**
```bash
# Causa: parameter changes vs resource changes
# What-if no detecta todos los casos

# Solución: usar full mode
az deployment group create \
  --resource-group rg-curso-prod \
  --template-file main.bicep \
  --mode Complete  # Full mode catches more
```

**6. "Slot swap loses settings":**
```bash
# Solución: marcar settings como sticky
az webapp config appsettings set \
  --name app-curso-prod \
  --resource-group rg-curso-prod \
  --slot-settings \
    DATABASE_CONNECTION="$CONN_STRING" \
    APPLICATIONINSIGHTS_CONNECTION_STRING="$AI_CONN"
# Result: estas NO se mueven con el swap
```

**7. "Tests pass locally but fail in pipeline":**
```yaml
# Causa: Different environment, missing setup
# Solución: dockerize tests + cache dependencies

- task: DotNetCoreCLI@2
  displayName: 'Restore packages'
  inputs:
    command: 'restore'
    projects: '**/*.csproj'

- task: Cache@2
  displayName: 'Cache NuGet'
  inputs:
    key: 'nuget | "$(Agent.OS)" | **/packages.lock.json'
    path: $(NUGET_PACKAGES)

- task: DotNetCoreCLI@2
  displayName: 'Run tests'
  inputs:
    command: 'test'
    arguments: '--logger "trx;LogFileName=results.trx"'
```

**8. "Deploy successful pero changes not visible":**
```bash
# Causa: CDN cache, browser cache, App Service warmup
# Solución:

# 1. Clear App Service cache
az webapp restart --name app-curso-prod -g rg-curso-prod

# 2. Clear CDN si se usa
az cdn endpoint purge \
  --resource-group rg-curso-prod \
  --profile-name cdn-curso \
  --name endpoint-curso \
  --content-paths "/*"

# 3. Verify deployed version
curl https://app-curso-prod.azurewebsites.net/version
```

**9. "Costs spike después de deploy":**
```bash
# Causa común: removed sampling, increased instances
# Verify post-deploy:
az monitor metrics list \
  --resource /subscriptions/.../app-curso-prod \
  --metric "CpuTime" "Requests" "Http5xx" \
  --interval PT15M

# Setup cost alert para early detection
az monitor metrics alert create \
  --name "App cost anomaly" \
  --resource-group rg-curso-prod \
  --condition "max Cost > 100" \
  --action /subscriptions/.../actionGroups/ag-curso-prod
```

**10. "Pipeline approval timeout":**
```yaml
# Default: 30 days waiting for approval
# Problem: forgotten PRs

# Solution: shorter timeout
environment:
  name: production
  # Configure en GitHub:
  # Settings → Environments → Wait timer
  # → Auto-cancel after 7 days
```

**Debugging checklist universal:**
```
1. ¿Pipeline file syntax válido? (yamllint)
2. ¿Permissions correctos en job?
3. ¿Variables/secrets disponibles en environment?
4. ¿Service connection authorized?
5. ¿Network access (firewall/private endpoints)?
6. ¿Quotas no excedidas (cores, IPs)?
7. ¿Logs disponibles en Diagnostic Settings?
```

## Slide 22 — Reto avanzado: GitOps con Argo CD o Flux

Para AKS workloads, GitOps reemplaza pipelines push:

```
Pipeline tradicional (PUSH):
GitHub → Build → Pipeline pushes → AKS

GitOps (PULL):
GitHub (desired state) ← Argo CD watches ← AKS (actual state)
                                ↓
                          Auto-syncs differences
```

**Setup Argo CD en AKS:**
```bash
# 1. Install Argo CD
kubectl create namespace argocd
kubectl apply -n argocd -f \
  https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# 2. Get initial admin password
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d

# 3. Port-forward para acceso UI
kubectl port-forward svc/argocd-server -n argocd 8080:443

# Login: https://localhost:8080
```

**Application manifest:**
```yaml
# argocd/applications/api-pedidos.yaml

  name: api-pedidos
  namespace: argocd
spec:
  project: default
  
  source:
    repoURL: https://github.com/empresa/k8s-manifests
    targetRevision: main
    path: apps/api-pedidos/overlays/production
  
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  
  syncPolicy:
    automated:
      prune: true       # Delete removed resources
      selfHeal: true    # Auto-sync if drift
    syncOptions:
      - CreateNamespace=true
      - PrunePropagationPolicy=foreground
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
```

**Métricas DORA (DevOps Research & Assessment):**

Las 4 key metrics que define elite teams:

```
1. DEPLOYMENT FREQUENCY
   Elite:    Multiple times/day
   High:     Daily-Weekly
   Medium:   Weekly-Monthly
   Low:      < Once/month

   Elite:    < 1 hour (commit → production)
   High:     1 day - 1 week
   Medium:   1 week - 1 month
   Low:      > 1 month
   
   Tu equipo (post-M08): _____ avg time

3. MEAN TIME TO RECOVER (MTTR)
   Elite:    < 1 hour
   High:     < 1 day
   Medium:   1 day - 1 week
   Low:      > 1 week
   
   Tu equipo (post-M08): _____ avg MTTR

4. CHANGE FAILURE RATE
   Elite:    0-15%
   High:     16-30%
   Medium:   31-45%
   Low:      > 46%
   
   Tu equipo (post-M08): _____% failures
```

**Medirlas con KQL:**
```kusto
// Lead Time for Changes
let deployments = AzureDevOps_Deployments
  | where TimeGenerated > ago(30d)
  | project DeployTime = TimeGenerated, CommitId;

let commits = AzureDevOps_Commits
  | where TimeGenerated > ago(60d)
  | project CommitTime = TimeGenerated, CommitId;

deployments | join kind=inner commits on CommitId
| extend LeadTimeHours = (DeployTime - CommitTime) / 1h
| summarize 
    P50_LeadTime = percentile(LeadTimeHours, 50),
    P95_LeadTime = percentile(LeadTimeHours, 95)

// Deployment Frequency
AzureDevOps_Deployments
| where TimeGenerated > ago(30d)
| where Environment == "production"
| where Status == "Succeeded"
| summarize Deploys = count() by bin(TimeGenerated, 1d)
| summarize AvgPerDay = avg(Deploys), AvgPerWeek = avg(Deploys)*7

// Change Failure Rate
AzureDevOps_Deployments
| where TimeGenerated > ago(30d)
| where Environment == "production"
| summarize 
    Total = count(),
    Failed = countif(Status == "Failed" or RolledBack == true)
| extend FailureRatePct = 100.0 * Failed / Total

// MTTR
SecurityIncident
| where TimeGenerated > ago(30d)
| where Severity == "High"
| extend MTTR_hours = (LastModifiedTime - FirstActivityTimeUtc) / 1h
| summarize MedianMTTR = percentile(MTTR_hours, 50)
```
