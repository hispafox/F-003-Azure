## Slide 2 — Qué es este módulo bonus
Este módulo es un bonus track: no estaba en el temario original de AZ-204, pero en 2026 no podéis ignorarlo. La IA ha pasado de ser "autocompletado en el IDE" a ser "agente que ejecuta workflows completos". Y específicamente para Azure, hay un ecosistema entero: Claude Code con skills oficiales de Microsoft, MCP servers para Azure y Bicep, Claude Cowork para knowledge work, y agentes que construyen, despliegan y operan infraestructura.

En este módulo: qué es cada pieza, cómo usarla con Azure, y cómo aplicar todo esto a los 10 módulos que ya habéis visto.

## Slide 3 — La evolución: 3 generaciones de IA para desarrollo

```
Generación 1 (2020-2023): Autocompletado
├── GitHub Copilot (sugerencias línea a línea)
├── Contexto: archivo actual
└── Acción: completar código mientras escribes

Generación 2 (2023-2025): Chat conversacional
├── ChatGPT, Claude.ai, Copilot Chat
├── Contexto: lo que copies y pegues en el prompt
└── Acción: generar bloques de código bajo demanda

Generación 3 (2025-2026): Agentes
├── Claude Code, Cowork, Cursor, Aider
├── Contexto: proyecto completo + herramientas reales
└── Acción: ejecuta tareas multipaso (leer, escribir, ejecutar, verificar)
```

Estamos en la generación 3. El salto no es incremental — es cualitativo. Un agente puede leer vuestro repo, modificar 15 archivos, ejecutar tests, abrir un PR en Azure DevOps y actualizar el work item asociado. Todo en una conversación.

## Slide 4 — Qué es un agente (en este contexto)
Un agente es un LLM que puede **percibir, razonar y actuar** usando herramientas:

```
          ┌──────────────┐
     ┌───→│  PERCEPCIÓN   │ ← Lee archivos, logs, resultados
     │    └──────┬───────┘
     │           ↓
     │    ┌──────────────┐
     │    │  RAZONAMIENTO │ ← Planifica próximos pasos
     │    └──────┬───────┘
     │           ↓
     │    ┌──────────────┐
     └────┤    ACCIÓN     │ → Edita archivos, ejecuta comandos,
          │              │   llama APIs, invoca MCP tools
          └──────────────┘
```

El loop se ejecuta hasta que la tarea se completa o el humano interviene. La diferencia con un chatbot: un agente **no responde** — **hace**.

## Slide 6 — La filosofía: Microsoft apuesta por skills abiertos
Microsoft podría haber construido "Copilot para Azure" como producto cerrado. En vez de eso, en marzo 2026 publicaron **Azure Skills Plugin** (github.com/microsoft/azure-skills): 20 skills oficiales para Azure en formato estándar SKILL.md, compatible con Claude Code, GitHub Copilot, Cursor, Codex CLI y cualquier agent compatible.

La apuesta: los skills son interoperables entre agentes. Si aprendéis a usar skills con Claude Code para Azure, esos mismos skills funcionan en GitHub Copilot CLI el día que cambiéis de herramienta.

## Slide 10 — Los 3 niveles de uso

**Nivel 1 — Ayudante:** Le pedís a Claude Code cosas concretas ("genera un Bicep para una Function App"). Revisáis y aplicáis. Sois vosotros el conductor.

**Nivel 2 — Colega:** Configuráis skills y MCP. Claude Code actúa con contexto. Trabaja en múltiples archivos. Ejecuta comandos. Iteráis en conversación.

**Nivel 3 — Agente autónomo:** Definís workflows (agents, plugins, scheduled tasks). Claude Code ejecuta tareas completas sin supervisión continua. Vosotros revisáis resultados.

Vais a subir por estos niveles durante el módulo. No todos los equipos llegan al nivel 3 — depende del tipo de trabajo y la tolerancia al riesgo.

## Slide 12 — Lo que NO es Claude Code (expectativas realistas)
- **No es mágico.** Si vuestro prompt es vago, la salida será vaga
- **No reemplaza al desarrollador.** Reemplaza el trabajo repetitivo, amplifica el juicio
- **No es infalible.** Alucina APIs, métodos y configuraciones. Siempre verificar
- **No es gratis.** Coste típico: $20-200/mes por developer (plan o API usage)
- **No es privado por defecto.** El código se envía a Anthropic (excepto en Enterprise con ZDR)
- **No sustituye buenas prácticas.** Si vuestro equipo no hace code review, tampoco revisarán lo que genere IA

## Slide 13 — Privacidad y compliance con Claude Code + Azure
Si trabajáis con datos sensibles o bajo regulaciones estrictas (GDPR, HIPAA, financial), considerad:

```
Opciones por nivel de privacidad:
├── Plan Pro/Max individual → datos van a API de Anthropic (estándar)
├── Plan Team/Enterprise → SSO + audit logs + admin controls
├── Enterprise con ZDR (Zero Data Retention) → datos no se guardan
├── Anthropic via AWS Bedrock → vuestro AWS account
├── Anthropic via Google Vertex AI → vuestra GCP
└── Anthropic via Azure AI Foundry → vuestra Azure (más relevante para M11!)
```

**Clave para empresas:** Claude está disponible en Azure AI Foundry. Podéis usar el modelo sin que los datos salgan de vuestra suscripción Azure. El compliance oficer de vuestra empresa probablemente prefiera esta opción.

## Slide 14 — Claude en Azure AI Foundry: la opción enterprise

```bash
# Claude está disponible en Microsoft Foundry (ex Azure AI Foundry)
# Modelos: Claude Sonnet 4.x, Claude Opus 4.x, Haiku

# Beneficios:
# - Los datos no salen de vuestra suscripción Azure
# - Facturación a través de Azure (no a Anthropic directamente)
# - Compliance ya validado (SOC 2, HIPAA, FedRAMP, GDPR)
# - Integración nativa con Entra ID para auth
# - Private Endpoints disponibles

# Para usar Claude Code con Foundry (requiere config específica):
export ANTHROPIC_BASE_URL="https://<foundry-endpoint>.services.ai.azure.com/..."
export ANTHROPIC_API_KEY="<foundry-api-key>"
claude
```

**Patrón típico enterprise:** Los devs usan Claude Code con API key de Anthropic (rápido para adoptar). Para workloads productivos o con datos sensibles, se migra a Claude en Foundry.

## Slide 15 — Modelos disponibles y selección
```bash
# En Claude Code, podéis elegir modelo según la tarea
claude --model claude-opus-4-7        # Más capaz, más caro
claude --model claude-sonnet-4-6      # Balance capacidad/coste
claude --model claude-haiku-4-5-20251001  # Rápido y barato

# Reglas generales:
# Opus → arquitectura, debugging complejo, code review profundo
# Sonnet → la mayoría del trabajo (generación, refactoring)
# Haiku → tareas simples, alto volumen (clasificación, formatos)
```

Podéis configurar el modelo por agent:
```yaml
# .claude/agents/bicep-reviewer.md
---
name: bicep-reviewer
description: Review Bicep files for best practices
model: sonnet      # Coste-eficiente para review
---
```

## Slide 16 — El flujo típico del día con Claude Code + Azure

```
09:00 Arranque
  ├─ claude (en terminal, en el repo)
  ├─ "Muéstrame mis work items del sprint actual"
  │   → ADO MCP responde con lista
  └─ "Empecemos por el bug #1234"

09:30 Trabajo
  ├─ "Analiza el módulo de auth y sugiere la causa"
  │   → Lee archivos, razona, propone fix
  ├─ "Implementa el fix y escribe tests"
  │   → Edita 3 archivos
  ├─ "Ejecuta los tests"
  │   → dotnet test → 42/42 passed
  └─ "Valida el Bicep que toca y ejecuta what-if"
     → Bicep MCP valida, Azure MCP hace what-if

11:00 Review
  ├─ "Usa el bicep-reviewer agent sobre los cambios de infra"
  │   → Agent ejecuta en background
  └─ Revisa findings y aprueba

11:30 Delivery
  ├─ "Crea un PR con estos cambios"
  │   → ADO MCP crea PR
  └─ "Actualiza el bug #1234 a 'In Review' con link al PR"
     → ADO MCP actualiza work item
```

20 minutos de conversación → 3 horas de trabajo equivalente.

## Slide 18 — Los 4 principios del equipo que adopta IA bien

**1. Skills son código.** Versionadlos en Git como cualquier otra cosa. El equipo contribuye skills, no cada persona los mantiene aislados.

**2. Agentes con permisos mínimos.** Dadle tools al agente solo si los necesita. Un code-reviewer no necesita `bash` ni `write` — solo `read`.

**3. Humano en el loop para acciones con impacto.** Claude puede proponer el `az deployment group create` a producción. Ejecutarlo lo hace un humano.

**4. Auditar el uso.** Logs de comandos ejecutados, archivos modificados, costes de API. Un checkpoint por sesión. Podéis revisar qué hizo la IA igual que revisáis qué hizo un junior.

## Slide 19 — Miedos comunes (y respuestas)

**"Va a reemplazar a los devs del equipo."**
No — va a multiplicar su productividad. Los devs que usan IA bien producen 2-3x. Los devs que no la usan quedan atrás. Reemplaza trabajo, no personas.

**"Va a generar código inseguro."**
Puede, como cualquier dev junior. Por eso existe code review. Con skills tipo "security-review" podéis automatizar el primer filtro.

**"Los datos del cliente salen de la empresa."**
Con plan individual, sí. Con Enterprise ZDR o Claude en Foundry, no. Elegid la opción correcta para vuestro contexto.

**"El coste se nos va de las manos."**
$20-200/mes por dev es barato comparado con el tiempo ahorrado. Hay controles de budget (daily cap, rate limits). Medibles.
