## Slide 16 — M4 con Claude Code: Durable Functions patterns

```bash
> Implementa un Durable Functions orchestrator con el patrón "Fan-out/Fan-in":
  - Escenario: procesar un pedido grande con 10 items
  - Para cada item, llama a una Activity function que verifica stock
  - Espera que todas las Activities terminen
  - Si alguna Activity reporta sin stock, marca el pedido como incompleto
  - Si todas OK, marca el pedido como "listo para envío"
  - Incluye retry policy con exponential backoff
  - Incluye tests unitarios del orchestrator usando IDurableOrchestrationContext mock
```

Durable Functions tiene mucho boilerplate. CC genera el orchestrator + activities + tests siguiendo el patrón correcto.

## Slide 17 — M4 con Claude Code: DLQ monitoring

```bash

  1. Cuántos mensajes hay en DLQ
  2. Lee los primeros 10 para ver el patrón
  3. Analiza el DeadLetterReason y DeadLetterErrorDescription
  4. Identifica la causa común (si hay)
  5. Propón solución:
     - Si es bug de código → fix

## Slide 29 — M7 con Claude Code: event-driven patterns

  4. Reservar envío (service Shipping)

```

## Slide 37 — Importante: qué NO cambia con CC
**El ahorro es real pero tiene condiciones:**

- Necesitáis buen setup inicial (CLAUDE.md + skills + MCP)
- Necesitáis revisar lo que CC genera (bugs, alucinaciones)
- El tiempo de revisión cuenta (está incluido en los números de arriba)
- Tareas creativas / de decisión no se aceleran tanto
- Equipos sin disciplina de code review NO ven estos ahorros

**Lo que se mantiene igual:**
- Las decisiones de arquitectura las toma el humano
- La comunicación con stakeholders
- El debugging de lógica de negocio compleja
- Las pruebas con usuarios reales

## Slide 38 — Cierre del submódulo
Hemos recorrido los 10 módulos del curso mostrando dónde y cómo Claude Code acelera cada tarea. El patrón es consistente: tareas procedurales bien definidas (generar, validar, migrar, configurar) → ahorro del 70-85%. Tareas de decisión y creatividad → IA como asistente, no sustituto.

Aplicad esto gradualmente: un módulo, un workflow, un skill cada vez. En 2-3 meses el equipo transforma su productividad.

Siguiente: Claude Cowork para Azure — la misma potencia para knowledge workers sin terminal.
