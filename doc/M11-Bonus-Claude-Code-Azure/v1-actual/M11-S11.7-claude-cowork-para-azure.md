## Slide 1 — Portada
**Módulo 11 · BONUS · Submódulo 11.7**

La potencia de Claude Code, pero sin terminal — para knowledge workers que operan Azure

---

## Slide 2 — Por qué Cowork existe
Anthropic observó un patrón en 2025: sus propios equipos de marketing, data y finanzas abandonaban la interfaz de chat y usaban **Claude Code** (herramienta para devs) porque podía manipular archivos, ejecutar comandos y automatizar tareas multi-step.

El problema: abrir un terminal y escribir comandos no es razonable para un PM, una persona de operaciones o alguien de compliance.

**Cowork es la respuesta:** misma arquitectura agéntica que Claude Code, envuelta en una app de escritorio que cualquier persona puede usar. Enero 2026 en preview, abril 2026 en GA.

---

## Slide 3 — Cowork: lo que es y lo que no es

```
ES:
✓ Un tercer modo en Claude Desktop (junto a Chat y Code)
✓ Un agente que lee, edita y crea archivos en tu máquina
✓ Multi-step por diseño: defines el objetivo, no los pasos
✓ Acceso a connectors (Gmail, Slack, Notion, AWS Marketplace, etc.)
✓ Scheduled tasks (tareas recurrentes sin tener que pedirlas)
✓ Projects (workspaces persistentes con memoria)

NO ES:
✗ Un sustituto de Claude Code para desarrolladores
✗ Un asistente conversacional simple (es agéntico, actúa)
✗ Un producto web (requiere la app de escritorio)
✗ Gratis (requiere plan Pro/Max/Team/Enterprise)
```

## Slide 4 — Por qué Cowork encaja en un equipo Azure

Vuestro equipo de desarrollo Azure no está solo en la organización. Hay otras personas que interactúan con Azure sin escribir código:

```
Roles típicos en torno a Azure que no tocan terminal:
├── Product Managers → necesitan dashboards, cost reports, roadmap
├── Operaciones → reports de uptime, compliance, incidentes
├── Finanzas → análisis de costes, forecasts de cloud spend
├── Seguridad → auditorías, revisión de accesos, compliance reports
├── Soporte L1/L2 → investigar incidentes sin acceso a Claude Code
├── Dirección → informes ejecutivos de salud del producto
└── Data Analysts → exportar datos de App Insights a Excel
```

Todos estos roles pueden usar Cowork para operar sobre Azure con lenguaje natural, sin terminal.

## Slide 8 — Folders: dar acceso controlado

Cowork no tiene acceso a tu disco entero — solo a las carpetas que apruebas.

```
Settings > Folders > Add folder

Ejemplos típicos en un equipo Azure:
├── /Users/yo/azure-reports/          → donde guardar informes generados
├── /Users/yo/downloads/azure-logs/   → para procesar exports de logs
├── /Users/yo/project-ventas/docs/    → docs del proyecto (lectura)
└── /Users/yo/project-ventas/data/    → datasets locales para análisis

Por cada folder, podéis:
- Solo lectura
- Lectura + escritura
- Restringir patrones (ej: no *.env, no *.pfx)
```

Los archivos fuera de estas carpetas son invisibles para Cowork.

## Slide 12 — Folder instructions vs Global instructions
```
Global instructions (Settings > Cowork > Global instructions):
├── Se aplican a TODAS las sesiones de Cowork
├── Ej: "Mi nombre es Pedro, trabajo en Equipo Ventas"
├── Ej: "Siempre pregunta antes de borrar archivos"
└── Ej: "Zona horaria: CET/CEST"

Folder instructions (contextuales por carpeta):
├── Se aplican solo cuando trabajas con esa carpeta
├── Ej: en /azure-reports/ → "Siempre formato Excel con pestaña Resumen"
├── Ej: en /compliance/ → "Aplica clasificación TLP:AMBER a todo output"
└── Cowork puede actualizar estas instrucciones solo durante la sesión
```

Combinadas, definen el comportamiento de Cowork en el nivel correcto de granularidad.

## Slide 17 — Scheduled tasks: automatización recurrente
Cowork permite crear tareas que se ejecutan automáticamente en un cadence.

```
Crear scheduled task:
En cualquier task, escribir: /schedule

O ir a: Cowork > Scheduled > New

Configuración:
├── Nombre: "Daily Azure health check"
├── Prompt: el prompt que ejecutar
├── Cadence: 
│   ├── Daily at 08:00
│   ├── Weekly (Mon-Fri at 09:00)
│   ├── Monthly (first day)
│   └── Custom (cron)
├── Condiciones:
│   └── "Solo ejecutar si el equipo está en día laboral"
└── Output:
    ├── Guardar resultado en carpeta X
    └── Notificar por Slack a canal Y
```

**Limitación importante:** Solo se ejecutan cuando tu ordenador está encendido Y la app Cowork abierta.

1. "Daily Azure health briefing" (cada mañana 08:00)

El equipo no tiene que acordarse de generar estos reports — Cowork los genera solo.

## Slide 20 — Computer use: el escalón siguiente (preview)
Desde finales de 2025, Cowork incluye "computer use": Claude puede controlar directamente el ratón/teclado de tu máquina cuando no hay otra forma de hacer algo.

```
Cómo decide Cowork qué usar:
1. ¿Hay connector oficial? → lo usa (rápido, fiable)
2. ¿Hay acceso vía navegador? → usa Claude in Chrome
3. ¿Solo queda la app visual? → computer use

Computer use pide permiso para cada app. Ves todo en tiempo real.

Casos donde aplica para Azure:
├── Portal Azure para algo que no hay en az CLI/MCP
├── Power BI para extraer insights de dashboards custom
├── Herramientas internas sin API pública
└── Apps legacy on-premise que no tienen connector
```

**Honesto:** computer use es lento y menos fiable que APIs. Úsalo como último recurso.

## Slide 21 — Mobile access: Cowork en el móvil (Pro/Max)
Desde marzo 2026, Pro y Max pueden usar Cowork desde el móvil. El flujo:

```
1. Desde el móvil, abres la app Claude
2. Envías un prompt a Cowork
3. El trabajo se ejecuta en tu desktop (debe estar encendido + app abierta)
4. El resultado llega de vuelta a tu móvil

Ejemplo real:
Estás en una reunión y alguien pregunta: 
"¿Cuánto costó Azure el mes pasado?"

Desde el móvil, a Cowork:
> "Dame el total de Azure spend del mes pasado, desglosado por proyecto"

2 minutos después: notificación con el dato en tu móvil.

Limitaciones:
- Desktop debe estar activo
- Algunas tareas (computer use, archivos grandes) no funcionan en mobile
- Solo funciona con scheduled tasks o requests simples
```

## Slide 22 — Seguridad en Cowork

Cowork tiene "riesgos únicos" por su naturaleza agéntica — Anthropic lo reconoce explícitamente:

```
Controles de seguridad:
├── Folder scoping: solo ve carpetas que apruebas
├── Connector approvals: debes autorizar cada conector
├── Plan preview: muestra qué va a hacer antes de ejecutar
├── Steering: puedes intervenir en cualquier paso
├── Conversation history local: NO se sube a servidores Anthropic
├── Network egress permissions: controláis a qué dominios puede ir
└── Computer use: pide permiso antes de controlar cada app

Para Team/Enterprise:
├── Admin controls: gestión centralizada de features
├── Compliance API: mapear tool calls via OpenTelemetry
├── SIEM integration: logs a Splunk/Datadog/etc.
└── Audit trails: rastreo completo de acciones

Importante: web search y MCPs NO respetan egress permissions por defecto.
Para equipos muy restringidos, deshabilitar estos canales.
```

## Slide 26 — Riesgos y consideraciones para Cowork en equipos Azure

**Riesgos a considerar:**

```
1. Credenciales Azure en la máquina del usuario
   → Si Cowork puede ejecutar az CLI, el usuario tiene las mismas perms de Azure
   → Problema: alguien de finanzas tal vez no deba poder modificar recursos
   → Mitigación: usar Service Principals con permisos de solo lectura

2. Egress de datos sensibles
   → Los datos leídos de Azure viajan a Anthropic para razonamiento
   → Problema para data classified (HIPAA, PCI)
   → Mitigación: Claude en Azure AI Foundry (datos no salen de Azure)

3. Accidentes en operaciones productivas
   → Un prompt mal formulado puede pedir operaciones destructivas
   → Mitigación: plan preview, folder scoping, agents readonly, MI con scope mínimo

4. Coste agregado
   → Cowork consume más tokens que Chat (agéntico)
   → 10 usuarios a $200/mes = $2000/mes solo en plans
   → Mitigación: empezar con piloto, medir ROI antes de rollout
```

## Slide 28 — Cierre del submódulo
Cowork extiende la potencia de Claude agéntico más allá del terminal, alcanzando a todos los roles que operan alrededor de Azure sin escribir código. PMs, ops, finanzas, seguridad — todos pueden ejecutar workflows complejos sobre Azure con prompts en lenguaje natural.

La clave estratégica: **los skills y agents son el idioma común entre Claude Code (devs) y Cowork (resto del equipo)**. Invertís una vez en skills de calidad y toda la organización se beneficia.

Siguiente: workflows avanzados que combinan todo lo anterior.
