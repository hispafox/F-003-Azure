## Slide 3 — Hooks: el gancho en el loop agéntico
Hooks son scripts shell que Claude Code ejecuta automáticamente en momentos clave del ciclo:

```
Hooks disponibles:
├── PreToolUse      → antes de que Claude use cualquier tool
├── PostToolUse     → después de que un tool devuelva
├── UserPromptSubmit → antes de enviar prompt al modelo
├── Stop             → al finalizar una sesión
└── SessionStart     → al arrancar Claude Code
```

Casos de uso:
- Logging de todas las acciones para auditoría
- Bloqueos por política (no deploys los viernes tarde)
- Notificaciones a Slack cuando CC ejecuta algo sensible
- Verificaciones pre-commit automatizadas

## Slide 4 — Hook práctico: audit log de acciones Azure
```bash
# .claude/hooks/pre-tool-use.sh
#!/bin/bash
# Log de todas las acciones que pueden tocar Azure

TOOL=$1
ACTION=$2
TIMESTAMP=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
USER=$(whoami)

# Log siempre
echo "$TIMESTAMP | $USER | $TOOL | $ACTION" >> ~/.claude-audit.log

# Log específico Azure (comando az, bicep, azd)
if echo "$ACTION" | grep -qE '\b(az|azd|bicep)\b'; then
  echo "$TIMESTAMP | $USER | AZURE | $ACTION" >> ~/.claude-azure-audit.log
  
  # Notificar a SIEM si es acción destructiva
  if echo "$ACTION" | grep -qE '\b(delete|remove|rm|destroy)\b'; then
    curl -X POST https://siem.empresa.com/events \
      -H "Content-Type: application/json" \
      -d "{
        \"severity\": \"high\",
        \"user\": \"$USER\",
        \"tool\": \"claude-code\",
        \"action\": \"$ACTION\",
        \"timestamp\": \"$TIMESTAMP\"
      }" >/dev/null 2>&1
  fi
fi

exit 0
```

Con esto tenéis trazabilidad completa. Auditoría corporativa: ✓.

## Slide 5 — Checkpointing: snapshots automáticos
Claude Code auto-crea checkpoints antes de cambios significativos. Podéis volver a cualquiera.

```bash
# Listar checkpoints
> /checkpoint list

# Output:
# cp-001 | 2026-04-22 09:15 | "Before refactor PedidoService"
# cp-002 | 2026-04-22 09:42 | "After adding tests"
# cp-003 | 2026-04-22 10:15 | "Before Bicep changes"

# Restaurar un checkpoint
> /checkpoint restore cp-002

# Undo rápido del último batch
> /undo
```

**Ventaja clave:** experimentación sin miedo. Probad refactors agresivos — si no funcionan, `/undo` y a otra cosa.

## Slide 8 — CI/CD integration: code review en PR
```yaml
# azure-pipelines.yml — step de AI code review
- task: Bash@3
  displayName: 'AI Code Review with Claude Code'
  condition: eq(variables['Build.Reason'], 'PullRequest')
  inputs:
    targetType: inline
    script: |
      # Instalar CC
      npm install -g @anthropic-ai/claude-code

      # Obtener diff del PR
      git fetch origin $(System.PullRequest.TargetBranch)
      git diff origin/$(System.PullRequest.TargetBranch)...HEAD > pr-diff.patch

      # Review con Claude Code (headless)
      cat pr-diff.patch | claude -p "
      Revisa este diff de un PR y reporta en JSON:
      {
        \"summary\": \"overall assessment\",
        \"findings\": [
          {\"severity\": \"critical|high|medium|low\",
           \"file\": \"path\", \"line\": N, \"issue\": \"...\"}
        ],
        \"decision\": \"approve | changes-requested | blocked\"
      }
      
      Criterios:
      - Critical: bugs de seguridad, secretos expuestos, SQL injection
      - High: sin MI en recursos Azure, missing error handling, race conditions
      - Medium: violaciones de convenciones del equipo (ver CLAUDE.md)
      - Low: estilo, sugerencias
      " --no-interactive > review.json

      # Publicar como comentario en PR
      BODY=$(cat review.json | jq -r '.summary + "\n\n### Findings\n" + 
              (.findings | map("- **\(.severity)** \(.file):\(.line) — \(.issue)") | join("\n"))')
      
      az repos pr comment create \
        --org $(System.CollectionUri) \
        --project $(System.TeamProject) \
        --pull-request-id $(System.PullRequest.PullRequestId) \
        --content "$BODY"
      
      # Si hay critical, fallar el build
      CRITICAL=$(cat review.json | jq '[.findings[] | select(.severity=="critical")] | length')
      if [ "$CRITICAL" -gt 0 ]; then
        echo "##vso[task.logissue type=error]$CRITICAL critical findings detected"
        exit 1
      fi
  env:
    ANTHROPIC_API_KEY: $(ANTHROPIC_API_KEY)
```

Cada PR recibe automáticamente un first-pass review por IA. El reviewer humano ya no busca lo obvio.

## Slide 9 — CI/CD integration: changelog automático
```yaml
# .github/workflows/release.yml
- name: Generate changelog from commits
  run: |
    npm install -g @anthropic-ai/claude-code
    
    LAST_TAG=$(git describe --tags --abbrev=0)
    COMMITS=$(git log --oneline --no-merges $LAST_TAG..HEAD)
    WORKITEMS=$(git log $LAST_TAG..HEAD | grep -oE "AB#[0-9]+" | sort -u)
    
    echo "$COMMITS" | claude -p "
    Genera changelog en formato Keep a Changelog desde estos commits:
    
    [commits]
    
    Work items referenciados: $WORKITEMS
    
    Formato:
    ## [vX.Y.Z] - $(date +%Y-%m-%d)
    
    ### Added
    - (features nuevos)
    
    ### Changed
    - (cambios en existente)
    
    ### Fixed
    - (bugs)
    
    ### Security
    - (cambios de seguridad)
    
    Lenguaje para usuarios finales, no developer jargon.
    " --no-interactive > CHANGELOG-ENTRY.md
```

Release con changelog legible en 1 minuto. No más "fix stuff" en los release notes.

## Slide 10 — Métricas: medir ROI de IA
Para convencer a dirección (y a vosotros mismos) de que la inversión vale la pena:

```
Métricas recomendadas (trackear mensualmente):

1. Tiempo por tipo de tarea
   ├── Antes IA: feature típica tardaba X horas
   └── Con IA: ahora tarda Y horas
   Ahorro: (X-Y)/X × 100%

2. Throughput del equipo
   ├── Story points completados por sprint (antes vs después)
   └── Features shipped por quarter

3. Calidad
   ├── Bugs escapados a producción (¿sube o baja?)
   ├── Test coverage (¿sube?)
   └── Code review findings post-merge (menos = mejor)

4. Onboarding
   ├── Tiempo para primer PR aceptado de dev nuevo
   └── Satisfacción del dev nuevo (survey)

5. Coste IA
   ├── Gasto mensual en API tokens (Claude Code)
   ├── Gasto mensual en plans (Cowork)
   └── ROI = tiempo ahorrado × coste hora developer − gasto IA
```

## Slide 11 — ROI real: cálculo ejemplo
```
Equipo Ventas: 8 developers (€40/h fully-loaded)

ANTES de IA (mes típico):
├── Tiempo medio en features: 60% del sprint
├── Resto: bugs, meetings, exploración
└── Output: ~45 story points/sprint

CON IA (3 meses después):
├── Tiempo medio en features: 75% del sprint (menos bugs pre-merge)
├── Velocity: ~58 story points/sprint (+29%)
└── Bugs escapados a prod: -35%

COSTE IA mensual:
├── Claude Code (8 devs × $20 Max base) = $160
├── Uso API adicional: ~$400
├── Cowork (2 PMs): $40
├── Total: $600/mes

VALOR tiempo ahorrado:
├── 13 story points extra/sprint × 2 sprints = 26 SP/mes
├── Tiempo equivalente: ~50h de dev/mes
├── Valor: 50h × €40 = €2000/mes
└── ROI neto: €1400/mes (~2.3x return)

Por eso los equipos mantienen estas herramientas.
```

## Slide 13 — Zero Data Retention (ZDR) en Enterprise
Si tenéis plan Enterprise, ZDR es una feature crítica para compliance:

```
Sin ZDR (default en API y planes individuales):
├── Anthropic guarda inputs/outputs por 30 días
├── Usados para abuse monitoring
└── No para entrenamiento (salvo opt-in)

Con ZDR (Enterprise):
├── Zero retention: nada se guarda post-procesamiento
├── No se puede entrenar sobre vuestros datos
├── Audit logs disponibles en vuestro lado (no Anthropic)
└── Incluye Claude Code + Cowork + API

Para activar:
├── Contactar al account manager Enterprise
├── Firmar DPA específico para ZDR
└── Provision de workspace con flag activado
```

Crítico para: healthcare (HIPAA), banca (regulaciones locales), defensa, sector público.

## Slide 15 — Multi-agent workflow: release automation end-to-end
Combinando todo lo anterior, un workflow real de release:

```
Trigger: merge a main detectado por pipeline

Paso 1: deploy-orchestrator agent
├── Pre-flight checks (tests, coverage, security scan)
├── Bicep validate + what-if
├── Deploy a staging slot
├── Smoke tests
└── Si OK → continúa; si no → rollback + notificación

Paso 2: release-gate agent (paralelo)
├── security-auditor sobre changes
├── cost-analyzer sobre deltas de infra
├── test-coverage checker
└── Combina outputs, decide proceed/hold/block

Paso 3: Si todos pasan → swap a producción
├── App Service swap staging → prod
├── Smoke test post-swap
└── Monitor 5 minutos post-deploy

Paso 4: Post-release agent
├── Genera changelog desde commits + work items ADO
├── Publica release notes en Notion/Confluence
├── Envía notificación a Slack #releases
├── Actualiza status page
└── Crea retrospectiva en ADO para siguiente sprint

Total humano involucrado: 1 aprobación manual antes del swap.
Todo lo demás automatizado.
```

## Slide 16 — Governance: gobierno corporativo de IA

Si el equipo crece, necesitáis governance. Preguntas clave:

```
Gobierno de skills/agents:
├── ¿Quién aprueba nuevos skills compartidos? → Tech lead + security
├── ¿Cómo se revisan antes de merge? → PR con reviewers obligatorios
├── ¿Hay skills que requieren audit especial? → tag "security-sensitive"
└── ¿Rollback de skill problemático? → git revert + notificación

Gobierno de permissions:
├── ¿Qué puede ejecutar Bash(*) en la empresa? → senior devs
├── ¿Qué agents pueden escribir a producción? → solo deploy-orchestrator
├── ¿Quién autoriza nuevos MCP servers? → data security team
└── ¿Rotación de PATs, SPs, keys? → cada 90 días obligatorio

Gobierno de datos:
├── ¿Qué datos pueden ir a API Anthropic? → no-PII, no-PCI
├── ¿Qué requiere ZDR? → healthcare, financial, HR
├── ¿Qué requiere Foundry (no-egress)? → cualquier dato GDPR-special
└── ¿Audit de uso? → mensual, reportado a CISO
```

## Slide 18 — Troubleshooting común

```
Problema: Claude Code lento en proyecto grande
├── Causa: context window saturado, muchos archivos irrelevantes leídos
├── Solución: .clauderules con exclude patterns (node_modules, dist, etc.)
└── Solución: usar agents con fork para no saturar main context

Problema: Claude alucina Bicep inválido
├── Causa: usa API versions obsoletas de su training
├── Solución: bicep-mcp.get_az_resource_type_schema antes de generar
└── Solución: siempre bicep-mcp.get_bicep_file_diagnostics después

Problema: Tokens explotan (coste inesperado)
├── Causa: agentes en loop, o prompts gigantes
├── Solución: set max_turns en agents (evita loops)
└── Solución: monitoring diario con alertas de spend

Problema: Credenciales expiran durante sesión larga
├── Causa: Azure CLI tokens expiran (~1h)
├── Solución: hook SessionStart que haga az login fresh
└── Solución: usar SP con lifetime largo (pero rotado)

Problema: Equipo no adopta CC
├── Causa: setup complicado o CLAUDE.md pobre
├── Solución: onboarding doc de 30 min con primer caso de uso
└── Solución: pair programming con champion al inicio
```

## Slide 19 — Anti-patterns a evitar

```
1. "Vibe coding" — aceptar todo lo que CC genera sin revisar
   → Bugs entran en producción
   → Deuda técnica se acumula
   → Revisión humana NO es opcional

2. Skill "de todo para todos"
   → Description vaga → Claude nunca lo activa
   → O se activa mal
   → Skills deben ser específicos

3. Agents con Bash(*) y full permissions
   → Un prompt injection y adiós
   → Mínimo privilegio siempre

4. No versionar skills/CLAUDE.md
   → Cada dev con setup diferente
   → Inconsistencia
   → Commitear SIEMPRE al repo

5. Ignorar los costes
   → Opus en todo → gasto mensual se dispara
   → Monitoring + alertas obligatorios

6. Esperar que la IA sustituya al pensamiento
   → Arquitectura, decisiones de producto → humano
   → La IA acelera ejecución, no reemplaza juicio

7. Romper compliance por conveniencia
   → "Copio este dato de cliente al prompt, total para qué"
   → Si estáis en GDPR/HIPAA, esto es violación
   → Policy clara + training del equipo
```
