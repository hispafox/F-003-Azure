## Slide 2 — Qué vais a construir

Una aplicación WPF mínima empaquetada como **MSIX** usando el wizard de Visual Studio. El wizard genera todo: manifest, certificado self-signed, instalador y el paquete `.msix`.

**El recorrido:**

```
1. Crear una WPF mínima en Visual Studio
2. Añadir un Windows Application Packaging Project
3. Generar certificado de prueba con el wizard
4. Crear el paquete MSIX (Sideloading mode)
5. Instalar y probar la app empaquetada
6. Inspeccionar lo que generó el wizard
7. Desinstalar limpiamente
```

**Lo que NO hay en esta práctica** (a propósito):

- ❌ Certificado real (Sectigo, DigiCert) → wizard usa self-signed
- ❌ MakeAppx CLI manual (M07-S7.P principal)
- ❌ SignTool CLI manual (M07-S7.P)
- ❌ Auto-update con AppInstaller (M07-S7.6)
- ❌ Distribución a Microsoft Store (M07-S7.P avanzada)
- ❌ Migración desde ClickOnce (M07-S7.7)

**Por qué Visual Studio Wizard:**

- ✅ Cero CLI: todo desde la UI
- ✅ Cero conocimiento previo de manifests
- ✅ Cert self-signed gestionado automáticamente
- ✅ El alumno ve resultado tangible en 30 minutos
- ✅ Modelo mental claro antes de bajar al CLI

**Tiempo estimado:** 45-60 minutos.

**Coste real:** **0€** (solo Visual Studio + Windows local).

**MSIX es Windows-only.** Para hacer esta práctica necesitáis Windows nativo o una VM:


**Verificar Visual Studio Installer:**

```

2. Click "Modify" en VS 2022
3. Pestaña "Workloads":
   ☑ ".NET desktop development"

```

```
→ Developer Mode: ON  (recomendado)
```

**Por qué Sideloading:**

```

- Sideloading permite MSIX firmados con cert confiable
- Sin esto: no podréis instalar el paquete que generéis
```

## Slide 8 — Paso 5: Instalar el certificado

Antes de instalar el MSIX, hay que confiar en el certificado self-signed.

**¿Por qué?**

```
El paquete está firmado con un cert self-signed.
Self-signed = NO viene de una CA confiable (Verisign, DigiCert).
Windows por defecto NO confía en self-signed certs.
→ Hay que añadir el cert a "Trusted Root" o "Trusted People" manualmente.
```

**Método 1: usar el script Install.ps1 (recomendado)**

```powershell
# Abrir PowerShell COMO ADMINISTRADOR (importante)
cd "C:\dev\msix-curso\MiPrimeraMSIX.Package\AppPackages\MiPrimeraMSIX.Package_1.0.0.0_Test\"

# Ejecutar el script de instalación
.\Install.ps1

# Si pregunta:
# Execution Policy: ¿permitir? → A (Yes to All)
# El script:
# 1. Importa el cert .cer al Trusted People store
# 2. Instala el .msix
```

**Método 2: instalación manual (educativo)**

```powershell
# 1. Importar el certificado (como Admin)
$cert = "MiPrimeraMSIX.Package_1.0.0.0_x64.cer"
Import-Certificate -FilePath $cert -CertStoreLocation "Cert:\LocalMachine\TrustedPeople"

# 2. Instalar el MSIX (puede ser usuario normal)
Add-AppPackage -Path "MiPrimeraMSIX.Package_1.0.0.0_x64.msix"
```

**Verificar que instaló correctamente:**

```powershell
# Listar apps instaladas con ese nombre
Get-AppPackage -Name "*MiPrimeraMSIX*" | Select-Object Name, Version, InstallLocation

# Output esperado:
# Name                              Version       InstallLocation
# ----                              -------       ---------------
# MiPrimeraMSIX.Package             1.0.0.0       C:\Program Files\WindowsApps\...
```

**Si falla con "untrusted certificate":**

```
El certificado no está en Trusted People.
Solución:
1. Abrir certmgr.msc (Certificate Manager)
2. Trusted People → Certificates → Import...
3. Seleccionar el .cer del paquete
4. Importar al store "Trusted People"
5. Reintentar Add-AppPackage
```

**Si falla con "developer mode required":**

```
Settings → Privacy & security → For developers
→ Developer Mode: ON
```

```

- Registry virtualizado (no toca el registry real)
- Desinstalación SIEMPRE limpia (Windows lo gestiona)
- Archivos read-only (un usuario no puede modificarlos)
```

Es educativo ver qué hizo el wizard "por debajo". Abrid el `.msix` con un explorador de zips:

**Output esperado:**

```
[AppxBlockMap.xml]      Integrity verification (hash de cada bloque)
[AppxManifest.xml]      Manifest principal
[AppxSignature.p7x]     Firma digital (PKCS#7)
[Content_Types].xml     Tipos MIME del paquete
MiPrimeraMSIX.exe       Vuestro ejecutable
MiPrimeraMSIX.dll       Vuestras DLLs (.NET runtime, deps)

Images/                 Iconos del manifest

```

**Examinar AppxManifest.xml:**

```xml
<?xml version="1.0" encoding="utf-8"?>
<Package xmlns="http://schemas.microsoft.com/appx/manifest/foundation/windows10">
  <Identity Name="MiPrimeraMSIX.Package"
            Publisher="CN=Pedro Pérez"
            Version="1.0.0.0"
            ProcessorArchitecture="x64" />
  <Properties>
    <DisplayName>Mi Primera App MSIX</DisplayName>
    <PublisherDisplayName>Pedro Pérez</PublisherDisplayName>
    <Logo>Images\StoreLogo.png</Logo>
  </Properties>
  <Dependencies>
    <TargetDeviceFamily Name="Windows.Desktop"
                       MinVersion="10.0.17763.0"
                       MaxVersionTested="10.0.22621.0" />
  </Dependencies>
  <Capabilities>
    <rescap:Capability Name="runFullTrust" />
  </Capabilities>
  <Applications>
    <Application Id="App" Executable="MiPrimeraMSIX.exe" EntryPoint="Windows.FullTrustApplication">
      <uap:VisualElements DisplayName="Mi Primera App MSIX" 
                          Description="Práctica del curso AZ-204"
                          Square150x150Logo="Images\Square150x150Logo.png"
                          ... />
    </Application>
  </Applications>
</Package>
```

**Lo más importante a entender:**

```
<Identity>:
- Name + Publisher + Version = clave única del paquete
- Cambio de Publisher → otra app distinta (no es upgrade)
- Cambio de Version → upgrade
- Cambio de Name → otra app distinta

<Capabilities>:
- runFullTrust → la app accede al sistema (no UWP sandboxed)
- Otras: internet, picturesLibrary, location, etc.

<Applications>:
- La entry del menú Start
- Cada Application = una entrada en el Start menu
- Una app puede tener varias Applications (raro)
```

## Slide 11 — Paso 8: Smoke tests automatizados

Script PowerShell que valida la instalación y desinstalación:

```powershell
# Crear smoke-tests.ps1
@'
$ErrorActionPreference = "Stop"

$packageName = "MiPrimeraMSIX.Package"

Write-Host "Smoke tests sobre $packageName"

# Test 1: ¿La app está instalada?
Write-Host -NoNewline "  [1/4] App instalada... "
$pkg = Get-AppPackage -Name $packageName -ErrorAction SilentlyContinue
if ($pkg) {
    Write-Host "OK (v$($pkg.Version))" -ForegroundColor Green
} else {
    Write-Host "FALLO - app no instalada" -ForegroundColor Red
    exit 1
}

# Test 2: ¿Aparece en el menú Start?
Write-Host -NoNewline "  [2/4] Aparece en Start menu... "
$startMenu = Get-StartApps -Name "Mi Primera App MSIX" -ErrorAction SilentlyContinue
if ($startMenu) {
    Write-Host "OK" -ForegroundColor Green
} else {
    Write-Host "FALLO" -ForegroundColor Red
    exit 1
}

# Test 3: ¿El executable existe?
Write-Host -NoNewline "  [3/4] Executable presente... "
$exePath = Join-Path $pkg.InstallLocation "MiPrimeraMSIX.exe"
if (Test-Path $exePath) {
    Write-Host "OK" -ForegroundColor Green
} else {
    Write-Host "FALLO - no encuentra MiPrimeraMSIX.exe" -ForegroundColor Red
    exit 1
}

# Test 4: ¿La firma es válida?
Write-Host -NoNewline "  [4/4] Firma valida... "
$sig = Get-AuthenticodeSignature $exePath
if ($sig.Status -eq "Valid") {
    Write-Host "OK ($($sig.SignerCertificate.Subject))" -ForegroundColor Green
} else {
    Write-Host "AVISO ($($sig.Status))" -ForegroundColor Yellow
    # No exit en este caso porque self-signed puede aparecer como UnknownError
}

Write-Host ""
Write-Host "Todos los tests basicos pasados" -ForegroundColor Green
'@ | Out-File -FilePath smoke-tests.ps1 -Encoding utf8

# Ejecutar
.\smoke-tests.ps1
```

**Output esperado:**

```
Smoke tests sobre MiPrimeraMSIX.Package
  [1/4] App instalada... OK (v1.0.0.0)
  [2/4] Aparece en Start menu... OK
  [3/4] Executable presente... OK
  [4/4] Firma valida... OK (CN=Pedro Pérez)

Todos los tests basicos pasados
```

**Test manual adicional:**

```
1. Abrir la app desde Start menu
2. Click en "Mostrar info de la app"
3. Verificar MessageBox aparece con info correcta
4. Cerrar la app
```

## Slide 13 — Variante: instalar con doble-click (para usuarios finales)

El método PowerShell es para devs. Para usuarios finales, MSIX se instala con doble-click:

**Modo: instalación gráfica:**

```
1. Hacer doble-click sobre el archivo .msix
2. Aparece "App Installer" (built-in en Windows)
3. Muestra:
   - Display name
   - Publisher (nombre del cert)
   - Versión
   - Capabilities solicitadas
4. Click "Install"
5. Espera ~10 segundos
6. App instalada
```

**Cuándo App Installer NO funciona:**

```
❌ Si el cert NO está en Trusted People:
   "This app package is not signed with a trusted certificate"
   Solución: instalar el cert manualmente primero (certmgr.msc)

❌ Si la app es un major version downgrade:
   Solución: desinstalar primero la versión anterior
   
❌ Si Windows no es 1809+:
   Solución: actualizar Windows
```

**Comparativa: 3 métodos de instalación:**

| Método | Cuándo | Quién |
|---|---|---|
| **Doble-click .msix** | Usuario final con cert ya confiable | Final users |
| **PowerShell `Add-AppPackage`** | Devs / sysadmins / scripting | Devs |
| **Microsoft Store** | Distribución pública | All |

**Para distribución empresarial:**


```powershell
# Desinstalar la app MSIX
Get-AppPackage -Name "MiPrimeraMSIX.Package" | Remove-AppPackage

# Verificar que se desinstaló
```

```powershell

  Where-Object { $_.Subject -like "*<vuestro-nombre>*" }

# Eliminar (necesita Admin)
Get-ChildItem -Path "Cert:\LocalMachine\TrustedPeople" |
  Where-Object { $_.Subject -like "*<vuestro-nombre>*" } |
  ForEach-Object { Remove-Item $_.PSPath -Force }
```

**Limpiar archivos del proyecto:**

```powershell

Remove-Item "C:\dev\msix-curso\MiPrimeraMSIX" -Recurse -Force

# - El código fuente

# - Los archivos zip de inspección
```

## Slide 15 — Comparativa: Wizard vs CLI manual

¿Por qué hay dos prácticas (esta y la M07-S7.P principal)?

| Aspecto | Wizard (S7.P2) | **CLI manual (S7.P)** |
|---|---|---|
| **Tiempo de setup** | 5 minutos | **30-60 minutos** |
| **Comprensión profunda** | Media | **Alta** |
| **Customización** | Limitada | **Total** |
| **Reproducibilidad** | UI manual | **Scripts versionables** |
| **CI/CD friendly** | No | **Sí (todo CLI)** |
| **Cert** | Self-signed wizard | **Cualquier cert (real, vault, etc.)** |
| **Manifest** | Editor visual | **XML manual completo** |
| **Para qué nivel** | Junior / introducción | **Senior / producción** |

**El wizard hace por debajo:**

```
1. Calls makeappx.exe pack /d <build-output> /p <output.msix>
2. Calls signtool.exe sign /fd SHA256 /a /f <cert.pfx> <output.msix>
3. Genera Install.ps1 con:
   - Import-Certificate del .cer
   - Add-AppPackage del .msix
4. Genera AppInstaller.xml (si auto-update está habilitado)
```

**Cuándo wizard:**

```
✅ Aprendiendo MSIX por primera vez
✅ Apps simples (single-app, single-arch)
✅ Distribución a un grupo pequeño
✅ Probar rápido el formato
✅ Desarrollos individuales
```

**Cuándo CLI (M07-S7.P principal):**

```
✅ Pipeline CI/CD automatizado (Azure DevOps, GitHub Actions)
✅ Cert real desde Key Vault
✅ Múltiples plataformas (x86 + x64 + ARM64)
✅ Múltiples idiomas
✅ Modificaciones avanzadas del manifest
✅ Distribución corporativa con AppInstaller + auto-update
✅ Equipo grande / proyecto grande
```

**Patrón típico en empresas:**

```
Devs: usan wizard en local (rápido, iterativo)
Pipelines: usan CLI (reproducible, automatizado)

Mismo formato MSIX al final, distintos paths para llegar.
```

## Slide 16 — Troubleshooting: errores comunes

Los 6 errores más típicos al empaquetar MSIX y cómo resolverlos:

**1. "0x80073CFD: The current user does not have permission..."**

```
Causa: el cert no está en Trusted People (o no en LocalMachine)
Síntoma: instalación falla con código 0x80073CFD

Diagnóstico:
  Get-ChildItem -Path "Cert:\LocalMachine\TrustedPeople" |
    Where-Object Subject -like "*<vuestro-publisher>*"

Si vacío:
  Import-Certificate -FilePath cert.cer -CertStoreLocation "Cert:\LocalMachine\TrustedPeople"
  (necesita PowerShell como admin)
```

**2. "Add-AppPackage: Cannot install package due to..."**

```
Causa común: Sideloading no habilitado
Diagnóstico:
  Settings → Privacy & security → For developers
  
Fix:
  Developer Mode: ON
  
O sin Developer Mode:
  Sideload apps: ON (en lugar de "Microsoft Store only")
```

**3. "MSB3325: Cannot import the following key file..."**

```
Causa: el .pfx no encuentra la password o la clave privada
Síntoma: error al compilar el packaging project

Fix:
- Eliminar el certificado del proyecto
- Volver a lanzar el wizard "Create App Packages"
- Re-crear el cert con password vacía
```

**4. "The file is not digitally signed"**

```
Causa: olvidasteis firmar el .msix
Síntoma: aparece warning al instalar

Verificar:
  Get-AuthenticodeSignature MiPrimeraMSIX.Package_1.0.0.0_x64.msix

Si dice "NotSigned":
  Volver al wizard y asegurad que seleccionasteis cert
```

**5. "Cannot register package because..."**

```
Causa: ya existe una versión instalada con publisher distinto
Síntoma: install falla porque el publisher cambió

Fix:
  # Desinstalar primero la versión anterior
  Get-AppPackage -Name "MiPrimeraMSIX.Package" | Remove-AppPackage
  
  # Luego instalar la nueva
  Add-AppPackage -Path nueva-version.msix
```

**6. "App not appearing in Start menu"**

```
Causa: instalación con error silencioso, o icono no se renderizó
Diagnóstico:
  Get-AppPackage -Name "MiPrimeraMSIX.Package" | Format-List

Verificar:
- Status: Ok (no Error)
- IsResourcePackage: False
- SignatureKind: Developer

Fix:
  # Reinstalar
  Remove-AppPackage MiPrimeraMSIX.Package_...
  Add-AppPackage -Path MiPrimeraMSIX.Package_...msix
```

**Logs detallados:**

```
Event Viewer → Windows Logs → Application
Filtrar por "AppX" o "AppxDeploymentClient"
Veréis eventos de instalación con motivo del fallo
```

## Slide 17 — Limitaciones del Wizard a saber

Conviene saber qué NO podéis hacer con el wizard (motivación para CLI):

**Limitación 1: cert siempre self-signed o seleccionado de cert store**

```
Wizard no permite:
- Cert desde Azure Key Vault
- Cert desde HSM externo
- Cert desde Windows Update (CA pública)

CLI sí permite:
- signtool /fd SHA256 /sha1 <cert-thumbprint> /tr <timestamp-server>
- Acceso a cert por thumbprint en Trusted Root
```

**Limitación 2: una sola architecture por wizard run**

```
Wizard genera UN .msix por arquitectura seleccionada (x64 o x86 o ARM64).

Para distribución multi-arch:
- Necesitáis un "bundle" .msixbundle (multiple .msix juntos)
- Wizard NO genera bundles
- CLI: makeappx bundle ...
```

**Limitación 3: no genera AppInstaller automáticamente**

```
Wizard puede crear AppInstaller básico, pero:
- Sin URL de update server
- Sin reglas de update (forced, optional)
- Sin tracking de versiones

Para auto-update real:
- Generar AppInstaller XML manualmente
- O usar pipeline que lo genere
```

**Limitación 4: limited modifications del manifest**

```
El editor visual del manifest cubre:
✅ Display name, description
✅ Visual assets
✅ Capabilities estándar
✅ File associations básicas
✅ Protocol handlers básicos

NO cubre directamente (necesita XML manual):
❌ Restricted capabilities (rescap)
❌ App execution aliases
❌ Background tasks
❌ Custom AppX extensions
❌ Multi-app packages (varias entries)
```

**Limitación 5: sin pre-build customization**

```
En CI/CD real necesitáis:
- Inyectar versión desde Git tag
- Variables de entorno en el manifest
- Templating del manifest

Wizard:
- Versión manual o auto-increment
- Manifest fijo en disco

Alternativa: usar Build Targets + msbuild que modifican el manifest pre-build.
```

**Por qué importa entender estas limitaciones:**

```
Para empezar: wizard es perfecto.
Para producción real con equipo: CLI/pipeline es esencial.
La M07-S7.P principal os enseña ESE flujo.
```

## Slide 18 — Cuándo MSIX vs alternativas

Tras esta práctica, conviene situar MSIX en el panorama de empaquetado Windows:

| Formato | Cuándo |
|---|---|
| **MSIX** | Apps Windows 10+, distribución managed, Microsoft Store, intune |
| **MSI** | Legacy, Windows pre-Win10, infraestructura WIX/InstallShield |
| **EXE setup** | Apps con instalación compleja (Inno Setup, NSIS) |
| **ClickOnce** | Apps simples .NET con auto-update built-in |
| **Portable .exe** | Apps zero-install (descomprimir y ejecutar) |
| **Microsoft Store** | Distribución pública con monetización |
| **WinGet** | Distribución por línea de comandos (`winget install ...`) |

**Comparativa MSIX vs MSI:**

```
MSI (legacy):
- Estándar desde 1999
- Instalación: write to Program Files + registry
- Desinstalación: a veces deja restos
- Update: in-place upgrade vía MSI Transform
- Soporte: activo pero "legacy"

MSIX (moderno):
- Desde Windows 10 1709 (2017)
- Instalación: container aislado en WindowsApps
- Desinstalación: SIEMPRE limpia
- Update: automático con AppInstaller
- Soporte: "el futuro" pero adopción lenta
```

**Comparativa MSIX vs ClickOnce (M07-S7.4 / S7.7 explora esto):**

```
ClickOnce:
✅ Auto-update built-in
✅ Sandbox de seguridad
✅ No requiere admin
❌ Limited a apps .NET
❌ UI/UX dated
❌ Microsoft lo desactualizará en algún momento

MSIX:
✅ Cross-tech (.NET, C++, Python apps...)
✅ Better security model (containers)
✅ Auto-update con AppInstaller
✅ Microsoft Store distribution
❌ Curva de aprendizaje mayor
❌ Cert real cuesta dinero (~€200/año)
❌ Adopción lenta en empresas
```

**Para apps NUEVAS:**

```
Recomendación 2026:
✅ MSIX si vuestra app es Windows-only
✅ MSIX para distribución a usuarios externos
✅ MSI/Inno solo si tenéis legacy infrastructure pesada

Para empresas internas:
- Empezad con MSIX directamente
- Distribuíd con AppInstaller en intranet
- Migrad a Microsoft Store si vais a vender
```
