## Slide 2 — Qué vais a hacer

Instalar Claude Code, hacer vuestra primera sesión y resolver un par de tareas reales: leer un proyecto, explicar código, modificar un archivo, ejecutar tests. Sin servidores MCP, sin sub-agentes, sin orquestaciones — la experiencia base.

**El recorrido:**

```
1. Instalar Claude Code (CLI)
2. Hacer login con vuestra cuenta Anthropic
3. Primera sesión: "explícame este repo"
4. Modificar un archivo guiado por Claude
5. Crear un CLAUDE.md mínimo (memoria del proyecto)
6. Pedirle hacer tests / ejecutar comandos
7. Aprender los slash commands esenciales
8. Cerrar sesión limpiamente
```

**Lo que NO hay en esta práctica** (a propósito):

- ❌ Servidores MCP (eso es M09-S9.P / M09-S9.4)
- ❌ Sub-agentes (avanzado)
- ❌ Hooks (avanzado)
- ❌ CLAUDE.md complejo con jerarquía (M11)
- ❌ Integraciones con Azure / Notion / GitHub (M11)
- ❌ Pipelines IA-augmented (M11)

**Por qué empezar así:**

- ✅ Claude Code es enormemente potente, pero abruma
- ✅ La barrera real no es técnica, es mental: "¿qué le pido?"
- ✅ Esta práctica os da las primeras 5-10 interacciones útiles
- ✅ Una vez sentís el flujo, todo lo demás es escalado

**Tiempo estimado:** 45-60 minutos.

**Coste real:** depende del plan Anthropic. Esta práctica consume ~5-10 mensajes (céntimos en API, gratis en Pro).

## Slide 8 — Paso 5: Permission modes — entender qué se aprueba

Por defecto, Claude pide permiso antes de cada operación que modifique algo. Hay 3 modos:

**Default (recomendado):**

```
- Lectura de archivos: automática (sin prompt)
- Escritura de archivos: pide permiso (y/N)
- Ejecución de comandos: pide permiso (y/N)
- Comandos peligrosos (rm, etc.): pide permiso EXPLÍCITO
```

**Acceptedits (más fluido):**

```
> /permissions

Set mode to: acceptEdits
- Edits a archivos: AUTO sin pedir permiso
- Comandos shell: siguen pidiendo permiso
- Útil cuando estáis en flujo iterativo
```

**Plan mode (planificar sin ejecutar):**

```
> /plan

Modo:
- Claude HACE plan pero NO ejecuta nada
- Útil para grandes refactorings: ver el plan antes de ejecutarlo
- Vosotros aprobáis el plan completo, luego ejecuta
```

**Cambiar de modo en sesión:**

```
> /permissions

Esto abre un selector con las opciones.
Podéis cambiar varias veces en la misma sesión.
```

**Cuándo usar cada modo:**

| Modo | Cuándo |
|---|---|
| **Default** | Aprendiendo, o tareas críticas |
| **acceptEdits** | Iterando en código que conocéis bien |
| **plan** | Antes de un refactor grande |

**Comando especial: bypassPermissions**

```bash
# Lanzar sin pedir CASI nada (uso experto)
claude --dangerously-skip-permissions

# ⚠️ Solo para tareas que confiáis 100%
# Claude puede borrar archivos, ejecutar rm -rf, etc.
# Para esta práctica: NO lo uséis
```

## Slide 9 — Paso 6: Slash commands esenciales

Dentro de la sesión, Claude responde a comandos especiales que empiezan con `/`:

**Los más útiles para esta práctica:**

```
/help           Ver ayuda
/clear          Limpiar pantalla
/compact        Compactar el contexto (cuando llega al límite)
/permissions    Cambiar modo de permisos
/exit           Salir de Claude Code
/cost           Ver consumo de tokens de la sesión
/model          Cambiar de modelo (Opus, Sonnet, Haiku)
/init           Generar CLAUDE.md inicial para el proyecto
```

**Probar `/help`:**

```
> /help

Available commands:
  /help          Show this help
  /clear         Clear the screen
  /compact       Compact conversation history
  ... (etc.)
```

**Probar `/cost`:**

```
> /cost

Tokens used in this session: 3,420
Cost estimate: $0.05
```

**Probar `/model`:**

```
> /model

Currently: claude-opus-4.7
Available:
- claude-opus-4.7 (más potente, más caro)
- claude-sonnet-4.6 (balance)
- claude-haiku-4.5 (rápido, barato)

Select: ...
```

**Tip pro:**

```
- Para tareas COMPLEJAS (refactors grandes): Opus
- Para tareas SIMPLES (renombrar variables, fix bugs): Sonnet o Haiku
- Para iteración rápida: Haiku (mucho más rápido)
```

**Personalizar slash commands:**

```bash
# Crear vuestro propio comando custom
mkdir -p ~/.claude/commands

cat > ~/.claude/commands/explain.md << 'EOF'
Read the file path provided as $ARGUMENTS and provide:
1. A 2-line summary
2. Main classes/functions and their purpose
3. Anti-patterns or smells if any
4. Suggested improvements
EOF

# Ahora dentro de Claude:
> /explain Program.cs
```

**Estructura de comandos custom:**

```
~/.claude/commands/<name>.md      → comando personal disponible siempre
.claude/commands/<name>.md         → comando del proyecto (compartible via git)
```

```
Ejemplo de output:
```

```markdown
## Overview
This is a .NET 8 sample console application that demonstrates:
- Calling REST APIs with HttpClient
- Parsing JSON responses with System.Text.Json
- Async/await patterns

## Tech Stack

- Program.cs: entry point and main logic
- *.csproj: project file with dependencies

- Run: `dotnet run`
- Test: `dotnet test` (if test project exists)

- Async methods end with "Async"
- Use record types for DTOs
- Public APIs follow PascalCase
```

**Editar el CLAUDE.md generado:**

```
> Edita el CLAUDE.md y añade una sección "Lessons learned" que diga
> "Esta es una práctica del curso AZ-204 de Pedro".
```

**Claude lo edita.**

**Verificar el resultado:**


## Slide 12 — Trucos: cómo escribir buenos prompts

Los primeros prompts suelen ser malos. Aquí lo que mejora resultados:

**Anti-pattern 1: muy genérico**

```
❌ "Mejora el código"
   → Claude no sabe qué priorizar

✅ "Refactoriza Program.cs para extraer la llamada HTTP a un método 
    separado llamado FetchRepositoriesAsync"
   → Claude sabe exactamente qué hacer
```

**Anti-pattern 2: pedirle que adivine**

```
❌ "Arregla los bugs"
   → ¿Qué bugs? Claude inventará algunos

✅ "Cuando ejecuto el programa, sale: 'NullReferenceException 
    at line 23'. Mira esa línea y arrégla el problema"
   → Claude tiene el síntoma y la pista
```

**Anti-pattern 3: dar TODO de golpe**

```
❌ "Crea una API REST con auth, BBDD, tests, CI/CD, y deploy"
   → Claude lo intentará pero saldrá una mezcla mediocre

✅ Iterar:
   "Crea el esqueleto de la API"
   → revisar
   "Añade EF Core y un endpoint GET /productos"
   → revisar
   "Ahora añade tests para ese endpoint"
   → revisar
```

**Patrón muy útil: confirmación previa**

```
> "Antes de implementar, dime CÓMO lo harías y por qué."

Claude responde con plan, vosotros confirmáis o ajustáis,
LUEGO le decís "vale, hazlo".

→ Os ahorra deshacer cambios cuando vais por mal camino
```

**Patrón pro: usar el "rubber duck"**

```
> "Estoy intentando hacer X pero me da Y error. 
> Mi enfoque actual es Z. ¿Me explico mal en algo?"

Claude no solo arregla; te ayuda a pensar mejor.
```

**Cuándo NO usar Claude Code:**

```
❌ Tareas críticas de seguridad sin revisar (Claude puede meter bugs sutiles)
❌ Cuando ya sabéis exactamente qué hacer (a veces es más rápido vosotros)
❌ Para "evitar pensar" (estaréis dependiendo demasiado)
❌ Para producción si no tenéis tests sólidos

✅ Exploración de código nuevo
✅ Refactorings rutinarios
✅ Boilerplate (setup de proyectos, configs)
✅ Cuando el "qué" está claro pero el "cómo" no
```

## Slide 13 — Variantes: API key vs claude.ai login

Dos formas de autenticar Claude Code, según el caso:

**Opción A: Login con claude.ai (lo que hicisteis)**

```bash
claude
# → Login navegador
# → Sesión activa
```

**Pros:**
```
✅ Setup en 30 segundos
✅ Si tenéis Pro/Max, sin coste extra (incluido)
✅ No hay key que rotar
✅ Recomendado para uso personal/equipo
```

**Contras:**
```
❌ Sesión limitada a vuestra cuota del plan
❌ No funciona en CI/CD (no hay browser)
❌ Si rotáis password, hay que re-login
```

**Opción B: API key**

```bash
# Configurar API key
export ANTHROPIC_API_KEY="sk-ant-..."

claude  # ahora usa la key, no el login
```

**Pros:**
```
✅ Funciona en CI/CD
✅ Coste por uso (no plan fijo)
✅ Útil para automation / scripts
```

**Contras:**
```
❌ Coste no acotado (si Claude consume mucho, paga la cuenta)
❌ Hay que gestionar/rotar la key
❌ Setup más complicado
```

**Cambiar de modo:**

```bash
# Logout (vuelve a estado inicial)
claude logout

# Re-login
claude
# → te pregunta de nuevo: claude.ai vs API key
```

**Cuándo usar cada una:**

```
Uso personal / equipo:        Login con claude.ai
Side projects:                Login con claude.ai
Pipelines CI/CD:              API key (en GitHub Secrets / ADO Variables)
Automatización scripts:       API key
Probar Claude por primera vez: Login con claude.ai (más fácil)
```

**Para esta práctica:** ya estáis en login claude.ai. No cambiéis nada.

## Slide 14 — Smoke tests automatizados

¿Cómo validar que vuestra instalación de Claude Code funciona? Test rápido:

```bash
cat > smoke-tests.sh << 'EOF'
#!/bin/bash
set -e

echo "🔍 Smoke tests de Claude Code"

# Test 1: Comando claude existe
echo -n "  [1/5] Comando claude instalado... "
if command -v claude &> /dev/null; then
  echo "✓ ($(which claude))"
else
  echo "✗ no instalado"
  exit 1
fi

# Test 2: Versión correcta
echo -n "  [2/5] Versión >= 1.0... "
VERSION=$(claude --version 2>&1 | grep -oE '[0-9]+\.[0-9]+\.[0-9]+' | head -1)
if [ -n "$VERSION" ]; then
  echo "✓ ($VERSION)"
else
  echo "✗"
  exit 1
fi

# Test 3: Login activo
echo -n "  [3/5] Sesión autenticada... "
if claude auth status 2>&1 | grep -qi "authenticated\|logged in"; then
  echo "✓"
else
  echo "✗ no autenticado (ejecutar: claude)"
fi

# Test 4: ~/.claude existe
echo -n "  [4/5] Directorio ~/.claude... "
if [ -d "$HOME/.claude" ]; then
  echo "✓"
else
  echo "✗"
fi

# Test 5: Directorio actual tiene CLAUDE.md (opcional)
echo -n "  [5/5] CLAUDE.md en proyecto... "
if [ -f "CLAUDE.md" ]; then
  echo "✓"
else
  echo "ℹ  (opcional, recomendado)"
fi

echo ""
echo "✅ Claude Code listo para usar"
EOF

chmod +x smoke-tests.sh
./smoke-tests.sh
```

**Output esperado:**

```
🔍 Smoke tests de Claude Code
  [1/5] Comando claude instalado... ✓ (/usr/local/bin/claude)
  [2/5] Versión >= 1.0... ✓ (1.0.5)
  [3/5] Sesión autenticada... ✓
  [4/5] Directorio ~/.claude... ✓
  [5/5] CLAUDE.md en proyecto... ✓

✅ Claude Code listo para usar
```

**Si algún test falla:**

```
[1/5] FAIL → npm install -g @anthropic-ai/claude-code
[2/5] FAIL → npm update -g @anthropic-ai/claude-code
[3/5] FAIL → ejecutar `claude` y completar login
[4/5] FAIL → ejecutar `claude` al menos una vez (lo crea)
[5/5] FAIL → ejecutar `/init` dentro de Claude Code
```

## Slide 15 — Comparativa: Claude Code vs alternativas

¿Cómo encaja Claude Code en el ecosistema de IA-coding?

| Herramienta | Modelo | UI | Acceso a archivos | Ejecuta comandos |
|---|---|---|---|---|
| **Claude Code** | Claude (Opus/Sonnet/Haiku) | CLI | ✅ | ✅ con permiso |
| **GitHub Copilot** | Codex/GPT-4 | IDE inline | ✅ (autocompletado) | ❌ |
| **Cursor** | Multi-modelo | IDE completo | ✅ | ✅ con permiso |
| **Aider** | Multi-modelo | CLI | ✅ | ✅ |
| **ChatGPT** | GPT-4/o1 | Web chat | ❌ (copy-paste) | ❌ |
| **Claude.ai** | Claude | Web chat | ❌ (file upload) | ❌ |

**Cuándo Claude Code sobresale:**

```
✅ Tareas multi-archivo (refactorings, migraciones)
```

## Slide 17 — Troubleshooting: errores comunes

Los 6 errores más típicos al empezar con Claude Code:

**1. "claude: command not found"**

```
Causa: el binario no está en el PATH
Diagnóstico:
  npm list -g | grep claude-code
  
Si lista aparece pero claude no se encuentra:
- npm config get prefix → ver dónde instaló
- Añadir esa carpeta /bin al PATH

Si la lista está vacía:
- Reinstalar: npm install -g @anthropic-ai/claude-code
```

**2. "EACCES: permission denied" al instalar**

```
Causa: npm intenta escribir en directorios de sistema
Síntoma: error durante npm install -g

Fix Mac/Linux:
  mkdir -p ~/.npm-global
  npm config set prefix ~/.npm-global
  echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.zshrc
  source ~/.zshrc
  npm install -g @anthropic-ai/claude-code

Fix Windows: ejecutar PowerShell como Administrator
```

**3. "Login failed in browser"**

```
Causa: redirect URL bloqueado o popup bloqueado
Diagnóstico:
- ¿Veis la página de login de Claude.ai pero no vuelve a la terminal?

Fix:
- Permitir popups en claude.ai
- O usar otro navegador (Chrome / Firefox)
- O usar API key en lugar de login web
```

**4. "Rate limit exceeded"**

```
Causa: superado el limit de mensajes/minuto del plan
Síntoma: error tras varios mensajes seguidos

Fix:
- Esperar 1-5 minutos
- /model: cambiar a Haiku o Sonnet (límites más altos)
- O actualizar plan a Pro/Max
```

**5. "Session keeps disconnecting"**

```
Causa: contexto demasiado grande o conexión inestable
Síntoma: Claude pierde memoria de mensajes anteriores

Fix:
- /compact (compactar el contexto antiguo)
- /clear (empezar pantalla limpia, mantiene contexto)
- En sesiones muy largas: /exit y volver a empezar
```

**6. "Claude no puede leer archivos fuera del directorio"**

```
Causa: por defecto solo accede al cwd y subdirectorios
Síntoma: "I can't access /etc/passwd" (lo cual está bien)

Fix:
- Mover los archivos al working directory
- O cambiar el cwd:
  cd /otro/directorio
  claude
```

**Cuando nada funciona — reset:**

```bash
# Logout
claude logout

# Limpiar cache
rm -rf ~/.claude/cache  # si existe

# Reinstalar
npm uninstall -g @anthropic-ai/claude-code
npm install -g @anthropic-ai/claude-code

# Re-login
claude
```

## Slide 18 — Buenas prácticas

Si vais a usar Claude Code en serio (que recomendamos):

**1. Usad CLAUDE.md SIEMPRE**

```
- Ahorra contexto en cada sesión
- Documenta convenciones del proyecto
- Cualquier humano nuevo también lo aprovecha
- Commitearlo a Git
```

**2. Modo permission según fase**

```
Fase exploratoria: default (con permisos)
Fase iterativa rápida: acceptEdits
Refactor grande: plan mode antes de ejecutar
NUNCA: bypassPermissions sin razón muy clara
```

**3. Confirma planes antes de ejecutar grandes cambios**

```
> "Antes de hacer nada, dame el plan."

Os ahorra deshacer cambios.
Os ayuda a aprender qué hace Claude.
```

**4. Iteración pequeña > prompt mega-detallado**

```
❌ Un prompt de 30 líneas con todo lo que queréis
✅ Iterar con prompts cortos, validando entre cada paso
```

**5. Usad git como red de seguridad**

```
- Commit antes de cualquier cambio grande
- Si Claude rompe algo: git reset --hard
- Branch para experimentos: git checkout -b experiment-claude
```

**6. Contexto vs costes**

```
Sesión muy larga = más coste por mensaje
- /compact periódicamente
- /clear cuando cambias de tarea
- Empezad sesiones nuevas para contextos diferentes
```

**7. Slash commands customs para flujos repetitivos**

```bash
# .claude/commands/review.md
Lee los archivos modificados (git diff HEAD).
Valida:
- Tests presentes
- No secrets
- Sigue convenciones del CLAUDE.md
- Sin código muerto

Devuelve un resumen estilo PR review.
```

```
> /review
```

**8. NO uséis Claude Code para:**

```
❌ Migraciones de BBDD productivas sin revisar a fondo
❌ Eliminar archivos sin verificar
❌ Cualquier cosa que no entendáis
❌ "Hazlo todo, no pregunto"
```

## Slide 20 — Retos opcionales

**Reto 1 — Slash command custom**

Crear un comando custom `/review` que valide el código modificado:

```bash
mkdir -p .claude/commands

cat > .claude/commands/review.md << 'EOF'
Read the files changed by `git diff HEAD` and review them like a code reviewer.
Check for:
1. Missing tests
2. Hardcoded secrets
3. Magic numbers
4. Naming conventions per CLAUDE.md
5. Dead code

Provide a summary with severity (low/medium/high) and specific suggestions.
EOF

# En Claude:
> /review
```

**Reto 2 — Refactor guiado**

Pedirle a Claude:

```
> Refactoriza Program.cs para extraer toda la lógica HTTP a una 
> clase GitHubClient. Mantén el comportamiento idéntico. 
> Antes de hacer nada, muéstrame el plan.
```

Verificad que el plan es razonable. Aprobad si es así. Sin no, ajustad.

Introducir un bug a propósito:

```csharp
// En Program.cs, cambiar Take(10) por Take(-1) 
// → genera ArgumentOutOfRangeException al ejecutar
```

Pedirle a Claude:

```
> Cuando ejecuto el programa, sale: 
> "ArgumentOutOfRangeException: count must be non-negative"
> Encuentra el problema y arréglalo.
```

**Reto 4 — Probar dos modelos**

- Coste

```
> "Refactoriza Program.cs"
```
