## Slide 2 — Contexto: IA para desarrollo en 2026
La IA generativa ha cambiado cómo se escribe código. No reemplaza al desarrollador — amplifica su capacidad. Claude Code es una herramienta de línea de comandos que pone un agente IA directamente en vuestro terminal, con acceso al filesystem, git, y herramientas externas vía MCP.

**Lo que Claude Code puede hacer:**
- Generar código a partir de descripciones en lenguaje natural
- Refactorizar código existente
- Escribir tests para código existente
- Crear archivos Bicep/YAML/Dockerfile desde especificaciones
- Depurar errores analizando logs y stack traces
- Ejecutar comandos y analizar resultados

## Slide 3 — Instalar Claude Code
```bash
# Instalar (requiere Node.js 18+)
npm install -g @anthropic-ai/claude-code

# Verificar
claude --version

# Autenticar (obtener API key en console.anthropic.com)
claude auth login
# O con variable de entorno
export ANTHROPIC_API_KEY="sk-ant-..."
```

**Requisitos:** Node.js 18+, terminal (bash, zsh, PowerShell), cuenta Anthropic con API key.

## Slide 4 — Primer uso: el flujo básico
```bash
# Navegar al proyecto
cd mi-proyecto-dotnet

# Iniciar Claude Code
claude

# Ahora estáis en modo interactivo:
> Analiza la estructura de este proyecto y dime qué hace

> Añade un endpoint GET /api/health que devuelva status ok y la versión

> Escribe tests unitarios para el servicio PedidoService

> Genera un archivo Bicep para desplegar esta app en Azure
```

Claude Code lee los archivos del proyecto, entiende el contexto, y genera código directamente en los archivos. No copia-pega — edita.

## Slide 5 — Claude Code vs GitHub Copilot: diferencias clave

| | Claude Code | GitHub Copilot |
|---|:---:|:---:|
| **Modelo** | Claude (Anthropic) | GPT-4/Codex (OpenAI) |
| **Interfaz** | Terminal (CLI) | IDE (VS Code, JetBrains) |
| **Contexto** | Proyecto completo | Archivo actual + vecinos |
| **Agente** | Sí (ejecuta comandos, edita archivos) | Parcial (Copilot Workspace) |
| **MCP** | Sí (conecta con herramientas) | No |
| **Multi-archivo** | Sí (edita N archivos en un paso) | Limitado |
| **Ejecución** | Puede ejecutar build, test, deploy | No (solo genera código) |
| **Coste** | API usage (~$10-50/mes) | $10-19/mes (fijo) |

**No son excluyentes.** Copilot para autocompletado en el IDE. Claude Code para tareas más grandes (generar módulos, refactorizar, IaC, debugging).

## Slide 6 — Configuración del proyecto para Claude Code
```bash
# Crear archivo de contexto para Claude Code
cat > .claude/config.yml << EOF
context:
  - "Este es un proyecto .NET 8 con Azure App Service, Cosmos DB y Azure Functions"
  - "Usamos Azure DevOps para CI/CD"
  - "Managed Identity para conexiones (sin connection strings con password)"
  - "El stack es: Blazor frontend, API backend, Functions para procesamiento async"
  
conventions:
  - "Usar ILogger para logging, no Console.Write"
  - "Async/await en todas las operaciones I/O"
  - "DTOs con records, no clases"
  - "Tests con xUnit + FluentAssertions"
  - "Nombres en inglés, comentarios en español"
EOF
```

## Slide 7 — Casos de uso prácticos: generación de código

```bash
# Generar un servicio completo
> Crea un servicio PedidoService con:
  - GetByIdAsync(string id) que lea de Cosmos DB
  - CreateAsync(CrearPedidoDto dto) que valide y guarde
  - ListByClienteAsync(string clienteId) con paginación
  - Inyectar CosmosClient por constructor
  - Usar ILogger para logging estructurado

# Generar tests para el servicio
> Escribe tests unitarios para PedidoService usando xUnit, Moq y FluentAssertions.
  Mockea CosmosClient y verifica todos los escenarios: éxito, not found, validación fallida.

# Generar endpoint API
> Crea un minimal API endpoint para PedidoService en Program.cs con:
  - GET /api/pedidos/{id}
  - POST /api/pedidos
  - GET /api/pedidos?clienteId=xxx&page=1&pageSize=20
  - Autenticación con [Authorize]
  - Responses correctos (200, 201, 404, 400)
```

## Slide 11 — Seguridad con Claude Code

**Lo que Claude Code NO debe hacer:**
- Acceder a secretos de producción
- Ejecutar comandos destructivos sin confirmación
- Tener la API key hardcodeada en repos

**Buenas prácticas:**
```bash
# Claude Code pide confirmación antes de ejecutar comandos
# Modo --ask-before-execute (default)
claude --ask-before-execute

# Limitar qué directorios puede leer
# .claude/config.yml
exclude:
  - "*.env"
  - ".secrets"
  - "local.settings.json"
  - "*.pfx"
```

## Slide 13 — Claude Code: modos de ejecución

```bash
# Modo interactivo (conversación)
claude
> Analiza este proyecto y sugiere mejoras

# Modo one-shot (un solo comando)
claude -p "Crea un Dockerfile multi-stage para esta app .NET 8"

# Modo pipe (leer de stdin)
cat error-log.txt | claude -p "Analiza estos errores y sugiere la causa raíz"

# Modo con archivo de contexto
claude -p "Revisa main.bicep y añade Application Insights" --allowedTools bash,write

# Modo headless (en scripts/pipelines)
claude -p "Ejecuta dotnet test y reporta el resultado" --no-interactive
```

## Slide 17 — Claude Code en CI/CD: automatización

```yaml
# Pipeline step: Code review automático con Claude Code
- script: |
    # Obtener diff del PR
    git diff origin/main...HEAD > changes.diff
    
    # Análisis con Claude Code
    cat changes.diff | claude -p "Revisa este diff y reporta:
    1. Problemas de seguridad (crítico)
    2. Problemas de rendimiento (medio)
    3. Violaciones de convenciones (bajo)
    Formato: JSON con {severity, file, line, description}" \
    --no-interactive > review.json
    
    # Verificar si hay problemas críticos
    CRITICAL=$(cat review.json | jq '[.[] | select(.severity=="critical")] | length')
    if [ "$CRITICAL" -gt 0 ]; then
      echo "##vso[task.logissue type=error]$CRITICAL critical issues found"
      cat review.json | jq '.[] | select(.severity=="critical")'
      exit 1
    fi
  displayName: 'AI Code Review'
```
