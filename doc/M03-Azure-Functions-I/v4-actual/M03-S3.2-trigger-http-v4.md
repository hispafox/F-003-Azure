## Slide 2 — Qué es un HTTP Trigger
El HTTP trigger convierte una Azure Function en un endpoint de API. Recibe una petición HTTP y devuelve una respuesta.

Es el trigger más usado y el más intuitivo: funciona exactamente como un controlador de ASP.NET Core, pero sin el boilerplate de un proyecto web completo.

**Cuándo usarlo:**
- APIs REST simples (CRUD, webhooks, callbacks)
- Endpoints auxiliares que no justifican un App Service entero
- Webhooks de servicios externos (GitHub, Stripe, Azure DevOps)
- APIs de tráfico esporádico donde pagar un plan 24/7 no tiene sentido

## Slide 3 — HTTP Trigger mínimo (Isolated Worker)

```csharp
using Microsoft.Azure.Functions.Worker;
using Microsoft.Azure.Functions.Worker.Http;
using System.Net;

public class HolaMundo
{
    [Function("HolaMundo")]
    public HttpResponseData Run(
        [HttpTrigger(AuthorizationLevel.Anonymous, "get")] 
        HttpRequestData req)
    {
        var response = req.CreateResponse(HttpStatusCode.OK);
        response.Headers.Add("Content-Type", "application/json");
        response.WriteString("{\"mensaje\": \"Hola desde Azure Functions!\"}");
        return response;
    }
}
```

**URL resultante:**
- Local: `http://localhost:7071/api/HolaMundo`
- Azure: `https://mi-func.azurewebsites.net/api/HolaMundo`

El prefijo `api/` es configurable en `host.json` (campo `extensions.http.routePrefix`).

## Slide 5 — Métodos HTTP: GET, POST, PUT, DELETE

```csharp
public class ProductosApi
{
    private readonly IProductoService _service;
    
    public ProductosApi(IProductoService service) => _service = service;

    [Function("ListarProductos")]
    public async Task<IActionResult> Listar(
        [HttpTrigger(AuthorizationLevel.Function, "get", Route = "productos")] 
        HttpRequest req)
    {
        var productos = await _service.ListarAsync();
        return new OkObjectResult(productos);
    }

    [Function("CrearProducto")]
    public async Task<IActionResult> Crear(
        [HttpTrigger(AuthorizationLevel.Function, "post", Route = "productos")] 
        HttpRequest req)
    {
        var body = await req.ReadFromJsonAsync<CrearProductoDto>();
        if (body is null) return new BadRequestResult();
        
        var producto = await _service.CrearAsync(body);
        return new CreatedResult($"/api/productos/{producto.Id}", producto);
    }

    [Function("ActualizarProducto")]
    public async Task<IActionResult> Actualizar(
        [HttpTrigger(AuthorizationLevel.Function, "put", Route = "productos/{id}")] 
        HttpRequest req, string id)
    {
        var body = await req.ReadFromJsonAsync<ActualizarProductoDto>();
        var resultado = await _service.ActualizarAsync(id, body);
        return resultado is null ? new NotFoundResult() : new OkObjectResult(resultado);
    }

    [Function("EliminarProducto")]
    public async Task<IActionResult> Eliminar(
        [HttpTrigger(AuthorizationLevel.Function, "delete", Route = "productos/{id}")] 
        HttpRequest req, string id)
    {
        var eliminado = await _service.EliminarAsync(id);
        return eliminado ? new NoContentResult() : new NotFoundResult();
    }
}
```

## Slide 6 — Routing: URLs personalizadas

Por defecto, la URL es `/api/{NombreFuncion}`. Podéis personalizarla con `Route`:

```csharp
// URL: /api/productos
[HttpTrigger(AuthorizationLevel.Function, "get", Route = "productos")]

// URL: /api/productos/123
[HttpTrigger(AuthorizationLevel.Function, "get", Route = "productos/{id}")]

// URL: /api/clientes/456/pedidos
[HttpTrigger(AuthorizationLevel.Function, "get", Route = "clientes/{clienteId}/pedidos")]

// URL: /api/productos/123 (id es opcional)
[HttpTrigger(AuthorizationLevel.Function, "get", Route = "productos/{id?}")]

// URL: /api/search?q=algo (sin parámetro de ruta)
[HttpTrigger(AuthorizationLevel.Function, "get", Route = "search")]
```

**Parámetros de ruta se inyectan como argumentos de la función:**
```csharp
public IActionResult Run(
    [HttpTrigger(..., Route = "clientes/{clienteId}/pedidos/{pedidoId}")] 
    HttpRequest req,
    string clienteId,    // ← viene de {clienteId}
    string pedidoId)     // ← viene de {pedidoId}
```

**Quitar el prefijo `/api`:**
```json
// host.json
{
  "extensions": {
    "http": {
      "routePrefix": ""  // URLs sin /api/ — directamente /productos
    }
  }
}
```

## Slide 8 — Request body: leer JSON

```csharp
// DTO para el body
public record CrearPedidoDto(
```

## Slide 10 — Niveles de autorización

HTTP triggers tienen niveles de authorization predefinidos. Entender cuándo usar cada uno:

```csharp
// Anonymous: público, sin auth
[HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "public/ping")]

// Function: requiere API key de la función específica
[HttpTrigger(AuthorizationLevel.Function, "get", Route = "productos/{id}")]
// URL: /api/productos/X?code=<function-key>

// Admin: requiere master key (acceso a TODAS las funciones)
[HttpTrigger(AuthorizationLevel.Admin, "post", Route = "admin/reset")]

// User: se combina con Easy Auth (App Service Authentication)
[HttpTrigger(AuthorizationLevel.User, "get", Route = "user/profile")]
```

**Dónde están las keys:**
```bash
# Ver keys de una función específica
az functionapp function keys list \
  --name func-ventas -g rg-ventas-prod \
  --function-name GetProducto

# Master key de la Function App
az functionapp keys list \
  --name func-ventas -g rg-ventas-prod

# Rotar una key
az functionapp function keys set \
  --name func-ventas -g rg-ventas-prod \
  --function-name GetProducto \
  --key-name default --key-value "nueva-key"
```

**En 2026 — regla de seguridad:**

| Nivel | Cuándo usar | Alternativa moderna |
|---|---|---|
| Anonymous | Endpoints públicos (health, metadata) | Correcto |
| Function | Internal APIs, webhooks | **Mejor: Entra ID + JWT** |
| Admin | Operaciones de mantenimiento | **Mejor: Entra ID + Role "Admin"** |
| User | Apps con Easy Auth | OK, pero mejor JWT custom |

**Recomendación moderna:** usad `Anonymous` en el nivel de Function pero implementad JWT validation vosotros. Más control y estándar.

## Slide 11 — Autenticación con Entra ID (preview)

Para proteger HTTP triggers con autenticación real:

**Opción 1 — Easy Auth (configuración, sin código):**
```bash

  --enabled true \
  --action LoginWithAzureActiveDirectory \
  --aad-client-id <app-registration-client-id>
```

**Opción 2 — En código (más control):**
```csharp
[Function("GetPerfil")]
public IActionResult GetPerfil(
    [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "perfil")] 
    HttpRequest req)
{
    // La identidad viene del middleware de autenticación
    var identity = req.HttpContext.User.Identity;
    
    if (!identity?.IsAuthenticated ?? true)
        return new UnauthorizedResult();
    
    var email = req.HttpContext.User.FindFirst("preferred_username")?.Value;
    var nombre = req.HttpContext.User.FindFirst("name")?.Value;
    
    return new OkObjectResult(new { email, nombre, autenticado = true });
}
```

## Slide 13 — Dependency Injection en HTTP triggers

```csharp
// Program.cs — registrar servicios
var host = new HostBuilder()
    .ConfigureFunctionsWebApplication()
    .ConfigureServices(services =>
    {
        services.AddSingleton<ICosmosService, CosmosService>();
        services.AddScoped<IValidadorService, ValidadorService>();
        services.AddHttpClient("ApiExterna", c => {
            c.BaseAddress = new Uri(Environment.GetEnvironmentVariable("API_EXTERNA_URL")!);
            c.Timeout = TimeSpan.FromSeconds(30);
        });
    })
    .Build();

// Function — inyectar por constructor
public class PedidosApi
{
    private readonly ICosmosService _cosmos;
    private readonly IHttpClientFactory _httpFactory;
    private readonly ILogger<PedidosApi> _logger;

    public PedidosApi(
        ICosmosService cosmos, 
        IHttpClientFactory httpFactory,
        ILogger<PedidosApi> logger)
    {
        _cosmos = cosmos;
        _httpFactory = httpFactory;
        _logger = logger;
    }

    [Function("GetPedido")]
    public async Task<IActionResult> Get(
        [HttpTrigger(AuthorizationLevel.Function, "get", Route = "pedidos/{id}")] 
        HttpRequest req, string id)
    {
        _logger.LogInformation("Buscando pedido {PedidoId}", id);
```

## Slide 14 — Middleware (Isolated Worker)

Podéis añadir middleware como en ASP.NET Core:

```csharp
var host = new HostBuilder()
    .ConfigureFunctionsWebApplication(worker =>
    {
        // Middleware de logging
        worker.UseMiddleware<CorrelationIdMiddleware>();
        
        // Middleware de manejo de errores
        worker.UseMiddleware<ExceptionHandlingMiddleware>();
    })
    .Build();
```

```csharp
public class ExceptionHandlingMiddleware : IFunctionsWorkerMiddleware
{
    private readonly ILogger<ExceptionHandlingMiddleware> _logger;

    public ExceptionHandlingMiddleware(ILogger<ExceptionHandlingMiddleware> logger)
        => _logger = logger;

    public async Task Invoke(FunctionContext context, FunctionExecutionDelegate next)
    {
        try
        {
            await next(context);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Error no controlado en {Function}", context.FunctionDefinition.Name);
            
            var req = await context.GetHttpRequestDataAsync();
            if (req is not null)
            {
                var response = req.CreateResponse(System.Net.HttpStatusCode.InternalServerError);
                await response.WriteAsJsonAsync(new { error = "Error interno", traceId = context.InvocationId });
                context.GetInvocationResult().Value = response;
            }
        }
    }
}
```

## Slide 15 — Validación de request

```csharp
// Con DataAnnotations
public record CrearProductoDto
{
    [Required(ErrorMessage = "Nombre es obligatorio")]
    [StringLength(100, MinimumLength = 3)]
    public string Nombre { get; init; } = "";
    
    [Range(0.01, 999999.99, ErrorMessage = "Precio debe ser entre 0.01 y 999999.99")]
    public decimal Precio { get; init; }
    
    [Required]
    public string Categoria { get; init; } = "";
}

[Function("CrearProducto")]
public async Task<IActionResult> Crear(
    [HttpTrigger(AuthorizationLevel.Function, "post", Route = "productos")] 
    HttpRequest req)
{
    var dto = await req.ReadFromJsonAsync<CrearProductoDto>();
    if (dto is null) 
        return new BadRequestObjectResult(new { error = "Body JSON requerido" });

    // Validar con DataAnnotations
    var validationResults = new List<ValidationResult>();
    if (!Validator.TryValidateObject(dto, new ValidationContext(dto), validationResults, true))
    {
        var errores = validationResults.Select(v => v.ErrorMessage);
        return new BadRequestObjectResult(new { errores });
    }

    // Procesar...
    return new CreatedResult($"/api/productos/{Guid.NewGuid()}", dto);
}
```

## Slide 19 — HTTP Trigger + Cosmos DB (ejemplo completo)

Combinando HTTP trigger con Cosmos DB input/output bindings:

```csharp
public class ProductosApi
{
    [Function("GetProducto")]
    public IActionResult Get(
        [HttpTrigger(AuthorizationLevel.Function, "get", Route = "productos/{id}")] 
        HttpRequest req,
        [CosmosDBInput("tienda", "productos",
            Connection = "CosmosDbConnection",
            Id = "{id}",
            PartitionKey = "{id}")] Producto? producto,
        string id)
    {
        // producto ya viene cargado por el binding — sin escribir código de conexión
        return producto is null 
            ? new NotFoundObjectResult(new { error = $"Producto {id} no encontrado" })
            : new OkObjectResult(producto);
    }

    [Function("CrearProducto")]
    [CosmosDBOutput("tienda", "productos", Connection = "CosmosDbConnection")]
    public object Crear(
        [HttpTrigger(AuthorizationLevel.Function, "post", Route = "productos")] 
        HttpRequest req)
    {
        var producto = req.ReadFromJsonAsync<Producto>().Result;
        producto!.Id = Guid.NewGuid().ToString();
        producto.CreadoEn = DateTime.UtcNow;
        
        // El return va directamente a Cosmos DB (output binding)
        return producto;
    }
}
```

**Cero código de conexión a Cosmos DB.** Los bindings hacen todo: leer por ID, escribir documentos. Solo necesitáis la connection string en App Settings.

## Slide 21 — Rate limiting en HTTP triggers

Functions no tiene rate limiting nativo, pero podéis implementarlo:

```csharp
// Middleware custom para rate limiting
public class RateLimitMiddleware : IFunctionsWorkerMiddleware
{
    private readonly IMemoryCache _cache;
    private const int MAX_REQUESTS_PER_MINUTE = 100;

    public RateLimitMiddleware(IMemoryCache cache) => _cache = cache;

    public async Task Invoke(FunctionContext ctx, FunctionExecutionDelegate next)
    {
        var httpReq = await ctx.GetHttpRequestDataAsync();
        if (httpReq == null) { await next(ctx); return; }

        // Clave: IP + minuto actual
        var clientIp = httpReq.Headers.GetValues("X-Forwarded-For").FirstOrDefault() 
                    ?? "unknown";
        var cacheKey = $"rate:{clientIp}:{DateTime.UtcNow:yyyyMMddHHmm}";

        var count = _cache.GetOrCreate(cacheKey, e => {
            e.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(2);
            return 0;
        }) + 1;

        _cache.Set(cacheKey, count, TimeSpan.FromMinutes(2));

        if (count > MAX_REQUESTS_PER_MINUTE)
        {
            var resp = httpReq.CreateResponse(HttpStatusCode.TooManyRequests);
            await resp.WriteStringAsync($"Rate limit exceeded. Try again later.");
            resp.Headers.Add("Retry-After", "60");
            ctx.GetInvocationResult().Value = resp;
            return;
        }

        await next(ctx);
    }
}

// Program.cs
builder.Services.AddMemoryCache();
builder.UseWhen<RateLimitMiddleware>(
    ctx => ctx.FunctionDefinition.InputBindings.Values.Any(b => b.Type == "httpTrigger"));
```

**Mejor aún:** usar **API Management** delante de Functions. APIM tiene rate limiting built-in, más configurable. Lo veréis en M7.

## Slide 22 — API versioning patterns

Versionar APIs es crítico. Tres patrones comunes:

```csharp
// 1. Por URL (más visible, recomendado para APIs públicas)
[Function("GetProductoV1")]
public HttpResponseData GetProductoV1(
    [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "v1/productos/{id}")] 
    HttpRequestData req, string id) { /* versión 1 */ }

[Function("GetProductoV2")]
public HttpResponseData GetProductoV2(
    [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "v2/productos/{id}")] 
    HttpRequestData req, string id) { /* versión 2 con más campos */ }

// 2. Por header (más limpia, invisible a usuarios casuales)
[Function("GetProducto")]
public HttpResponseData GetProducto(
    [HttpTrigger(...)] HttpRequestData req, string id)
{
    var apiVersion = req.Headers.GetValues("X-API-Version").FirstOrDefault() ?? "1";
    return apiVersion switch {
        "1" => GetV1(id),
        "2" => GetV2(id),
        _ => req.CreateResponse(HttpStatusCode.BadRequest)
    };
}

// 3. Por query string (para testing rápido)
// GET /api/productos/X?api-version=2
```

**Estrategia recomendada:**

```
APIs internas del equipo:
└── Por header X-API-Version (más limpio)

APIs externas / terceros:
└── Por URL /v1/, /v2/ (más explícito, fácil de ver)

Deprecación:
├── v1: existe, añadimos header "X-API-Deprecated: true"
├── v2: actual
└── v1: se mantiene 6-12 meses tras v2, luego se retira

Comunicación:
├── Changelog público de API
├── Email a consumers conocidos
└── Métricas: uso por versión para decidir retiros
```

En vez de devolver errores en formatos inconsistentes, usad el estándar RFC 7807:

```csharp
public static class ProblemDetailsExtensions
{
    public static async Task<HttpResponseData> NotFoundProblem(
        this HttpRequestData req, string detail, string? instance = null)
    {
        var resp = req.CreateResponse(HttpStatusCode.NotFound);
        resp.Headers.Add("Content-Type", "application/problem+json");
        await resp.WriteAsJsonAsync(new
        {
            type = "https://api.ventas.com/errors/not-found",
            title = "Resource Not Found",
            status = 404,
            detail,
            instance = instance ?? req.Url.PathAndQuery,
            traceId = Activity.Current?.Id
        });
        return resp;
    }

    public static async Task<HttpResponseData> ValidationProblem(
        this HttpRequestData req, Dictionary<string, string[]> errors)
    {
        var resp = req.CreateResponse(HttpStatusCode.UnprocessableEntity);
        resp.Headers.Add("Content-Type", "application/problem+json");
        await resp.WriteAsJsonAsync(new
        {
            type = "https://api.ventas.com/errors/validation",
            title = "One or more validation errors occurred",
            status = 422,
            detail = "See 'errors' for details",
            instance = req.Url.PathAndQuery,
            errors
        });
        return resp;
    }
}

// Uso
if (producto == null)
    return await req.NotFoundProblem($"Producto '{id}' no encontrado");
```

## Slide 27 — Health endpoints específicos de Functions

Health checks bien hechos son críticos para monitorización:

```csharp
public class HealthFunctions
{
    private readonly CosmosClient _cosmos;
    private readonly ServiceBusClient _sb;
    private readonly ILogger<HealthFunctions> _logger;

    public HealthFunctions(CosmosClient cosmos, ServiceBusClient sb, ILogger<HealthFunctions> logger)
    {
        _cosmos = cosmos;
        _sb = sb;
        _logger = logger;
    }

    // Health liveness: solo la app responde
    [Function(nameof(HealthLive))]
    public HttpResponseData HealthLive(
        [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "health/live")] 
        HttpRequestData req)
    {
        var resp = req.CreateResponse(HttpStatusCode.OK);
        resp.WriteString($"{{\"status\":\"healthy\",\"timestamp\":\"{DateTime.UtcNow:O}\"}}");
        return resp;
    }

    // Health readiness: verifica dependencias
    [Function(nameof(HealthReady))]
    public async Task<HttpResponseData> HealthReady(
        [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "health/ready")] 
        HttpRequestData req)
    {
        var checks = new Dictionary<string, object>();
        var allHealthy = true;

        // Check Cosmos DB
        try
        {
            await _cosmos.ReadAccountAsync();
            checks["cosmos"] = new { status = "healthy" };
        }
        catch (Exception ex)
        {
            checks["cosmos"] = new { status = "unhealthy", error = ex.Message };
            allHealthy = false;
        }

        // Check Service Bus
        try
        {
            await using var sender = _sb.CreateSender("health-check");
            checks["servicebus"] = new { status = "healthy" };
        }
        catch (Exception ex)
        {
            checks["servicebus"] = new { status = "unhealthy", error = ex.Message };
            allHealthy = false;
        }

        var status = allHealthy ? HttpStatusCode.OK : HttpStatusCode.ServiceUnavailable;
        var resp = req.CreateResponse(status);
        await resp.WriteAsJsonAsync(new 
        {
            status = allHealthy ? "healthy" : "unhealthy",
            timestamp = DateTime.UtcNow,
            checks
        });
        return resp;
    }
}
```

**Patterns:**
- `/health/live` → ¿la app está viva? (mínimo posible)
- `/health/ready` → ¿lista para recibir tráfico? (incluye dependencias)
- `/health/startup` → ¿terminó de arrancar? (Kubernetes-like)

**Usado por:**
- Azure App Service Health Check
- API Management health probes
- Azure Front Door origin health
- Load balancers externos

## Slide 29 — Content negotiation y response compression

Optimizar responses para diferentes clientes:

```csharp
public class ProductosFunctions
{
    [Function(nameof(GetProductos))]
    public async Task<HttpResponseData> GetProductos(
        [HttpTrigger(...)] HttpRequestData req)
    {
        var productos = await GetProductosData();

        var accept = req.Headers.GetValues("Accept").FirstOrDefault() ?? "application/json";
        var acceptEncoding = req.Headers.GetValues("Accept-Encoding").FirstOrDefault() ?? "";

        var response = req.CreateResponse(HttpStatusCode.OK);

        // Content negotiation
        if (accept.Contains("application/xml"))
        {
            response.Headers.Add("Content-Type", "application/xml");
            var xml = SerializeToXml(productos);
            await response.WriteStringAsync(xml);
        }
        else if (accept.Contains("text/csv"))
        {
            response.Headers.Add("Content-Type", "text/csv");
            var csv = SerializeToCsv(productos);
            await response.WriteStringAsync(csv);
        }
        else
        {
            // Default: JSON
            response.Headers.Add("Content-Type", "application/json");
            await response.WriteAsJsonAsync(productos);
        }

        // Compression si el cliente lo soporta
        if (acceptEncoding.Contains("gzip"))
        {
            // GzipStream wrapping (solo para responses grandes)
            response.Headers.Add("Content-Encoding", "gzip");
        }

        return response;
    }
}
```

**Mejor aún — dejar que APIM o Azure Front Door hagan compression:**
- Lo hacen en el edge (más cerca del cliente)
- La Function no consume CPU en compresión
- Configuración global, no por endpoint

**Tip:** solo comprimir responses > 1KB (overhead no compensa en pequeñas).

## Slide 31 — Caching responses con output caching

Para endpoints GET que no cambian con frecuencia, cachear responses reduce latencia y coste:

```csharp
public class ProductosFunctions
{
    private readonly IMemoryCache _cache;
    private readonly IProductoService _svc;

    public ProductosFunctions(IMemoryCache cache, IProductoService svc)
    {
        _cache = cache;
        _svc = svc;
    }

    [Function(nameof(GetCategorias))]
    public async Task<HttpResponseData> GetCategorias(
        [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "categorias")]
        HttpRequestData req)
    {
        // Cache en memoria por 5 minutos
        var categorias = await _cache.GetOrCreateAsync("categorias", async entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
            entry.SetPriority(CacheItemPriority.High);
            return await _svc.GetAllCategoriasAsync();
        });

        var response = req.CreateResponse(HttpStatusCode.OK);
        
        // Añadir headers de cache para clientes + CDN
        response.Headers.Add("Cache-Control", "public, max-age=300");
        response.Headers.Add("ETag", $"\"{ComputeETag(categorias)}\"");
        
        // Si cliente manda If-None-Match con el mismo ETag, 304
        var clientEtag = req.Headers.GetValues("If-None-Match").FirstOrDefault();
        if (clientEtag == $"\"{ComputeETag(categorias)}\"")
        {
            return req.CreateResponse(HttpStatusCode.NotModified);
        }

        await response.WriteAsJsonAsync(categorias);
        return response;
    }

    private string ComputeETag(object data) => 
        Convert.ToBase64String(SHA256.HashData(
            JsonSerializer.SerializeToUtf8Bytes(data)));
}
```

**Niveles de caching:**

```
Cliente (browser/app) ← Cache-Control 
         ↓
CDN (Azure Front Door/CDN) ← max-age, s-maxage
         ↓
API Management ← response caching policy
         ↓
Function App ← IMemoryCache (local)
         ↓
Cosmos DB/SQL ← datos de verdad
```

Cuanto más arriba en la cadena caché, menor latencia y coste. Para datos muy estáticos (categorías, enums), cachear en CDN durante 1h+.

## Slide 32 — Errores comunes con HTTP triggers

**"404 Not Found" en Azure pero funciona en local:**
→ Verificad que la función aparece en `func azure functionapp list-functions`. Si no, el despliegue falló silenciosamente.

**"500 Internal Server Error" sin detalle:**
→ Habilitad Application Insights. Sin él, los errores internos son una caja negra.

**"CORS error" desde el frontend:**
→ Configurad CORS: `az functionapp cors add --allowed-origins "https://mi-frontend.com"`

**El function key no funciona:**
→ El key va como query param (`?code=xxx`) o como header (`x-functions-key: xxx`). Verificad que usáis el key correcto (function key, no host key).

**La función tarda mucho en responder la primera vez:**
→ Cold start. Normal en plan de consumo. Soluciones: Premium plan, ReadyToRun, menos dependencias.
