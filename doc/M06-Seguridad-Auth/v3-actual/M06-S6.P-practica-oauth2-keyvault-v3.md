# Submódulo 6.P — Práctica: OAuth2 con Entra ID + Key Vault

## Slide 1 — Portada
**Módulo 6 · Práctica**
OAuth2 con Entra ID + Key Vault
Proteger una API con autenticación real y almacenar secretos de forma segura

---

## Slide 2 — Qué vais a construir
Una API protegida con Entra ID (solo usuarios autenticados pueden acceder) + secretos almacenados en Key Vault:

1. Registrar la app en Entra ID (App Registration)
2. Crear Key Vault y almacenar un secreto (API key ficticia)
3. Configurar Key Vault Reference en App Settings
4. Proteger la API con autenticación Entra ID (Easy Auth)
5. Verificar que sin token no podéis acceder
6. Obtener un token y acceder a la API

**Tiempo estimado:** 25-30 minutos

---

## Slide 3 — Pre-flight: requisitos antes de empezar

OAuth2 + Key Vault tiene varios servicios involucrados. Validad permisos antes de empezar para no quedar a mitad de práctica sin acceso.

**Permisos necesarios en Microsoft Entra:**

```bash

az ad signed-in-user show --query "{User:userPrincipalName,Id:id}" -o table

# Listar vuestros roles de directorio

  --uri "https://graph.microsoft.com/v1.0/me/memberOf?\$select=displayName,roleTemplateId"

# Esperado mínimo: "Application Developer" (puede crear App Registrations)
# Si tenéis "Global Administrator": podéis hacer todo
# Si NO tenéis ninguno: pedidlos al admin de Entra antes de continuar
```

**Permisos necesarios en Azure subscription:**

```bash

# (para asignar roles RBAC a vuestra propia identidad y a la Web App)
az role assignment list \
  --assignee $(az ad signed-in-user show --query id -o tsv) \
  --scope /subscriptions/$(az account show --query id -o tsv) \
  --query "[].roleDefinitionName" -o tsv
```

**Validar que tenéis todo:**

```bash
# 1. Tenant ID y subscription correcta
az account show --query "{Tenant:tenantId, Sub:name, User:user.name}" -o table

# 2. Web App del módulo 1 disponible
az webapp show --name app-curso-<tu-nombre> -g rg-curso-azure-<tu-nombre>

# 3. Cliente para obtener tokens (curl + jq, o Postman, o az CLI)

**Coste aproximado:**

```

App Registration: GRATIS
Easy Auth en App Service: GRATIS (incluido)
TOTAL: <€0.10 esta práctica

**Tiempo realista:** 60-75 minutos (los 25-30 declarados son solo si tenéis todo configurado y dominais OAuth, lo cual no debería asumirse).

**Conceptos clave que conviene tener frescos:**
- App Registration ≠ Service Principal (uno por tenant, otro por sub)
- Client Credentials flow ≠ Authorization Code flow
- Access token vs ID token vs Refresh token
- Scopes vs Roles vs App Roles

## Slide 4 — Paso 1: Crear App Registration

```bash
# Crear registro de app
az ad app create \
  --display-name "API Curso AZ204 <tu-nombre>" \
  --sign-in-audience AzureADMyOrg

APP_ID=$(az ad app list --display-name "API Curso AZ204 <tu-nombre>" --query "[0].appId" -o tsv)
echo "Client ID: $APP_ID"

# Crear service principal
az ad sp create --id $APP_ID

# Crear client secret (guardaremos en Key Vault)
SECRET=$(az ad app credential reset --id $APP_ID --append --display-name "curso-secret" --years 1 --query password -o tsv)
echo "Client Secret: $SECRET (copiar para Key Vault)"
```

---

## Slide 5 — Paso 2: Crear Key Vault y almacenar secretos

```bash
# Crear Key Vault
az keyvault create \
  --name kv-curso-<tu-nombre> \
  --resource-group rg-curso-azure-<tu-nombre> \
  --location westeurope \
  --enable-rbac-authorization true

# Asignaros permisos
MY_ID=$(az ad signed-in-user show --query id -o tsv)
KV_ID=$(az keyvault show --name kv-curso-<tu-nombre> -g rg-curso-azure-<tu-nombre> --query id -o tsv)
az role assignment create --assignee $MY_ID --role "Key Vault Secrets Officer" --scope $KV_ID

# Almacenar el client secret
az keyvault secret set --vault-name kv-curso-<tu-nombre> \
  --name "AzureAd-ClientSecret" --value "$SECRET"

# Almacenar un API key ficticio
az keyvault secret set --vault-name kv-curso-<tu-nombre> \
  --name "ExternalApiKey" --value "sk_test_fictional_key_12345"

# Verificar
az keyvault secret list --vault-name kv-curso-<tu-nombre> --query "[].name" -o tsv
```

## Slide 7 — Paso 4: Configurar Key Vault References

```bash
TENANT_ID=$(az account show --query tenantId -o tsv)

az webapp config appsettings set \
  --name app-curso-<tu-nombre> -g rg-curso-azure-<tu-nombre> \
  --settings \
    AzureAd__TenantId="$TENANT_ID" \
    AzureAd__ClientId="$APP_ID" \
    AzureAd__ClientSecret="@Microsoft.KeyVault(VaultName=kv-curso-<tu-nombre>;SecretName=AzureAd-ClientSecret)" \
    ExternalApiKey="@Microsoft.KeyVault(VaultName=kv-curso-<tu-nombre>;SecretName=ExternalApiKey)"
```

**Verificar en el portal:** App Service → Configuration → cada variable debe mostrar ✓ "Key Vault Reference" en verde.

## Slide 8 — Paso 5: Habilitar Easy Auth

```bash
az webapp auth microsoft update \
  --name app-curso-<tu-nombre> -g rg-curso-azure-<tu-nombre> \
  --client-id $APP_ID \
  --client-secret-setting-name AzureAd__ClientSecret \
  --issuer "https://login.microsoftonline.com/$TENANT_ID/v2.0" \
  --yes

az webapp auth update \
  --name app-curso-<tu-nombre> -g rg-curso-azure-<tu-nombre> \
  --enabled true \
  --action Return401
```

`--action Return401`: devuelve 401 si no hay token (para APIs). Para web apps que quieran redirigir al login, usad `LoginWithAzureActiveDirectory`.

## Slide 9 — Paso 6: Crear la API protegida

Actualizad `Program.cs`:

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// Endpoint público (health check)
app.MapGet("/health", () => Results.Ok(new { status = "healthy" }));

// Endpoint protegido (solo con token válido — Easy Auth lo verifica)
app.MapGet("/api/perfil", (HttpContext ctx) =>
{
    var headers = ctx.Request.Headers;
    var nombre = headers["X-MS-CLIENT-PRINCIPAL-NAME"].ToString();
    var idp = headers["X-MS-CLIENT-PRINCIPAL-IDP"].ToString();
    
    var apiKey = builder.Configuration["ExternalApiKey"] ?? "no-configurada";
    
    return Results.Json(new
    {
        autenticado = true,
        nombre,
        identityProvider = idp,
        tieneApiKeyExterna = !string.IsNullOrEmpty(apiKey) && apiKey != "no-configurada",
        mensaje = "Estás autenticado con Entra ID y los secretos vienen de Key Vault"
    });
});

app.MapGet("/api/datos", (HttpContext ctx) =>
{
    var nombre = ctx.Request.Headers["X-MS-CLIENT-PRINCIPAL-NAME"].ToString();
    return Results.Json(new
    {
        usuario = nombre,
        datos = new[] { "Pedido 001", "Pedido 002", "Pedido 003" },
        fuente = "API protegida con OAuth2"
    });
});

app.Run();
```

## Slide 12 — Decodificar y debuggear tokens JWT

Cuando algo no funciona en OAuth, el primer paso es **mirar el token**. JWT es decodable sin secret (la firma se verifica con clave pública).

**Obtener un token desde tu app:**

```bash
# Client credentials flow (server-to-server)
TENANT_ID=$(az account show --query tenantId -o tsv)
APP_ID="<tu-app-id>"
SECRET="<tu-secret>"

TOKEN=$(curl -s -X POST \
  "https://login.microsoftonline.com/$TENANT_ID/oauth2/v2.0/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "client_id=$APP_ID" \
  -d "client_secret=$SECRET" \
  -d "scope=api://$APP_ID/.default" \
  | jq -r .access_token)

echo "Token: $TOKEN"
```

**Decodificar el token** (sin verificar firma):

```bash
# Mac/Linux: usar jq
echo $TOKEN | cut -d. -f2 | base64 -d 2>/dev/null | jq

# Output esperado:
{
  "aud": "api://abc-123",                    ← Audience (tu API)
  "iss": "https://sts.windows.net/{tenant}/",  ← Issuer
  "iat": 1714206000,                          ← Issued at (timestamp)
  "exp": 1714209600,                          ← Expira en (1 hora)
  "appid": "abc-123",                         ← Client ID que solicitó token
  "tid": "tenant-id",                         ← Tenant ID
  "roles": ["Pedidos.Read", "Pedidos.Write"], ← App roles asignados
  "scp": "Pedidos.Read"                       ← Scopes (solo en delegated)
}
```

**Verificar token en jwt.ms** (alternativa visual):

```
1. Copiar el token completo
2. Ir a https://jwt.ms (oficial Microsoft, no manda nada al servidor)
3. Pegar token → ver claims decodificados + validation status
```

**Errores comunes de tokens y cómo identificarlos:**

```
❌ "AADSTS50011: Reply URL mismatch"
   → El redirect_uri que mandaste no está en la App Registration
   → Solución: añadir el redirect_uri en Portal → App Registration → Authentication

❌ "AADSTS70011: Invalid scope"
   → El scope solicitado no existe o está mal escrito
   → Para client credentials, debe ser: api://<app-id>/.default
   → Para delegated, debe ser: api://<app-id>/<scope-name>

❌ "AADSTS65001: User has not consented"
   → El admin no dio consent a los permisos solicitados
   → Solución: Portal → API permissions → "Grant admin consent"

❌ "AADSTS700016: Application not found in directory"
   → Estás llamando con un client_id que no existe en este tenant
   → Verificar: az ad app show --id $APP_ID

❌ Token decodifica OK pero la API devuelve 401
   → Posibles causas:
     a) "aud" no coincide con la API protegida
     b) Token expirado (verificar "exp" claim)
     c) Easy Auth configurada con tenant distinto
```

**Verificar firma del token (avanzado, no necesario en práctica):**

```bash
# La firma se verifica con la public key del tenant
# Endpoint: https://login.microsoftonline.com/{tenant}/discovery/v2.0/keys
# La librería Microsoft.Identity.Web hace esto automáticamente
```

## Slide 13 — Scopes vs Roles vs App Roles: cuál usar y cuándo

Esta es la confusión más común al diseñar APIs con Entra. Aclaramos la diferencia:

```
┌─────────────────────────────────────────────────────────────┐
│  SCOPES (Delegated permissions)                             │
│  ──────────────────────────────                             │
│  Para apps que actúan EN NOMBRE DE un usuario               │
│  Claim en token: "scp"                                      │
│  Ejemplo: "Pedidos.Read", "Pedidos.Write"                   │
│  Caso típico: SPA o mobile que llama a tu API tras login    │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  APP ROLES (Application permissions)                        │
│  ────────────────────────────────                           │
│  Para apps que actúan POR SÍ MISMAS (sin usuario)           │
│  Claim en token: "roles"                                    │
│  Ejemplo: "Pedidos.ReadAll", "Pedidos.Admin"                │
│  Caso típico: backend job que procesa pedidos en batch      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ROLES (Directory roles)                                    │
│  ───────────────────                                        │
│  Roles del propio Entra ID (no de tu API)                   │
│  Ejemplo: "Global Administrator", "User Administrator"      │
│  Caso típico: tu app necesita saber si user es admin Entra  │
└─────────────────────────────────────────────────────────────┘
```

**Definir scopes en App Registration:**

```bash
# Mediante CLI: editar manifest JSON
APP_ID="<tu-app-id>"

az ad app show --id $APP_ID --query "api.oauth2PermissionScopes" > scopes-current.json

# Editar scopes-current.json para añadir:
[
  {
    "id": "12345678-1234-1234-1234-123456789012",
    "adminConsentDescription": "Permite leer pedidos del usuario",
    "adminConsentDisplayName": "Read Pedidos",
    "userConsentDescription": "Permite leer tus pedidos",
    "userConsentDisplayName": "Read your pedidos",
    "value": "Pedidos.Read",
    "type": "User",
    "isEnabled": true
  }
]

az ad app update --id $APP_ID --set api.oauth2PermissionScopes=@scopes-current.json
```

**Definir App Roles:**

```bash
az ad app show --id $APP_ID --query "appRoles" > roles-current.json

# Añadir:
[
  {
    "id": "23456789-2345-2345-2345-234567890123",
    "displayName": "Pedidos Admin",
    "description": "Acceso administrativo a todos los pedidos",
    "value": "Pedidos.Admin",
    "isEnabled": true,
    "allowedMemberTypes": ["Application"]  ← Solo apps, no usuarios
  }
]

az ad app update --id $APP_ID --set appRoles=@roles-current.json
```

**Validar en tu API .NET:**

```csharp
// Authorize por scope (usuario)
[Authorize(Policy = "RequirePedidosRead")]
public async Task<IActionResult> GetPedidos() { }

// Configurar la policy
services.AddAuthorization(options =>
{
    options.AddPolicy("RequirePedidosRead", policy =>
        policy.RequireAssertion(context =>
            context.User.HasClaim("scp", "Pedidos.Read") ||
            context.User.IsInRole("Pedidos.Admin")  // app role como override
        ));
});

// Authorize por app role (servicio)
[Authorize(Roles = "Pedidos.Admin")]
public async Task<IActionResult> DeleteAllPedidos() { }
```

**Regla práctica:**
```
¿Tu API la llama un humano (browser/mobile)?
  → Usa Scopes
  
¿Tu API la llama un servicio (cron, batch, webhook)?
  → Usa App Roles
  
¿Ambos?
  → Define ambos y autoriza por cualquiera de los dos
```

## Slide 14 — Rotación automática de secretos en Key Vault

Hardcoded → App Settings → Key Vault Reference es progreso. Pero el siguiente nivel es **rotar los secretos sin downtime**.

**1. Configurar event handler para rotación:**

```bash
# Crear Event Grid topic para Key Vault
KV_NAME="kv-curso-<tu-nombre>"
KV_ID=$(az keyvault show --name $KV_NAME --query id -o tsv)

az eventgrid event-subscription create \
  --name kv-rotation-events \
  --source-resource-id $KV_ID \
  --included-event-types "Microsoft.KeyVault.SecretNewVersionCreated" \
  --endpoint <function-app-webhook-url> \
  --endpoint-type webhook
```

**2. Function que reacciona al evento:**

```csharp
[Function("HandleSecretRotation")]
public async Task HandleSecretRotation(
    [EventGridTrigger] EventGridEvent eventGridEvent,
    FunctionContext context)
{
    if (eventGridEvent.EventType != "Microsoft.KeyVault.SecretNewVersionCreated")
        return;
    
    var data = eventGridEvent.Data.ToObjectFromJson<SecretEventData>();
    _logger.LogInformation("Secret {Name} rotated to version {Version}",
        data.ObjectName, data.Version);
    
    // Si la app cachea secretos, invalidar cache
    await _secretCache.InvalidateAsync(data.ObjectName);
    
    // Notificar a equipos relevantes
    await _notifications.SendAsync(new
    {
        Subject = "Secret Rotation Completed",
        Body = $"Secret {data.ObjectName} ({data.Version}) is now active"
    });
}
```

**3. Configurar rotación automática del secreto:**

```bash
# Para certificates, hay rotación automática nativa
az keyvault certificate set-attributes \
  --vault-name $KV_NAME \
  --name api-cert \
  --enabled true \
  --recovery-level Recoverable

# Para secrets, necesitáis un script/Function que rote
# Ejemplo: rotate-secret.sh ejecutado vía Logic App schedule
cat > rotate-secret.sh << 'EOF'
#!/bin/bash
SECRET_NAME="api-key"
NEW_VALUE=$(openssl rand -base64 32)  # Generar nuevo

# Crear nueva version
az keyvault secret set \
  --vault-name $KV_NAME \
  --name $SECRET_NAME \
  --value $NEW_VALUE

# Eventgrid disparará automáticamente
echo "Rotación completada para $SECRET_NAME"
EOF
```

**4. App debe leer la versión más reciente automáticamente:**

```csharp
// ✅ BIEN: Key Vault Reference sin versión = siempre la última
"@Microsoft.KeyVault(VaultName=kv-curso;SecretName=api-key)"

// ❌ MAL: Key Vault Reference con versión específica = no rota
"@Microsoft.KeyVault(VaultName=kv-curso;SecretName=api-key;SecretVersion=abc123)"

// En código C#:
var client = new SecretClient(new Uri($"https://{KV_NAME}.vault.azure.net/"), 
    new DefaultAzureCredential());

// Leer SIEMPRE última versión (no hardcodear version)
var secret = await client.GetSecretAsync("api-key");

// Cache con TTL corto para que se actualice tras rotación
_memoryCache.Set("api-key", secret.Value.Value, TimeSpan.FromMinutes(5));
```

**5. Audit de rotaciones** (compliance):

```bash
# Ver historial de versiones de un secreto
az keyvault secret list-versions \
  --vault-name $KV_NAME \
  --name api-key \
  --query "[].{Created:attributes.created, Version:id, Enabled:attributes.enabled}" \
  --output table
```

**Regla de oro de seguridad:**
- Secretos críticos: rotar cada 90 días mínimo
- Secretos de servicios externos (APIs de pago, etc.): rotar cada 30-60 días
- Certificados: 1 año máximo, mejor 90 días con rotación automática

## Slide 15 — Smoke tests del flujo OAuth completo

Script bash que valida el flujo end-to-end en 30 segundos:

```bash
#!/bin/bash
# smoke-tests-oauth.sh
set -e

API_URL="https://app-curso-<tu-nombre>.azurewebsites.net"
TENANT_ID="<vuestro-tenant>"
APP_ID="<vuestro-app-id>"
CLIENT_SECRET="<vuestro-secret>"

echo "🔍 Smoke tests del flujo OAuth"

# Test 1: API protegida — sin token devuelve 401
echo -n "  [1/5] Sin token → 401... "
HTTP_CODE=$(curl -o /dev/null -s -w "%{http_code}" "$API_URL/productos")
[ "$HTTP_CODE" = "401" ] && echo "✓" || { echo "✗ ($HTTP_CODE)"; exit 1; }

# Test 2: Obtener token desde Entra
echo -n "  [2/5] Token desde Entra... "
TOKEN=$(curl -s -X POST \
  "https://login.microsoftonline.com/$TENANT_ID/oauth2/v2.0/token" \
  -d "grant_type=client_credentials" \
  -d "client_id=$APP_ID" \
  -d "client_secret=$CLIENT_SECRET" \
  -d "scope=api://$APP_ID/.default" \
  | jq -r .access_token)
[ -n "$TOKEN" ] && [ "$TOKEN" != "null" ] && echo "✓" || { echo "✗"; exit 1; }

# Test 3: API con token devuelve 200
echo -n "  [3/5] Con token → 200... "
HTTP_CODE=$(curl -o /dev/null -s -w "%{http_code}" \
  -H "Authorization: Bearer $TOKEN" \
  "$API_URL/productos")
[ "$HTTP_CODE" = "200" ] && echo "✓" || { echo "✗ ($HTTP_CODE)"; exit 1; }

# Test 4: Token expirado → 401
echo -n "  [4/5] Token inválido → 401... "
HTTP_CODE=$(curl -o /dev/null -s -w "%{http_code}" \
  -H "Authorization: Bearer fake-invalid-token-12345" \
  "$API_URL/productos")
[ "$HTTP_CODE" = "401" ] && echo "✓" || { echo "✗ ($HTTP_CODE)"; exit 1; }

# Test 5: Verificar que App Settings NO contienen secretos
echo -n "  [5/5] Sin secretos en App Settings... "
SECRETS=$(az webapp config appsettings list \
  --name app-curso-<tu-nombre> \
  -g rg-curso-azure-<tu-nombre> \
  --query "[?contains(value, 'AccountKey=') || contains(value, 'Password=')]" \
  -o tsv | wc -l)
[ "$SECRETS" -eq 0 ] && echo "✓" || { echo "✗ ($SECRETS secretos detectados)"; exit 1; }

echo ""
echo "✅ Todos los smoke tests pasados"
```

**Ejecutar antes y después de cualquier cambio significativo:**
```bash

```

## Slide 17 — Retos opcionales

**Reto 1 — Implementar auth en código (sin Easy Auth):**
Usad `Microsoft.Identity.Web` para validar tokens en el código en vez de depender de Easy Auth. Más control sobre autorización (roles, claims).

**Reto 2 — Añadir App Roles:**

## Slide 20 — Troubleshooting OAuth2/OIDC durante la práctica

Errores que SIEMPRE aparecen en esta práctica — fixes rápidos:

```
ERROR 1: AADSTS50011 - Reply URL mismatch
─────────────────────────────────────────
Síntoma: 
   "The reply URL specified in the request does not match the reply URLs..."

Causas:
├── 1. Redirect URI en código != App Registration
├── 2. http vs https mismatch  
├── 3. Trailing slash difference
└── 4. Wrong port

Fix:
├── App Registration → Authentication → Redirect URIs
├── Add EXACTLY same URL como en código
└── For Easy Auth: usually /.auth/login/aad/callback

ERROR 2: AADSTS65001 - User has not consented
──────────────────────────────────────────────
Síntoma: 
   "The user or administrator has not consented to use the application..."

Fix:
├── Option A: User consent en first sign-in
│   └── Just retry, accept dialog
├── Option B: Admin pre-consent (recomended para production)
│   └── az ad app permission admin-consent --id <app-id>
└── Option C: Configure permissions correctly
    └── User.Read should NOT need admin consent

ERROR 3: AADSTS70011 - Invalid scope
─────────────────────────────────────
Síntoma:
   "The provided value for the input parameter 'scope' is not valid"

Fix:
├── For Microsoft APIs: "https://graph.microsoft.com/User.Read"
├── For your APIs: "api://<api-id>/access_as_user"
├── Common typo: scope vs resource (v1 vs v2 endpoint)
└── Verify in App Registration → Expose an API → Scopes

ERROR 4: 401 from API after successful login
─────────────────────────────────────────────
Síntoma:
   Login works but calling /api/secure returns 401

Causas:
├── 1. Token's audience doesn't match API
├── 2. API expects different scope
├── 3. Token expired (>1h)
└── 4. API not configured to accept tokens from this tenant

Fix:
├── Decode token at jwt.ms
├── Verify aud claim = your API's app ID
├── Check API config: Authority, Audience, ValidIssuers
└── Get fresh token if expired

ERROR 5: Easy Auth blocks all requests after enable
────────────────────────────────────────────────────
Síntoma:
   App returns 401 for everything after habilitar Easy Auth

Causas:
├── 1. Anonymous access deshabilitado
├── 2. Login flow no completado
└── 3. Wrong issuer URL

Fix:
├── Auth settings: "Allow anonymous" = TEMPORARY for testing
├── Force login: visit /.auth/login/aad
└── Check Application Insights logs for auth errors

ERROR 6: KV Reference returns null
───────────────────────────────────
Síntoma:
   App Setting con @Microsoft.KeyVault(...) muestra null

Causas:
├── 1. MI not assigned to App Service
├── 2. MI doesn't have "Key Vault Secrets User" role
├── 3. Wrong KV reference syntax
├── 4. KV in deny mode without VNet integration

Fix:
├── az webapp identity show -n <app> -g <rg>
├── az role assignment list --assignee <mi-id>
├── Syntax: @Microsoft.KeyVault(VaultName=kv-prod;SecretName=mysecret)
└── Configuration → Key Vault references should show ✅
```

## Slide 21 — Reto avanzado: Step-up authentication

Implementar step-up para operations sensitive:

```csharp
// Setup: Define auth context en Entra ID
// Portal → Conditional Access → Authentication contexts
// Create: c1 = "High-value transactions"
// CA Policy: c1 requires phishing-resistant MFA

// API: Endpoint que requires step-up
[Authorize]
public class TransfersController : ControllerBase
{
    [HttpPost("transfer")]
    public async Task<IActionResult> Transfer([FromBody] TransferRequest req)
    {
        // Small amounts: just authenticated
        if (req.Amount <= 1000)
        {
            await ProcessTransferAsync(req);
            return Ok();
        }
        
        // Large amounts: require step-up
        var hasStepUp = User.FindAll("acrs").Any(c => c.Value == "c1");
        
        if (!hasStepUp)
        {
            // Trigger claims challenge
            var claimsChallenge = "{\"access_token\":{\"acrs\":{\"essential\":true,\"value\":\"c1\"}}}";
            
            return Challenge(new AuthenticationProperties
            {
                Items = { ["claims"] = claimsChallenge }
            });
        }
        
        // Step-up confirmed, process
        await ProcessTransferAsync(req);
        return Ok();
    }
}
```

**Frontend handling:**
```javascript
// React + MSAL.js
async function performTransfer(amount) {
    try {
        const response = await fetch('/api/transfer', {
            method: 'POST',
            headers: {
                'Authorization': `Bearer ${currentToken}`,
                'Content-Type': 'application/json'
            },
            body: JSON.stringify({ amount })
        });
        
        if (response.status === 401) {
            // Check for claims challenge
            const wwwAuth = response.headers.get('WWW-Authenticate');
            if (wwwAuth?.includes('claims=')) {
                const claimsChallenge = parseClaimsChallenge(wwwAuth);
                
                // Re-acquire token con claims challenge
                const newTokenResponse = await msalInstance.acquireTokenPopup({
                    scopes: ['api://your-api/access_as_user'],
                    claims: claimsChallenge  // forces step-up
                });
                
                // Retry transfer with new token
                return await fetch('/api/transfer', {
                    method: 'POST',
                    headers: {
                        'Authorization': `Bearer ${newTokenResponse.accessToken}`,
                        'Content-Type': 'application/json'
                    },
                    body: JSON.stringify({ amount })
                });
            }
        }
        
        return response;
    } catch (error) {
        console.error('Transfer failed:', error);
        throw error;
    }
}

function parseClaimsChallenge(header) {
    const match = header.match(/claims="([^"]+)"/);
    if (match) {
        return atob(match[1]);
    }
    return null;
}
```

2. Try transfer €5000 → 401 + claims challenge
3. MSAL prompts for stronger MFA
4. Retry transfer €5000 → success

public class MyGraphService
{
    private readonly GraphServiceClient _graphClient;
    
    public MyGraphService(GraphServiceClient graphClient)
    {
        _graphClient = graphClient;
    }
    
    // Get current user info
    public async Task<UserInfoDto> GetCurrentUserAsync()
    {
        var me = await _graphClient.Me.GetAsync();
        var photo = await GetUserPhotoAsync(me.Id);
        var groups = await _graphClient.Me.MemberOf.GetAsync();
        
        return new UserInfoDto
        {
            DisplayName = me.DisplayName,
            Email = me.Mail ?? me.UserPrincipalName,
            JobTitle = me.JobTitle,
            Department = me.Department,
            PhotoUrl = photo,
            Groups = groups.Value
                .OfType<Group>()
                .Select(g => g.DisplayName)
                .ToList()
        };
    }
    
    private async Task<string> GetUserPhotoAsync(string userId)
    {
        try
        {
            var stream = await _graphClient.Users[userId].Photo.Content.GetAsync();
            using var ms = new MemoryStream();
            await stream.CopyToAsync(ms);
            return $"data:image/jpeg;base64,{Convert.ToBase64String(ms.ToArray())}";
        }
        catch
        {
            return null;  // No photo
        }
    }
    
    // List users in tenant (admin permissions required)
    public async Task<List<UserDto>> ListUsersAsync(int top = 50)
    {
        var users = await _graphClient.Users.GetAsync(req =>
        {
            req.QueryParameters.Top = top;
            req.QueryParameters.Select = new[] { "displayName", "mail", "jobTitle" };
        });
        
        return users.Value.Select(u => new UserDto
        {
            DisplayName = u.DisplayName,
            Email = u.Mail,
            JobTitle = u.JobTitle
        }).ToList();
    }
}

#!/bin/bash
# cleanup-m06.sh — limpieza completa después de la práctica

set -e

KV_NAME="kv-curso-pedro"

echo "Calculating costs incurred..."
az consumption usage list \
  --start-date $(date -u -d '7 days ago' +%Y-%m-%d) \
  --end-date $(date -u +%Y-%m-%d) \
  --query "[?contains(instanceId, '$RG')] | [].pretaxCost" \

read -p "Continue with cleanup? (yes/no): " CONFIRM
if [ "$CONFIRM" != "yes" ]; then
  echo "Cleanup aborted"
  exit 0
fi

# 3. Disable Easy Auth (clean exit)
echo "Disabling Easy Auth..."
az webapp auth update \
  --name $APP_NAME \
  --resource-group $RG \
  --enabled false 2>/dev/null || true

# 4. Find and delete App Registration
APP_ID=$(az ad app list --display-name "$APP_NAME-auth" \
  --query "[0].appId" -o tsv 2>/dev/null || echo "")

if [ -n "$APP_ID" ]; then
  echo "Deleting App Registration..."
  az ad app delete --id $APP_ID
fi

# 5. Note about KV with purge protection
KV_HAS_PURGE=$(az keyvault show -n $KV_NAME -g $RG \
  --query "properties.enablePurgeProtection" -o tsv 2>/dev/null || echo "false")

  echo "⚠️  KV $KV_NAME has purge protection - will be in soft-delete state for 90 days"
  echo "   Cannot be fully deleted before that"
fi

# 6. Delete RG
echo "Deleting RG $RG..."
az group delete --name $RG --yes --no-wait

echo ""
echo "✅ Cleanup initiated - completes in ~10 minutes"
echo ""
echo "Verify cleanup later with:"
echo "  az group exists -n $RG  # should be false"
echo "  az keyvault list-deleted  # check soft-deleted KVs"
echo ""
echo "Total cleanup time: ~10-15 minutes"
