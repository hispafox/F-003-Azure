## Slide 2 — Qué vais a construir

Una API REST mínima para gestionar **notas personales**, desplegada a Azure como Web App F1, con persistencia en Table Storage. Un mini proyecto end-to-end que toca Web App + persistencia + tests + deploy.

**El recorrido:**

```
1. Diseñar el modelo (Note: id, title, content, tags)
2. Crear el proyecto .NET 8 minimal API
3. Implementar 5 endpoints CRUD con Table Storage
4. Tests unitarios del repositorio
5. Smoke tests para validar deploy
6. Crear infraestructura Azure (Web App F1 + Storage)
7. Desplegar la app
8. Validar end-to-end
9. Limpiar
```

**Lo que NO hay en esta práctica** (vs M10 principal):

- ❌ Frontend Blazor (M10-S10.1)
- ❌ Auth con Entra ID + Key Vault (M06)
- ❌ Service Bus / mensajería (M07)
- ❌ Functions / Cosmos / Change Feed (M03/M05)
- ❌ Pipeline CI/CD (M08)
- ❌ Application Insights / observabilidad avanzada (M08-S8.6)
- ❌ Slots / swap (M02-S2.P)
- ❌ Managed Identity (M05-S5.4)

**Por qué este alcance:**

- ✅ Suficiente para demostrar "un proyecto end-to-end"
- ✅ Combina M02 (Web App), M05 (Storage), M01 (deploy)
- ✅ Sin coste (F1 + Storage free tier)
- ✅ 60-75 min, no 4 horas como el integrador grande
- ✅ Base sobre la que añadir features del proyecto principal después

**Tiempo estimado:** 60-75 minutos.

**Coste real:** **0€** (Web App F1 + Storage Account dentro del free tier).

## Slide 4 — Paso 1: Diseñar el modelo

Antes de escribir código, definimos el modelo de datos. Una `Note` simple:

```
Modelo Note:
├── Id              (RowKey en Table Storage)
├── PartitionKey    (siempre "notes" para esta app)
├── Title           string, máx 200 chars
├── Content         string, máx 10K chars
├── Tags            string (CSV: "trabajo,proyecto-x")
├── CreatedAt       DateTime UTC
├── UpdatedAt       DateTime UTC
└── ETag            (managed by Azure SDK)
```

**Decisión: ¿por qué PartitionKey fija "notes"?**

```
Para una app personal con <10K notas:
✅ PartitionKey="notes" funciona bien
✅ Queries por todos los items son rápidas (1 partition)
❌ Limitación: no escala más allá de 10K notas/seg

Para producción multi-usuario:
- PartitionKey = userId (cada usuario tiene su partition)
- O PartitionKey = año-mes (notas por periodo)
```

**Endpoints REST que vamos a implementar:**

```
GET    /notes              → listar todas
GET    /notes/{id}         → obtener una
POST   /notes              → crear
PUT    /notes/{id}         → actualizar
DELETE /notes/{id}         → borrar
```


## Slide 6 — Paso 3: Implementar el modelo Note

```bash
mkdir -p src/MiniNotas/Models

cat > src/MiniNotas/Models/Note.cs << 'EOF'
using Azure;
using Azure.Data.Tables;

namespace MiniNotas.Models;

public class Note : ITableEntity
{
    // Campos obligatorios de ITableEntity
    public string PartitionKey { get; set; } = "notes";
    public string RowKey { get; set; } = Guid.NewGuid().ToString();
    public DateTimeOffset? Timestamp { get; set; }
    public ETag ETag { get; set; }

    // Campos del dominio
    public string Title { get; set; } = string.Empty;
    public string Content { get; set; } = string.Empty;
    public string Tags { get; set; } = string.Empty;
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public DateTime UpdatedAt { get; set; } = DateTime.UtcNow;
}

// DTO para inputs (sin campos managed)
public record CreateNoteRequest(string Title, string Content, string Tags);
public record UpdateNoteRequest(string Title, string Content, string Tags);
EOF
```

**Decisiones de diseño:**

```
1. Note hereda de ITableEntity (requerido por Azure.Data.Tables)
2. PartitionKey hardcoded a "notes" (single-partition app)
3. RowKey auto-generado con Guid (único por nota)
4. CreateNoteRequest / UpdateNoteRequest separan input de modelo
   → más limpio en API
   → previene "mass assignment" attacks
```

**Validación del modelo (la añadiremos en endpoints):**

```
Title:    no vacío, <200 chars
Content:  no vacío, <10000 chars
Tags:     opcional, CSV
```

## Slide 7 — Paso 4: Implementar el repositorio

```bash
mkdir -p src/MiniNotas/Repositories

cat > src/MiniNotas/Repositories/NotesRepository.cs << 'EOF'
using Azure;
using Azure.Data.Tables;
using MiniNotas.Models;

namespace MiniNotas.Repositories;

public interface INotesRepository
{
    Task<List<Note>> GetAllAsync(CancellationToken ct = default);
    Task<Note?> GetByIdAsync(string id, CancellationToken ct = default);
    Task<Note> CreateAsync(Note note, CancellationToken ct = default);
    Task<Note?> UpdateAsync(string id, Note note, CancellationToken ct = default);
    Task<bool> DeleteAsync(string id, CancellationToken ct = default);
}

public class NotesRepository : INotesRepository
{
    private const string PartitionKey = "notes";
    private readonly TableClient _table;

    public NotesRepository(IConfiguration config)
    {
        var connectionString = config["Storage:ConnectionString"]
            ?? throw new InvalidOperationException("Storage:ConnectionString no configurada");

        _table = new TableClient(connectionString, "notes");
        // Crear tabla si no existe (idempotente)
        _table.CreateIfNotExists();
    }

    public async Task<List<Note>> GetAllAsync(CancellationToken ct = default)
    {
        var resultado = new List<Note>();
        await foreach (var note in _table.QueryAsync<Note>(
            filter: $"PartitionKey eq '{PartitionKey}'",
            cancellationToken: ct))
        {
            resultado.Add(note);
        }
        return resultado;
    }

    public async Task<Note?> GetByIdAsync(string id, CancellationToken ct = default)
    {
        try
        {
            var response = await _table.GetEntityAsync<Note>(PartitionKey, id, cancellationToken: ct);
            return response.Value;
        }
        catch (RequestFailedException ex) when (ex.Status == 404)
        {
            return null;
        }
    }

    public async Task<Note> CreateAsync(Note note, CancellationToken ct = default)
    {
        note.PartitionKey = PartitionKey;
        if (string.IsNullOrEmpty(note.RowKey))
            note.RowKey = Guid.NewGuid().ToString();
        note.CreatedAt = DateTime.UtcNow;
        note.UpdatedAt = DateTime.UtcNow;

        await _table.AddEntityAsync(note, ct);
        return note;
    }

    public async Task<Note?> UpdateAsync(string id, Note note, CancellationToken ct = default)
    {
        note.PartitionKey = PartitionKey;
        note.RowKey = id;
        note.UpdatedAt = DateTime.UtcNow;

        try
        {
            await _table.UpdateEntityAsync(note, ETag.All, cancellationToken: ct);
            return note;
        }
        catch (RequestFailedException ex) when (ex.Status == 404)
        {
            return null;
        }
    }

    public async Task<bool> DeleteAsync(string id, CancellationToken ct = default)
    {
        try
        {
            await _table.DeleteEntityAsync(PartitionKey, id, cancellationToken: ct);
            return true;
        }
        catch (RequestFailedException ex) when (ex.Status == 404)
        {
            return false;
        }
    }
}
EOF
```

**Decisiones de diseño:**

```
✅ Interface IRepository → testeable con mocks
✅ CreateIfNotExists() → idempotencia (la tabla puede no existir)
✅ Try/catch específico para 404 → "no existe" no es excepción
✅ ETag.All en update → "actualizar sin importar versión"
✅ CancellationToken → buena práctica .NET moderna
✅ UpdatedAt managed por el repo → consistente
```

**Compilar:**

```bash
dotnet build
```

Esperado: build correcto.

## Slide 8 — Paso 5: Implementar los endpoints

Sustituir `src/MiniNotas/Program.cs`:

```bash
cat > src/MiniNotas/Program.cs << 'EOF'
using MiniNotas.Models;
using MiniNotas.Repositories;

var builder = WebApplication.CreateBuilder(args);

// DI
builder.Services.AddSingleton<INotesRepository, NotesRepository>();

var app = builder.Build();

// GET /notes — listar
app.MapGet("/notes", async (INotesRepository repo, CancellationToken ct) =>
{
    var notes = await repo.GetAllAsync(ct);
    return Results.Ok(new { total = notes.Count, notes });
});

// GET /notes/{id} — obtener una
app.MapGet("/notes/{id}", async (string id, INotesRepository repo, CancellationToken ct) =>
{
    var note = await repo.GetByIdAsync(id, ct);
    return note is null
        ? Results.NotFound(new { error = $"Nota {id} no encontrada" })
        : Results.Ok(note);
});

// POST /notes — crear
app.MapPost("/notes", async (CreateNoteRequest req, INotesRepository repo, CancellationToken ct) =>
{
    // Validación
    if (string.IsNullOrWhiteSpace(req.Title))
        return Results.BadRequest(new { error = "Title es obligatorio" });
    if (req.Title.Length > 200)
        return Results.BadRequest(new { error = "Title máximo 200 caracteres" });
    if (req.Content?.Length > 10000)
        return Results.BadRequest(new { error = "Content máximo 10000 caracteres" });

    var note = new Note
    {
        Title = req.Title,
        Content = req.Content ?? string.Empty,
        Tags = req.Tags ?? string.Empty
    };

    var creada = await repo.CreateAsync(note, ct);
    return Results.Created($"/notes/{creada.RowKey}", creada);
});

// PUT /notes/{id} — actualizar
app.MapPut("/notes/{id}", async (string id, UpdateNoteRequest req, INotesRepository repo, CancellationToken ct) =>
{
    if (string.IsNullOrWhiteSpace(req.Title))
        return Results.BadRequest(new { error = "Title es obligatorio" });

    var existente = await repo.GetByIdAsync(id, ct);
    if (existente is null)
        return Results.NotFound(new { error = $"Nota {id} no encontrada" });

    existente.Title = req.Title;
    existente.Content = req.Content ?? string.Empty;
    existente.Tags = req.Tags ?? string.Empty;

    var actualizada = await repo.UpdateAsync(id, existente, ct);
    return Results.Ok(actualizada);
});

// DELETE /notes/{id} — borrar
app.MapDelete("/notes/{id}", async (string id, INotesRepository repo, CancellationToken ct) =>
{
    var borrada = await repo.DeleteAsync(id, ct);
    return borrada
        ? Results.NoContent()
        : Results.NotFound(new { error = $"Nota {id} no encontrada" });
});

// Health check (útil para deploy)
app.MapGet("/health", () => Results.Ok(new
{
    status = "healthy",
    timestamp = DateTime.UtcNow,
    version = "1.0.0"
}));

app.Run();
EOF

# Compilar
dotnet build
```

**Endpoints resultantes:**

```
GET    /notes              → listar todas
GET    /notes/{id}         → obtener una
POST   /notes              → crear (CreateNoteRequest)
PUT    /notes/{id}         → actualizar (UpdateNoteRequest)
DELETE /notes/{id}         → borrar
GET    /health             → health check
```

**Validaciones implementadas:**

```
✅ Title obligatorio
✅ Title máx 200 chars
✅ Content máx 10K chars
✅ 404 cuando no existe
✅ 201 + Location header al crear
✅ 204 al borrar
```

## Slide 11 — Paso 8: Crear infraestructura en Azure

Script bash que crea todo lo necesario:

```bash
cat > infra/create-azure.sh << 'EOF'
#!/bin/bash
set -e

# Variables
RG_NAME="${1:-rg-mini-notas-curso}"
LOCATION="${2:-westeurope}"
SUFFIX="$(date +%s | tail -c 6)"

STORAGE_NAME="stnotas$SUFFIX"
PLAN_NAME="plan-notas-curso"
APP_NAME="webapp-notas-$SUFFIX"

echo "🏗️  Creando infraestructura en Azure"
echo "  RG: $RG_NAME"
echo "  Location: $LOCATION"

# 1. Resource Group
echo ""
echo "  [1/4] Resource Group..."
az group create --name $RG_NAME --location $LOCATION --output none

# 2. Storage Account
echo "  [2/4] Storage Account: $STORAGE_NAME"
az storage account create \
  --name $STORAGE_NAME \
  --resource-group $RG_NAME \
  --location $LOCATION \
  --sku Standard_LRS \
  --kind StorageV2 \
  --output none

# 3. App Service Plan F1
echo "  [3/4] App Service Plan F1..."
az appservice plan create \
  --name $PLAN_NAME \
  --resource-group $RG_NAME \
  --sku F1 --is-linux \
  --output none

# 4. Web App
echo "  [4/4] Web App: $APP_NAME"
az webapp create \
  --name $APP_NAME \
  --resource-group $RG_NAME \
  --plan $PLAN_NAME \
  --runtime "DOTNETCORE:8.0" \
  --output none

# 5. Configurar connection string como App Setting
echo "  [+] Configurando connection string..."
CONN_STRING=$(az storage account show-connection-string \
  --name $STORAGE_NAME \
  --resource-group $RG_NAME \
  --query connectionString -o tsv)

az webapp config appsettings set \
  --name $APP_NAME \
  --resource-group $RG_NAME \
  --settings "Storage__ConnectionString=$CONN_STRING" \
  --output none

# Output
echo ""
echo "✅ Infraestructura creada"
echo ""
echo "📋 Datos para deploy:"
echo "  APP_NAME: $APP_NAME"
echo "  RG_NAME: $RG_NAME"
echo "  URL: https://$APP_NAME.azurewebsites.net"
echo ""
echo "Guardad estos valores como variables:"
echo "  export APP_NAME=$APP_NAME"
echo "  export RG_NAME=$RG_NAME"
EOF

mkdir -p infra
chmod +x infra/create-azure.sh

# Ejecutar
./infra/create-azure.sh
```

## Slide 17 — Troubleshooting

Los 5 errores más típicos en este tipo de proyectos:

**1. "500 Internal Server Error tras deploy"**

```
Causa común: Storage:ConnectionString mal configurada
Diagnóstico:
  az webapp config appsettings list \
    --name $APP_NAME -g $RG_NAME \
    --query "[?name=='Storage__ConnectionString']"

Si está vacío:
  Re-ejecutar la parte de configuración del script create-azure.sh

Si está correcto:
  Ver logs:
  az webapp log tail --name $APP_NAME -g $RG_NAME
```

**2. "El primer request tarda 30+ segundos"**

```
Causa: cold start del F1 + crear table en primer arranque
Comportamiento normal:
- Primer request post-deploy: 10-30 seg
- Primer request tras 20 min sin tráfico: 5-15 seg
- Requests subsecuentes: <500 ms

Para evitarlo:
- Pasar a B1 (~€13/mes) → no se duerme
- O Premium Functions Flex Consumption
```

**3. "404 al hacer GET /notes/{id}"**

```
Causa: el ID que pasáis no existe en la tabla
Diagnóstico:
  curl $BASE/notes | jq '.notes[].rowKey'  # ver IDs reales

Fix:
- Usar uno de los rowKey listados
- Si listado vacío: crear una nota primero
```

**4. "Build fails: 'Azure.Data.Tables' not found"**

```
Causa: paquete no instalado correctamente
Fix:
  cd src/MiniNotas
  dotnet add package Azure.Data.Tables
  dotnet restore
```

**5. "Tests fallan con NullReferenceException"**

```
Causa común: tests intentan usar repositorio sin configuración
Fix:
- Tests del modelo (los que hicimos): NO necesitan repo, deberían funcionar
- Tests del repositorio: requieren mocks de TableClient o Azurite

Para esta práctica, solo tests del modelo son suficientes.
```

**Comando útil: ver TODO de la Web App:**

```bash
az webapp show \
  --name $APP_NAME \
  --resource-group $RG_NAME \
  --query "{
    Name:name,
    State:state,
    URL:defaultHostName,
    Runtime:siteConfig.linuxFxVersion,
    HttpsOnly:httpsOnly
  }" \
  -o yaml
```
