# Submódulo 4.P — Práctica: Flujo completo Cosmos DB → Function → Blob → HTTP

## Slide 1 — Portada
**Módulo 4 · Práctica**
Flujo completo de integración
Un evento en Cosmos DB dispara procesamiento, almacenamiento y notificación


---

## Slide 2 — Qué vais a construir

Un sistema de procesamiento de pedidos con 4 funciones conectadas:

```
1. API HTTP → Crear pedido → Cosmos DB
                                  ↓ (Change Feed)
2. Cosmos DB Trigger → Procesar pedido → generar factura JSON
                                  ↓ (Output Binding)
3. Factura → Blob Storage (contenedor "facturas")
                                  ↓ (Queue message)
4. Queue Trigger → Loguear notificación de factura generada
```

**Entregable:** Las 4 funciones corriendo en local, el flujo completo funcionando end-to-end.

**Tiempo estimado:** 25-30 minutos

**Conceptos que conviene tener frescos antes de empezar:**

```
┌────────────────────────────────────────────────────┐
│ Flujo a construir:                                 │
│                                                     │
│  Cliente HTTP → POST /pedidos                       │
│       ↓                                             │
│  Function 1 (HTTP Trigger): valida + escribe Cosmos │
│       ↓                                             │
│  Cosmos Change Feed → Function 2 (Cosmos Trigger)   │
│       ↓                                             │
│  Function 2: procesa + genera factura + → Queue     │
│       ↓                                             │
│  Queue → Function 3 (Queue Trigger)                 │
│       ↓                                             │
│  Function 3: envía notificación al cliente          │
└────────────────────────────────────────────────────┘
```

**Por qué este patrón:**
- ✅ Decoupling temporal: cada función puede fallar/escalar independientemente
- ✅ Garantías at-least-once en cada salto
- ✅ Observabilidad por etapa (cada función en App Insights)
- ✅ Replay posible desde Cosmos Change Feed

**Tiempo real:** 60-75 minutos (no los 25-30 optimistas si lo hacéis con cuidado).

## Slide 7 — Paso 4: Función 1 — API HTTP (crear pedido)

Cread `Functions/PedidoApi.cs`:

```csharp
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Mvc;
using Microsoft.Azure.Functions.Worker;
using System.Text.Json;

public class PedidoApi
{
    [Function("CrearPedido")]
    [CosmosDBOutput("tienda", "pedidos", Connection = "CosmosDbConnection")]
    public Pedido Crear(
        [HttpTrigger(AuthorizationLevel.Anonymous, "post", Route = "pedidos")]
        HttpRequest req, ILogger<PedidoApi> logger)
    {
        var dto = req.ReadFromJsonAsync<CrearPedidoDto>().Result;
        
        var pedido = new Pedido
        {
            ClienteId = dto!.ClienteId,
            ClienteNombre = dto.ClienteNombre,
            Items = dto.Items.Select(i => new ItemPedido
            {
                ProductoId = i.ProductoId,
                Nombre = i.Nombre,
                Cantidad = i.Cantidad,
                PrecioUnitario = i.PrecioUnitario
            }).ToList()
        };
        pedido.Total = pedido.Items.Sum(i => i.Cantidad * i.PrecioUnitario);
        
        logger.LogInformation("Pedido {Id} creado: {Total}€, {Items} items",
            pedido.Id, pedido.Total, pedido.Items.Count);
        
        // El return va directo a Cosmos DB (output binding)
        return pedido;
    }

    [Function("ListarPedidos")]
    public IActionResult Listar(
        [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "pedidos")]
        HttpRequest req,
        [CosmosDBInput("tienda", "pedidos", Connection = "CosmosDbConnection",
            SqlQuery = "SELECT TOP 10 * FROM c ORDER BY c.creadoEn DESC")]
        IReadOnlyList<Pedido> pedidos)
    {
        return new OkObjectResult(pedidos);
    }
}

public record CrearPedidoDto(
    string ClienteId, string ClienteNombre,
    List<ItemPedidoDto> Items);
public record ItemPedidoDto(
    string ProductoId, string Nombre, int Cantidad, decimal PrecioUnitario);
```

## Slide 8 — Paso 5: Función 2 — Cosmos DB Trigger (procesar + generar factura)

Cread `Functions/ProcesadorPedidos.cs`:

```csharp
using Microsoft.Azure.Functions.Worker;
using System.Text.Json;

public class ProcesadorPedidos
{
    public class ProcesarResult
    {
        [BlobOutput("facturas/{pedidoId}-factura.json", Connection = "StorageConnection")]
        public string FacturaJson { get; set; } = "";
        
        [QueueOutput("facturas-generadas", Connection = "StorageConnection")]
        public string MensajeCola { get; set; } = "";
    }

    [Function("ProcesarNuevosPedidos")]
    public ProcesarResult Procesar(
        [CosmosDBTrigger("tienda", "pedidos",
            Connection = "CosmosDbConnection",
            LeaseContainerName = "leases",
            CreateLeaseContainerIfNotExists = true)]
        IReadOnlyList<Pedido> cambios,
        ILogger<ProcesadorPedidos> logger)
    {
        var result = new ProcesarResult();
        
        foreach (var pedido in cambios)
        {
            logger.LogInformation("Procesando pedido {Id}: {Total}€", pedido.Id, pedido.Total);
            
            // Generar factura
            var factura = new
            {
                numero = $"FAC-{DateTime.UtcNow:yyyyMMdd}-{pedido.Id[..8]}",
                pedidoId = pedido.Id,
                cliente = new { id = pedido.ClienteId, nombre = pedido.ClienteNombre },
                items = pedido.Items.Select(i => new {
                    i.Nombre, i.Cantidad, i.PrecioUnitario,
                    subtotal = i.Cantidad * i.PrecioUnitario
                }),
                total = pedido.Total,
                iva = pedido.Total * 0.21m,
                totalConIva = pedido.Total * 1.21m,
                fechaEmision = DateTime.UtcNow,
                estado = "emitida"
            };
            
            result.FacturaJson = JsonSerializer.Serialize(factura, 
                new JsonSerializerOptions { WriteIndented = true });
            result.MensajeCola = JsonSerializer.Serialize(new {
                pedidoId = pedido.Id,
                facturaNumero = factura.numero,
                totalConIva = factura.totalConIva
            });
            
            logger.LogInformation("Factura {Numero} generada: {Total}€ con IVA",
                factura.numero, factura.totalConIva);
        }
        
        return result;
    }
}
```

## Slide 11 — Idempotencia: el flujo end-to-end debe poder reintentar

En cualquier sistema event-driven, **los mensajes pueden llegar duplicados**. El Cosmos Change Feed puede re-disparar al reiniciar la function. La queue puede entregar el mismo mensaje dos veces. Vuestro código DEBE soportarlo.

**Estrategia de idempotencia capa por capa:**

**1. HTTP API: idempotencia con `X-Request-Id`**
```csharp
[Function("CrearPedido")]
public async Task<IActionResult> CrearPedido(
    [HttpTrigger(AuthorizationLevel.Anonymous, "post", Route = "pedidos")]
    HttpRequest req,
    [CosmosDBInput(...)] CosmosClient cosmos)
{
    var requestId = req.Headers["X-Request-Id"].FirstOrDefault() ?? Guid.NewGuid().ToString();
    
    var container = cosmos.GetContainer("PedidosDB", "pedidos");
    
    // Buscar si ya procesamos este requestId
    var existingQuery = container.GetItemQueryIterator<Pedido>(
        $"SELECT * FROM c WHERE c.requestId = '{requestId}'");
    
    if (existingQuery.HasMoreResults)
    {
        var existing = await existingQuery.ReadNextAsync();
        if (existing.Any())
        {
            // Mismo requestId → mismo resultado (idempotente)
            return new OkObjectResult(existing.First());
        }
    }
    
    // Si no existe, crear
    var nuevo = new Pedido { /* ... */, RequestId = requestId };
    await container.CreateItemAsync(nuevo);
    return new CreatedResult($"/pedidos/{nuevo.Id}", nuevo);
}
```

**2. Cosmos Trigger: state machine para evitar re-procesar**
```csharp
[Function("ProcesarPedido")]
public async Task ProcesarPedido(
    [CosmosDBTrigger(...)] IReadOnlyList<Pedido> pedidos)
{
    foreach (var pedido in pedidos)
    {
        // Solo procesar si está PENDIENTE
        if (pedido.Estado != "PENDIENTE")
        {
            _logger.LogDebug("Skip pedido {Id}, estado={Estado}", pedido.Id, pedido.Estado);
            continue;
        }
        
        // Optimistic concurrency con etag (evita duplicados)
        try
        {
            pedido.Estado = "PROCESADO";
            await container.ReplaceItemAsync(
                pedido, pedido.Id, 
                new PartitionKey(pedido.ClienteId),
                new ItemRequestOptions { IfMatchEtag = pedido.ETag });
        }
        catch (CosmosException ex) when (ex.StatusCode == HttpStatusCode.PreconditionFailed)
        {
            // Otro proceso lo cambió → ignorar (es idempotente)
            _logger.LogWarning("ETag mismatch para {Id}, otro proceso lo actualizó", pedido.Id);
            continue;
        }
    }
}
```

**3. Queue Trigger: deduplicación con MessageId**
```csharp
[Function("NotificarFacturaGenerada")]
public void Notificar(
    [QueueTrigger("facturas-generadas")] QueueMessage message)
{
    // MessageId es único por mensaje
    var dedupeKey = $"notif:{message.MessageId}";
    
    // Verificar si ya procesado (cache distribuido o Cosmos)
    if (_cache.GetString(dedupeKey) == "done")
    {
        _logger.LogInformation("Mensaje {Id} ya procesado, skip", message.MessageId);
        return;
    }
    
    // Procesar...
    SendNotification(message.Body);
    
    // Marcar como procesado (con TTL razonable)
    _cache.SetString(dedupeKey, "done", new DistributedCacheEntryOptions
    {
        AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24)
    });
}
```

## Slide 12 — Variante: Service Bus en lugar de Storage Queue

Storage Queue es OK para empezar. Service Bus es lo recomendado para producción. La diferencia importa para vuestro CV/portfolio.

**Cuándo Service Bus > Storage Queue:**

| Feature | Storage Queue | Service Bus |
|---|:---:|:---:|
| Tamaño máx mensaje | 64 KB | 256 KB (Standard), 1 MB (Premium) |
| Garantías de orden | Best-effort | FIFO con sessions |
| Dead-letter queue | Manual | Automática |
| Transacciones | ❌ | ✅ |
| Duplicate detection | Manual (MessageId) | Built-in (10 min ventana) |
| Topics + subscriptions | ❌ | ✅ (pub/sub) |
| Coste base | ~€0.05/mes (storage) | ~€10/mes (Standard) |

**Migrar la práctica a Service Bus:**

**1. Cambiar paquete:**
```bash
dotnet remove package Microsoft.Azure.Functions.Worker.Extensions.Storage.Queues
dotnet add package Microsoft.Azure.Functions.Worker.Extensions.ServiceBus
```

**2. Crear namespace + queue:**
```bash
RG="rg-curso-flujo"
NAMESPACE="sb-pedidos-$(whoami)-$RANDOM"

az servicebus namespace create -g $RG -n $NAMESPACE --sku Standard
az servicebus queue create -g $RG --namespace-name $NAMESPACE \
  --name facturas-generadas \
  --enable-dead-lettering-on-message-expiration true \
  --max-delivery-count 5 \
  --requires-duplicate-detection true \
  --duplicate-detection-history-time-window PT10M

# Connection string
SB_CONN=$(az servicebus namespace authorization-rule keys list \
  -g $RG --namespace-name $NAMESPACE \
  --name RootManageSharedAccessKey \
  --query primaryConnectionString -o tsv)
```

**3. Actualizar `local.settings.json`:**
```json
{
  "Values": {
    "ServiceBusConnection": "Endpoint=sb://...;SharedAccessKeyName=...;SharedAccessKey=..."
  }
}
```

**4. Cambiar las 2 functions implicadas:**

**Function 2 (Cosmos Trigger): publicar a Service Bus**
```csharp

    [CosmosDBTrigger(...)] IReadOnlyList<Pedido> pedidos)
{
    // ... lógica ...
    
    var message = new ServiceBusMessage(JsonSerializer.Serialize(factura))
    {
        MessageId = $"factura-{factura.Numero}",  // Para dedupe nativo

```

**Function 3 (Service Bus Trigger):**
```csharp
[Function("NotificarFacturaGenerada")]
public void Notificar(
    [ServiceBusTrigger("facturas-generadas", Connection = "ServiceBusConnection")]
    ServiceBusReceivedMessage message)
{
    if (message.Subject != "FacturaGenerada")
    {
        _logger.LogWarning("Subject inesperado: {Subject}", message.Subject);

    // No need to mark complete: ServiceBusTrigger lo hace automáticamente
}
```

## Slide 16 — Retos opcionales

**Reto 1 — Durable Function:**
Reemplazar el flujo directo con un Orchestrator: `ValidarPedido → GenerarFactura → Notificar`. Añadir retry policy en cada paso.

**Reto 2 — Error handling:**
Forzar un error (por ejemplo, un campo faltante) y verificar que el Change Feed reintenta. Implementar un dead-letter manual para pedidos que fallan 3 veces.

**Reto 3 — Desplegar a Azure:**

## Slide 19 — Variante avanzada: integración con Managed Identity + Key Vault

Aplicar lo que viene en M6 — acceso a secretos sin connection strings:

```bicep
// Habilitar System Assigned MI en Function App
resource funcApp 'Microsoft.Web/sites@2023-12-01' = {
  name: 'func-pedidos-curso'
  location: location
  identity: {
    type: 'SystemAssigned'  // ⭐ MI automática
  }
  properties: { ... }
}

// Role assignment: MI puede leer secretos del Key Vault
resource kvRoleAssignment 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(funcApp.id, keyVault.id, 'Key Vault Secrets User')
  scope: keyVault
  properties: {
    principalId: funcApp.identity.principalId
    principalType: 'ServicePrincipal'
    roleDefinitionId: subscriptionResourceId(
      'Microsoft.Authorization/roleDefinitions',
      '4633458b-17de-408a-b874-0445c86b69e6'  // Key Vault Secrets User
    )
  }
}

// App Settings referencian Key Vault (no hay secrets en plain)
resource appSettings 'Microsoft.Web/sites/config@2023-12-01' = {
  name: '${funcApp.name}/appsettings'
  properties: {
    CosmosConnection: '@Microsoft.KeyVault(VaultName=kv-curso;SecretName=cosmos-connection)'
    ServiceBusConnection: '@Microsoft.KeyVault(VaultName=kv-curso;SecretName=sb-connection)'
  }
}
```

**En código — DefaultAzureCredential** (magic):
```csharp
// Program.cs
builder.Services.AddSingleton(sp =>
{
    // DefaultAzureCredential intenta automáticamente:
    // 1. Environment variables (dev local)
    // 2. Managed Identity (cuando corre en Azure)  ← producción
    // 3. Visual Studio / Azure CLI (dev local)
    
    var endpoint = Environment.GetEnvironmentVariable("COSMOS_ENDPOINT")!;
    return new CosmosClient(endpoint, new DefaultAzureCredential());
});

// Y para Service Bus
builder.Services.AddSingleton(sp =>
{
    var namespaceUrl = Environment.GetEnvironmentVariable("SB_NAMESPACE")!;
    return new ServiceBusClient(namespaceUrl, new DefaultAzureCredential());
});
```

**Role assignments necesarias:**
```bash
# Para Cosmos DB (built-in role)
az cosmosdb sql role assignment create \
  --account-name cosmos-curso \
  --resource-group rg-curso \
  --scope "/" \
  --principal-id $FUNC_MI_PRINCIPAL_ID \
  --role-definition-id "00000000-0000-0000-0000-000000000002"  # Cosmos DB Built-in Data Contributor

# Para Service Bus
az role assignment create \
  --role "Azure Service Bus Data Receiver" \
  --assignee $FUNC_MI_PRINCIPAL_ID \
  --scope $(az servicebus namespace show -g rg-curso -n sb-curso --query id -o tsv)

az role assignment create \
  --role "Azure Service Bus Data Sender" \
  --assignee $FUNC_MI_PRINCIPAL_ID \
  --scope $(az servicebus namespace show -g rg-curso -n sb-curso --query id -o tsv)
```

**Resultado:**
- ❌ Zero secretos en vuestro código
- ❌ Zero secretos en App Settings
- ✅ Rotación automática en Key Vault se refleja
- ✅ Audit log de accesos (quién leyó qué secret, cuándo)

## Slide 20 — Despliegue con GitHub Actions (opcional práctica)

Final touch para entregar como pro — workflow completo:

```yaml
# .github/workflows/deploy-practica.yml
name: Deploy Práctica M4

on:
  push:
    branches: [main]

permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup .NET 8
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0.x'
      
      - name: Restore & Build
        run: |
          dotnet restore
          dotnet build -c Release --no-restore
      
      - name: Test
        run: dotnet test -c Release --no-build --verbosity normal
      
      - name: Publish
        run: dotnet publish -c Release -o ./publish
      
      - name: Azure Login (OIDC)
        uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZURE_CLIENT_ID }}
          tenant-id: ${{ secrets.AZURE_TENANT_ID }}
          subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
      
      - name: Deploy Functions
        uses: Azure/functions-action@v1
        with:
          app-name: func-pedidos-curso
          package: ./publish
      
      - name: Smoke test
        run: |
          sleep 30
          curl -sf https://func-pedidos-curso.azurewebsites.net/api/orders \
            -H "Content-Type: application/json" \
            -H "x-functions-key: ${{ secrets.FUNCTION_KEY }}" \
            -d '{"productId":"test","quantity":1}' || exit 1
          echo "✅ Deploy successful"
```

