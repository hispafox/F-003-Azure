## Slide 2 — Qué vais a hacer

Explorar Azure desde el navegador usando **Cloud Shell** — la terminal integrada en el portal. No necesitáis instalar Azure CLI, Git, ni nada en vuestra máquina.

**El recorrido:**

```
1. Abrir Azure Cloud Shell en el portal
2. Configurar el storage de Cloud Shell (one-time)
3. Explorar comandos básicos: subscription, location, resource
4. Crear un Resource Group de prueba
5. Crear un Storage Account (gratis dentro del free tier)
6. Listar y filtrar recursos con queries JMESPath
7. Inspeccionar costes con az consumption
8. Limpiar todos los recursos creados
```

**Lo que NO hay en esta práctica** (a propósito):

- ❌ Instalación local de az CLI (lo cubre la S1.P principal)
- ❌ Code repos ni proyectos .NET (eso es M02)
- ❌ Web Apps ni Functions (M02 / M03)
- ❌ Configuración de tenants ni RBAC complejo (M06)

**Por qué empezar por Cloud Shell:** muchas veces el primer obstáculo de un alumno es **instalar las herramientas**. Cloud Shell elimina esa barrera por completo. Si tenéis cuenta Azure y un navegador, ya podéis empezar.

**Tiempo estimado:** 45-60 minutos.

**Coste real:** **0€** (Cloud Shell + Storage Account dentro de free tier).

```bash
# Listar todas las regiones disponibles
az account list-locations --output table | head -20

# Las más usadas en Europa:
# - westeurope     (Ámsterdam) ← lo más común para España
# - northeurope    (Irlanda)
# - francecentral  (París)

```

**Resource Group:**

```bash
# Concepto: un "contenedor lógico" para recursos relacionados
```

## Slide 7 — Paso 4: Crear vuestro primer Resource Group

Empezamos creando un Resource Group para esta práctica.

```bash
# Variables (cambiad <tu-nombre> por algo único)
RG_NAME="rg-cloudshell-<tu-nombre>"
LOCATION="westeurope"

# Crear el Resource Group
az group create \
  --name $RG_NAME \
  --location $LOCATION

# Verificar
az group show --name $RG_NAME --output table
```

**Salida esperada:**

```
Location    Name                          ProvisioningState
----------  ----------------------------  -----------------
westeurope  rg-cloudshell-pedro           Succeeded
```

**Lo que pasó por debajo:**

```
1. Cloud Shell envió un POST a la API REST de Azure
2. ARM (Azure Resource Manager) validó vuestros permisos
3. Creó la entidad RG (instantáneo)
4. Devolvió OK con los detalles
5. az formateó la salida en tabla
```

**Tags: organización desde el principio**

Tags son metadatos clave-valor que ayudan a clasificar recursos. **Buena costumbre desde el día uno:**

```bash
# Añadir tags al RG
az group update \
  --name $RG_NAME \
  --tags \
    proyecto="curso-az204" \
    entorno="practica" \
    propietario="<tu-nombre>" \
    fecha-creacion="$(date -u +%Y-%m-%d)"

# Ver los tags
az group show --name $RG_NAME --query "tags" --output json
```

**Por qué los tags importan en producción:**

- ✅ Filtrar costes por proyecto / equipo
- ✅ Aplicar políticas de governance
- ✅ Identificar recursos "huérfanos" (sin owner)
- ✅ Automatización (scripts que actúan según tags)

## Slide 8 — Paso 5: Crear un Storage Account

Storage Account es el servicio de almacenamiento de Azure (blobs, queues, tables, files). Vamos a crear uno con la configuración más sencilla y barata:

```bash
# El nombre debe ser único globalmente, 3-24 caracteres, solo letras/números
STORAGE_NAME="stcloudshell$(date +%s | tail -c 6)"
echo "Storage Account: $STORAGE_NAME"

# Crear con SKU Standard_LRS (lo más barato)
az storage account create \
  --name $STORAGE_NAME \
  --resource-group $RG_NAME \
  --location $LOCATION \
  --sku Standard_LRS \
  --kind StorageV2

# Verificar
az storage account show \
  --name $STORAGE_NAME \
  --resource-group $RG_NAME \
  --query "{Name:name, Sku:sku.name, Location:location, Kind:kind}" \
  --output table
```

**Tiempo estimado:** 30-60 segundos.

**Salida esperada:**

```
Name                  Sku           Location    Kind
--------------------  ------------  ----------  ---------
stcloudshell12345     Standard_LRS  westeurope  StorageV2
```

**Por qué estas opciones:**

| Parámetro | Valor | Por qué |
|---|---|---|
| `--sku Standard_LRS` | Locally Redundant Storage | Más barato, datos replicados 3 veces en una zona |
| `--kind StorageV2` | General Purpose v2 | Estándar moderno, soporta blobs/queues/tables/files |
| `--location westeurope` | Ámsterdam | Cercanía + soporte completo |

**Otros SKUs que NO usáis ahora (pero conviene conocer):**

```
Standard_GRS    - replicación geo-redundante (más caro, más resiliente)
Standard_RAGRS  - GRS + read access en secundaria
Premium_LRS     - SSD, mucho más rápido pero caro (~10x precio)
```

**Coste real de este Storage Account:**

```
- Sin datos: ~€0.02/mes
- Con 1 GB de blobs: ~€0.05/mes
- Para esta práctica: <€0.01 (lo borraremos al final)
```

## Slide 9 — Paso 6: Subir un archivo al Storage

Storage sin datos no sirve. Subamos un archivo de prueba:

```bash
# Crear un container (carpeta lógica de blobs)
az storage container create \
  --name pruebas \
  --account-name $STORAGE_NAME \
  --auth-mode login

# Crear un archivo de prueba
echo "¡Hola desde Cloud Shell!" > ~/saludo.txt
echo "Fecha: $(date)" >> ~/saludo.txt

# Subirlo al container
az storage blob upload \
  --account-name $STORAGE_NAME \
  --container-name pruebas \
  --name saludo.txt \
  --file ~/saludo.txt \
  --auth-mode login

# Listar blobs en el container
az storage blob list \
  --account-name $STORAGE_NAME \
  --container-name pruebas \
  --auth-mode login \
  --output table
```

**Salida esperada:**

```
Name        Blob Type    Length    Content Type
----------  -----------  --------  ------------
saludo.txt  BlockBlob    52        text/plain
```

**Descargar el blob:**

```bash
# Descargar a otro nombre
az storage blob download \
  --account-name $STORAGE_NAME \
  --container-name pruebas \
  --name saludo.txt \
  --file ~/saludo-descargado.txt \
  --auth-mode login

cat ~/saludo-descargado.txt
# ¡Hola desde Cloud Shell!
# Fecha: ...
```

**Por qué `--auth-mode login`:**

```
Sin --auth-mode login:
  - az usa una "key" del Storage Account para autenticar
  - Funciona pero NO es la práctica moderna

Con --auth-mode login:
  - az usa vuestra identidad Azure
  - Necesitáis rol RBAC sobre el Storage (Storage Blob Data Contributor)
  - Es lo que se usa en producción real
```

**Si el upload falla con "AuthorizationPermissionMismatch":**

```bash
# Daros permisos sobre el Storage
USER_ID=$(az ad signed-in-user show --query id -o tsv)
STORAGE_ID=$(az storage account show --name $STORAGE_NAME -g $RG_NAME --query id -o tsv)

az role assignment create \
  --assignee $USER_ID \
  --role "Storage Blob Data Contributor" \
  --scope $STORAGE_ID

# Esperar 1-2 minutos a que el rol se propague
# Reintentar el upload
```

## Slide 10 — Paso 7: Listar recursos con queries JMESPath

Una vez tenéis recursos, conviene aprender a **filtrarlos y formatear** salidas. JMESPath es el lenguaje de query del CLI:

**Listar TODO lo que hay en el RG:**

```bash
# Vista cruda (muy verbose)
az resource list --resource-group $RG_NAME

# Vista compacta con tabla
az resource list \
  --resource-group $RG_NAME \
  --output table
```

**Salida esperada:**

```
Name              ResourceGroup          Location    Type
----------------  ---------------------  ----------  -----------------------------
stcloudshell123   rg-cloudshell-pedro    westeurope  Microsoft.Storage/storageAccounts
```

**Queries JMESPath útiles:**

```bash
# Solo nombres
az resource list -g $RG_NAME --query "[].name" -o tsv

# Solo recursos de tipo Storage
az resource list -g $RG_NAME \
  --query "[?type=='Microsoft.Storage/storageAccounts']" \
  --output table

# Filtrar por tags
az resource list \
  --query "[?tags.proyecto=='curso-az204'].{Name:name, Type:type}" \
  --output table

# Top 5 RGs por número de recursos
az group list --query "sort_by([], &name)[:5].{Name:name, Loc:location}" -o table
```

**Patrones JMESPath más comunes:**

| Patrón | Significado |
|---|---|
| `[]` | Todos los elementos |
| `[0]` | Primer elemento |
| `[].name` | Lista de nombres |
| `[?prop=='val']` | Filtrar por propiedad |
| `[].{X:propA, Y:propB}` | Proyección custom |
| `length(@)` | Contar elementos |

**Ejemplo combinado: cuántos recursos hay por tipo**

```bash
az resource list --query "[].type" -o tsv | sort | uniq -c | sort -rn
```

## Slide 11 — Paso 8: Ver costes con az consumption

En Cloud Shell también podéis consultar costes (usefulness REAL en producción):

```bash
# Consumo del último día
az consumption usage list \
  --start-date $(date -u -d '1 day ago' +%Y-%m-%d) \
  --end-date $(date -u +%Y-%m-%d) \
  --output table

# Total gastado este mes (resumen)
az consumption usage list \
  --start-date $(date -u +%Y-%m-01) \
  --end-date $(date -u +%Y-%m-%d) \
  --query "[].pretaxCost" -o tsv \
  | awk '{s+=$1} END {printf "Total mes actual: $%.2f\n", s}'
```

**Salida esperada para esta práctica:**

```
Total mes actual: $0.01 (o similar, casi 0)
```

**Vista por servicio (qué cuesta más):**

```bash
az consumption usage list \
  --start-date $(date -u -d '7 days ago' +%Y-%m-%d) \
  --end-date $(date -u +%Y-%m-%d) \
  --query "[].{Service:meterCategory, Cost:pretaxCost}" \
  --output tsv \
  | awk -F'\t' '{costs[$1]+=$2} END {for (s in costs) printf "%-30s $%.2f\n", s, costs[s]}' \
  | sort -k2 -rn
```

**Trucos pro de costes:**

```bash
# 1. Ver coste de un RG específico
RG_ID=$(az group show --name $RG_NAME --query id -o tsv)
az consumption usage list --query "[?contains(instanceId, '$RG_ID')]" -o table

# 2. Configurar alertas de presupuesto
az consumption budget create \
  --budget-name budget-practica \
  --resource-group $RG_NAME \
  --amount 5 \
  --time-grain Monthly \
  --start-date $(date -u +%Y-%m-01) \
  --notifications-enabled true \
  --threshold 80
```

**Lo que NO podéis ver con CLI** (solo en portal):

- 🛑 Cost Management dashboards visuales
- 🛑 Forecasting de costes futuros
- 🛑 Recommendations de optimización

Para eso: Portal → Cost Management + Billing.

## Slide 13 — Paso 10: Smoke tests automatizados

Validación rápida de que todo lo creado funciona. Script que comprueba en 10 segundos:

```bash
cat > ~/smoke-tests.sh << 'EOF'
#!/bin/bash
set -e

RG_NAME="${1:?Pasa el RG como primer argumento}"

echo "🔍 Smoke tests sobre $RG_NAME"

# Test 1: RG existe y está OK
echo -n "  [1/5] Resource Group existe... "
if az group show --name $RG_NAME --query "properties.provisioningState" -o tsv 2>/dev/null | grep -q "Succeeded"; then
  echo "✓"
else
  echo "✗"
  exit 1
fi

# Test 2: Tags configurados
echo -n "  [2/5] Tags configurados... "
TAGS_COUNT=$(az group show --name $RG_NAME --query "tags | length(@)" -o tsv 2>/dev/null)
if [ "${TAGS_COUNT:-0}" -ge 3 ]; then
  echo "✓ ($TAGS_COUNT tags)"
else
  echo "✗ (solo $TAGS_COUNT tags)"
fi

# Test 3: Storage Account creado
echo -n "  [3/5] Storage Account... "
STORAGE_COUNT=$(az storage account list -g $RG_NAME --query "length(@)" -o tsv)
if [ "$STORAGE_COUNT" -ge 1 ]; then
  echo "✓ ($STORAGE_COUNT storage accounts)"
else
  echo "✗"
  exit 1
fi

# Test 4: Container "pruebas" existe
STORAGE_NAME=$(az storage account list -g $RG_NAME --query "[0].name" -o tsv)
echo -n "  [4/5] Container 'pruebas'... "
if az storage container exists \
    --name pruebas \
    --account-name $STORAGE_NAME \
    --auth-mode login \
    --query "exists" -o tsv 2>/dev/null | grep -q "true"; then
  echo "✓"
else
  echo "⚠️  no existe (puede ser OK si aún no lo creasteis)"
fi

# Test 5: Blob saludo.txt presente
echo -n "  [5/5] Blob 'saludo.txt'... "
if az storage blob exists \
    --container-name pruebas \
    --name saludo.txt \
    --account-name $STORAGE_NAME \
    --auth-mode login \
    --query "exists" -o tsv 2>/dev/null | grep -q "true"; then
  echo "✓"
else
  echo "⚠️  no existe"
fi

echo ""
echo "✅ Smoke tests completados"
EOF

chmod +x ~/smoke-tests.sh
~/smoke-tests.sh $RG_NAME
```

**Output esperado:**

```
🔍 Smoke tests sobre rg-cloudshell-pedro
  [1/5] Resource Group existe... ✓
  [2/5] Tags configurados... ✓ (4 tags)
  [3/5] Storage Account... ✓ (1 storage accounts)
  [4/5] Container 'pruebas'... ✓
  [5/5] Blob 'saludo.txt'... ✓

✅ Smoke tests completados
```

Si algún test falla, sabéis exactamente dónde.

## Slide 14 — Variante: usar PowerShell en vez de Bash

Cloud Shell soporta también PowerShell. Si venís del mundo .NET / Windows, os puede ser más natural:

**Cambiar a PowerShell:**

```
1. En la barra superior de Cloud Shell, click en el dropdown
2. Seleccionar "PowerShell"
3. Espera a que cargue (~10 seg primera vez)
```

**Comandos equivalentes en PowerShell:**

```powershell
# Verificar identidad
Get-AzContext

# Listar Resource Groups
Get-AzResourceGroup | Format-Table Name, Location, ProvisioningState

# Crear Resource Group
$rg = New-AzResourceGroup `
  -Name "rg-cloudshell-pedro-ps" `
  -Location "westeurope" `
  -Tag @{
    proyecto = "curso-az204"
    entorno = "practica-powershell"
  }

# Listar Storage Accounts
Get-AzStorageAccount -ResourceGroupName $rg.ResourceGroupName | Format-Table

# Crear Storage Account
$storage = New-AzStorageAccount `
  -ResourceGroupName $rg.ResourceGroupName `
  -Name "stcloudshellps$(Get-Random -Maximum 99999)" `
  -Location "westeurope" `
  -SkuName "Standard_LRS" `
  -Kind "StorageV2"

# Limpiar todo
Remove-AzResourceGroup -Name $rg.ResourceGroupName -Force
```

**Bash vs PowerShell: ¿cuál usar?**

| Aspecto | Bash + az CLI | PowerShell + Az |
|---|---|---|
| **Curva** | Más simple para scripts | Más natural para .NET devs |
| **Output** | JSON/text/table | Objetos tipados |
| **Pipeline** | Texto | Objetos |
| **Cross-platform** | ✅ Linux/Mac/WSL | ✅ Linux/Mac/Windows |
| **Comunidad scripts** | Mucho más grande | Más pequeña pero activa |

**Recomendación práctica:** aprended Bash + az CLI primero (es lo más universal). PowerShell es bueno tenerlo como segunda herramienta cuando venís de Windows admin.

## Slide 15 — Limpiar todo: cleanup obligatorio

Al terminar la práctica, limpiad recursos. Los costes son mínimos pero es buena costumbre.

## Slide 16 — Cuándo Cloud Shell vs az CLI local

Tras esta práctica, sabéis que ambas opciones existen. **¿Cuál usar cuándo?**

**Cloud Shell es genial cuando:**

```
✅ Estáis en una máquina sin az CLI instalado (cliente, viaje, móvil)
✅ Queréis acceso rápido sin configurar nada
✅ Trabajos puntuales o exploratorios
✅ Necesitáis acceso desde un Chromebook o tablet
✅ Workshop / training donde alumnos varían
```

**az CLI local es mejor cuando:**

```
✅ Trabajáis frecuentemente con Azure (muchas horas/día)
✅ Editáis código en VS Code y necesitáis terminal integrada
✅ Tenéis scripts que automatizan flujos
✅ Necesitáis offline editing (Cloud Shell requiere conexión)
✅ Manejáis grandes archivos (Cloud Shell tiene cuota)
```

**Comparativa rápida:**

| Aspecto | Cloud Shell | az CLI local |
|---|---|---|
| **Setup** | Cero | Instalación + login |
| **Latencia** | Más alta (round-trip a Azure) | Más baja |
| **Editor** | VS Code en navegador (lento) | VS Code nativo |
| **Persistencia** | Storage de Cloud Shell | Filesystem local |
| **Multi-tab** | Limitado | Cuántas terminales queráis |
| **Coste** | ~€0.10/mes (storage) | Solo coste de tu máquina |

**Mi recomendación:**

```
1. Aprended Cloud Shell PRIMERO
   → Sin barrera de entrada, todos pueden seguir clases
   
2. Una vez cómodos con az CLI, instalad en vuestra máquina
   → Para flujo profesional diario
   
3. Mantened Cloud Shell como "plan B"
   → Útil cuando estáis en un equipo que no es vuestro
```

## Slide 17 — Tips pro de productividad en Cloud Shell

Pequeños trucos que aceleran enormemente el uso de Cloud Shell:

**1. Aliases para comandos largos:**

```bash

# Aliases personalizados
alias k="kubectl"

  echo "=== RGs ==="
  az group list --query "[].name" -o tsv
  echo ""
  echo "=== Recursos por tipo ==="
  az resource list --query "[].type" -o tsv | sort | uniq -c

# Recargar

# Probar
mystatus
```

**2. Auto-completion mejorada:**

```bash
# Ya viene activada en Cloud Shell, pero podéis personalizarla
```

```bash
# Función helper
```

## Slide 18 — Troubleshooting Cloud Shell

Los 5 problemas más comunes en Cloud Shell y sus soluciones:

**1. "Cloud Shell se desconecta tras 20 minutos"**

```
Causa: comportamiento normal por inactividad
Síntoma: terminal congelada, comandos no responden

Fix:
- Reload la página (F5)
- O click en el icono "..." → "Restart"
- Vuestros archivos en $HOME persisten
```

**2. "Operaciones lentas o timeouts"**

```
Causa: Cloud Shell vive en una región concreta
Síntoma: az commands tardan 5-10 segundos cada uno

Diagnóstico:
  echo $ACC_LOCATION
  # Muestra: westeurope (o donde lo creasteis)

Fix:
- Si vivís en otra región, mover Cloud Shell a la cercana
- Portal → Cloud Shell settings → cambiar región
- O simplemente aceptar la latencia (es razonable)
```

**3. "Sin storage configurado"**

```
Causa: nunca configurasteis storage la primera vez
Síntoma: archivos no persisten entre sesiones

Fix:
- Reload Cloud Shell
- Aparecerá el diálogo de configurar storage
- Crear → tarda ~30 seg
```

**4. "Permission denied al crear recursos"**

```
Causa: vuestra cuenta no tiene rol Contributor en la subscription
Síntoma: az group create devuelve "AuthorizationFailed"

Diagnóstico:
  az role assignment list --assignee $(az ad signed-in-user show --query id -o tsv) -o table

Esperado:
- "Contributor" o "Owner" en alguna scope
- Si solo tenéis "Reader", no podéis crear

Fix:
- Pedid Contributor al admin de la suscripción
- O creáis vuestra propia free trial sub
```

**5. "Quota exceeded"**

```
Causa: la suscripción tiene límites de recursos
Síntoma: az ... devuelve "QuotaExceeded" o "SubscriptionQuotaReached"

Diagnóstico:
  az vm list-usage --location westeurope -o table | grep -i used

Fix:
- Borrar recursos no usados
- Pedir aumento de quota: Portal → Help → Service Health → New support request
- Cambiar de región si tenéis quota en otra
```

**Cloud Shell logs:**

```bash
# Si Cloud Shell tiene problemas raros:
# Portal → Cloud Shell → "..." → "Show logs"
# Muestra el setup y permite diagnosticar
```
